### Lane C3
- **Text-to-SQL tasks compared by execution on a sandboxed fixture** (PRD FR-2.56 new, [ADR 0055](docs/adr/0055-sql-tasks-compared-by-execution.md)). Two correct queries are rarely the same string, so the whole-answer rule called good text-to-SQL samples disagreements, and a text score called `city = 'Pune'` and `city = 'Oslo'` close.
  - `ratchet/sqlcheck.py` (new, standard library only): format `sql` (un-reserved; `tool_calls` stays reserved) with a `sql` object instead of fields: `fixture` (a SQL script inside `RATCHET_FIXTURES_DIR`), `dialect` (`sqlite`, or `postgres`: normalised text only), `ordered` (`auto`: in order when the outermost query has ORDER BY, else a multiset; `always`; `never`), `empty_result` (`text`: two empty results agree only as the same normalised query; `agree`), `max_rows` (1000), `max_steps` (200,000). Two answers agree when their queries return the same column count and rows on the fixture (names ignored, floats to 9 significant digits, a whole float as the integer).
  - An answer is one statement starting with SELECT, WITH or VALUES, bare or in one code fence (`clean_answer` strips the fence for sql tasks, also when serving and storing). Invalid, with a fixed reason that never quotes the answer: `not one query`, `reads the clock` (CURRENT_DATE, or `'now'`, `'localtime'` or `'utc'` among a date function's arguments), `sql error`, `sql denied`, `sql steps exceeded`, `sql time exceeded`, `sql memory exceeded`, `sql too many rows`, `sql result too large`; such a student sample gets no vote and such a teacher answer is never stored (INV-16).
  - The sandbox: one private in-memory SQLite database per fixture text, shared through a weak map, one lock; the fixture (at most 5 MB, a regular file opened without blocking or following a symlink) loads under its own authorizer (no ATTACH, `load_extension`, non-deterministic functions or PRAGMAs outside a short list) within 30 s and 64 MB; then `PRAGMA query_only = ON` and an authorizer allowing only SQLITE_SELECT, SQLITE_READ, SQLITE_RECURSIVE and deterministic functions; a progress handler (every 100 VM steps) stops a query after `max_steps`, 1 s or 128 MB of resident-memory growth (Linux); `Connection.setlimit` caps a value at 100 KB and a LIKE or GLOB pattern at 100 bytes, and `instr`, `replace` and the two-argument trims (quadratic inside one VM step in SQLite: one `trim` call took 15 s with 60,000 characters in each) are linear Python versions with SQLite's results, checked against it on random arguments; `json_patch` and `unhex` are denied; rows are hashed as fetched, up to `max_rows` and 8 MB; outcomes that do not depend on timing are cached per statement. A typical query takes about 0.1 ms. The gateway never connects to a customer database.
  - Python 3.10 has no `Connection.setlimit`, and there one client-steerable query took 3 GB and 18 s (measured), so a sqlite fixture is a spec error on 3.10 (`dialect: postgres` still works). The Docker image runs 3.12.
  - `Task.spec()` (and `spec_hash`) holds a sql task's options and its fixture's sha256, so an edited fixture recalibrates the task; no other task's spec gains a key. `taskspec` reads fixtures when a spec is parsed (`fixtures_dir`, passed from `Settings.fixtures_dir` by the gateway, the admin API and `python -m ratchet.live`), so a fixture outside the directory, missing, oversized, not UTF-8 or failing to load is a spec error with its path; `extends` merges `sql` by key; `PUT /ratchet/tasks/{name}` treats the same body over a changed fixture as a change. `taskspec.document` and `GET /ratchet/tasks` gain a `sql` key (null for other tasks).
  - Docs: CONFIGURATION.md (a text-to-SQL section: options, what agrees, valid answers, writing the fixture, security notes), THREAT_MODEL.md (T23 and a trust boundary), API.md, ARCHITECTURE.md, TESTING.md, the CLAUDE.md files, a proposed invariant in `docs/lanes/c3-invariants.md`. No built-in task uses the format: the reference simulation and the three pinned workloads are byte-identical.
  - 26 new tests (800 in total): 25 in the new `tests/test_sqlcheck.py` (the ten the item named, plus limits, the linear built-ins against SQLite's own, caching, threads, spec errors with paths, the 3.10 refusal, and sql tasks through the cascade, the golden eval, the dataset, the admin API and a tasks file) and one case in `tests/test_tasks.py`; two `tests/test_registry.py` expectations now use `tool_calls` as the reserved format.
- **Free-text tasks: a similarity comparator, per-task sample counts and a judge gate** (PRD FR-2.55 and FR-14.40 new, FR-5.5 extended, [ADR 0054](docs/adr/0054-free-text-similarity-and-a-judge-gate.md)). Two good summaries are rarely the same string, so the exact comparators called every pair of good free-text samples a disagreement and the student never earned a confident score; and the night's judge score was written but never read by the release gate.
  - `ratchet/similarity.py` (new, standard library only): `chrf` (character n-grams of 1 to 6 with whitespace removed, F-beta with beta 2, the lower of its two directions so the score is symmetric), `token_f1` (SQuAD's) and `rouge_l` (bit-parallel LCS over at most 512 tokens of each answer), on NFKC, case-folded text; inputs capped for the request path.
  - The `similarity` field type in `compare.py` (un-reserved; `tool_calls` stays reserved): `metric`, `threshold` (default 0.7) and `max_len_ratio` (default 2.0; answers further apart in length never agree), on `$` or a JSON field, mixed with other fields (`{category: label, summary: similarity}`); not inside `records` or as a set element. Each answer's features are built once, on its first comparison, and never for a validity check alone.
  - A task with a similarity field needs `policy.samples` of at least 2 (`ValueError`, or a `SpecError` with its path). The router (the shadow too) and the golden eval now sample each task `policy.samples` times (`Task.sample_count`, else `RATCHET_SAMPLES`), so a task is calibrated on what it is served with. The pairwise score already serves the medoid (most matches, then highest token probability).
  - The golden eval labels a similarity task's precision `precision_kind: proxy` (each record says `exact` or `proxy`; the eval says `proxy` when such a task was scored). With a judge, it grades the answers the student would serve on the held-out rows of free-text tasks (no fields, or a similarity field), chosen from the samples it already drew with `STUDENT_SAMPLING` and cleaned as served: `judge_n` and `judge_pass_rate`, overall and per task. `LiveEvaluator` no longer makes a separate greedy student call per free-text row and no longer judges the calibration half or rows that would escalate; a failed judge call still stops the night. `MockFleet.judge` (new) knows the stored truth, so the gate runs offline.
  - `RATCHET_MIN_JUDGE_PASS` (new `ReleasePolicy.min_judge_pass`, default 0, off): an overall judge pass rate below it rejects the candidate; a free-text task with `RATCHET_MIN_TASK_TEST_N` held-out rows below it is disabled on the candidate or rejects it (`RATCHET_TASK_MODE`); with the gate on, a free-text task the candidate would answer that no judge graded fails. The judge never runs on the request path.
  - `/ratchet/stats` `tasks[]` gains `precision_kind` and `judge_pass_rate` (from the live version's record; null where the other per-task keys are, and for older records). `tests/fixtures/stats_keys.json` grows by those two.
  - Docs: CONFIGURATION.md (the similarity type, a free-text tasks section with recommended defaults: pin long-form work, distill short summaries and translations with a similarity field, `RATCHET_UNKNOWN_TASKS=teacher` for unregistered free text; `RATCHET_MIN_JUDGE_PASS`; "the release gate does not use that score yet" removed), API.md, ARCHITECTURE.md, TESTING.md, the CLAUDE.md files, two proposed invariants in `docs/lanes/c3-invariants.md`. The default stays off and no built-in task uses the type: the reference simulation and the three pinned workloads are byte-identical.
  - 23 new tests (774 in total) in `tests/test_tasks.py`, `tests/test_release.py`, `tests/test_live.py` and `tests/test_registry.py`, among them chrF against its definition on seeded strings, the bit-parallel LCS against the textbook table, the medoid on a non-transitive chain, the judge gate disabling one task of three, the judge never named on the request path, and the mock judge catching an adapter that shows 100% proxy precision (simulation); five existing tests updated for the un-reserved type and the judge's new candidates.

### Lane C
- **A generic mock world: every request gets an answer in mock mode** (PRD FR-9.7 new, [ADR 0041](docs/adr/0041-generic-mock-world.md)). Mock mode answered only the demo's own tickets and Scout's calls (a 400 for anything else), and the mock trainer looked every stored row up the same way, so one example from any other request would have crashed Night School.
  - `sim/generic.py` (new): `sim.world.lookup(messages, params=None)` tries tickets, then research, then the generic world, so it never raises for a request the gateway accepts. Answers come from sha256 of the request's text: free text (`[mock teacher] ` and a restatement of the prompt, or of the tool result it ends with), an instance of a `response_format` json_schema (`instance_from_schema`: enums and booleans drawn, numbers within bounds, `mock text` strings, 1 or 2 array items, nested objects, local `$ref`, `anyOf`, `allOf`; never raises on a hostile schema), `{"answer": ...}` for json_object, and tool calls to the catalogue `lookup_order(order_id)` and `refund(order_id, amount, reason)` with arguments read from the prompt by regex (or to a client's own tool, with arguments from its schema), honouring `tool_choice`.
  - `Completion.tool_calls` (new, default None): OpenAI's `message.tool_calls`, filled only by the mock models so far. The router still refuses a teacher answer that ends in a tool call (502 `tool_calls_unsupported`), and the default allowlists still forward `tools` to neither model, so by default a tool request is answered in prose, as before.
  - The mock teacher and student honour `response_format` and `tools`; the student learns generic templates (keyed by schema name, tool set or system prompt, never the task name, which no model sees) on the same curve, wrong first on enum fields and tool choices. `MockFleet.train` and `evaluate` read generic rows by their stored conditions.
  - Workloads `schema` (three structured-output tasks, a nested fourth from the drift day) and `tools` (`order-support`) in `sim.world.make_stream`, `python -m sim.simulate --workload` and `POST /ratchet/demo/day?workload=` (mock only), each with its own seeded generator; the demo day's response adds `simulation: true` and the simulator prints a line saying its output is a simulation. Their prompts hold no personal data, so redaction never changes them.
  - `RATCHET_MOCK_STRICT=1` (new) restores the 400 for anything but a demo request. Tests that relied on that 400 now set it or expect the generic answer.
  - The ticket and research worlds are reached first and their draws are untouched: `make sim`, the pinned reference simulation and the three reference workloads are byte-identical.
  - 18 new tests (746 in total) in the new `tests/test_mock_world.py`, among them the OpenAI SDK's `parse()` with a Pydantic model against the mock gateway; the redaction no-op check covers the new workloads. Docs: TESTING.md (the new workloads, their results over five seeds, labelled simulation), API.md (mock mode answers, the demo workloads), CONFIGURATION.md, ARCHITECTURE.md, sim/CLAUDE.md (the generic world and its RNG rule), README.
- **Per-task calibration when several tasks share one adapter** (PRD FR-14.1 new, FR-2.3, FR-5.2 and FR-6.1 extended, [ADR 0040](docs/adr/0040-per-task-calibration.md)). One pooled threshold served the hardest task of a shared adapter below the target precision (the easy tasks' right answers diluted its wrong ones) and let a candidate that got one task badly wrong ship.
  - `cascade_eval` writes one record per task (`eval['tasks'][name]`: `golden_n`, `test_n`, `agreement`, `threshold`, `precision`, `coverage`, `spec_hash`, `target_precision`, `calibrated`) on the same even/odd halves as the global numbers, which do not move; one task's record is the global numbers again. A task is calibrated to its spec's `policy.target_precision` (default 0.97); with fewer than `RATCHET_MIN_TASK_GOLDEN` (new, 20) calibration rows its threshold is never below the global one; with no held-out row it is 1.01.
  - The router holds each task to its own threshold while its spec is unchanged (`ratchet/calibration.py`, new); a version scored before keeps its one threshold, and `eval['spec_hashes']` is still written and read. `system_fingerprint` hashes the threshold the answer was held to, so each task of a version has its own.
  - The golden gate checks each task with at least `RATCHET_MIN_TASK_TEST_N` (new, 10) held-out rows by the global gate's rule on its own rows: its held-out precision (a point estimate) against its floor (`policy.min_precision`) and against the live version's precision on it less the tolerance; a task that answers none of those rows fails too. (A first version checked the Wilson upper bound, which let 36 of 40 right, 90%, pass a 95% floor.) `RATCHET_TASK_MODE` (new): `disable` (default; the task's threshold becomes 1.01, a `task_disabled` event, the version ships for its other tasks, and re-scores keep the task disabled) or `reject`. A candidate left answering under `min_coverage` of its held-out rows at its per-task thresholds is rejected, so it cannot wait in shadow or canary forever. `ReleasePolicy` now takes a string field (`from_env` reads it case-insensitively; empty means the default).
  - One `alert` per (version, task) whose audited precision is strongly below the floor, for the live version and the canary (a new tick step, `_tick_tasks`), once-only across gates and processes (`Ledger.event_once` checks the events and writes the alert in one `BEGIN IMMEDIATE` transaction, so the gateway's tick and a cron tick on one file cannot both write it); versions whose audits are all one task's keep only their own alert. Rollback stays per version.
  - `Ledger.version_live_quality(..., task=)`, `task_live_quality`, `merge_task_eval` (one transaction), `has_event` and `event_once` (new). `/ratchet/stats` `tasks[]` gains `audits`, `audit_agreement`, `threshold`, `precision`, `coverage`, `calibrated` and `disabled` (`tests/fixtures/stats_keys.json` grows); the BOM's `eval` block carries the per-task records.
  - A task whose record on the serving version serves nothing (disabled by the gate, or no held-out row) is escalated without a student call (route `task_disabled`, new): no student samples to pay for, and no below-floor student answer for `RATCHET_ON_TEACHER_FAILURE=serve_student` to serve. The shadow still runs.
  - `RATCHET_PER_TASK_CALIBRATION` (new, default `1`): `0` makes Night School write no per-task records, so new versions keep one pooled threshold and the pooled gate, as in v0.4. `scripts/reference_check.py` runs the three reference workloads with it off (`LEGACY_ENV`), so `tests/fixtures/reference.json` stays v0.4.0's capture byte for byte (a first version of this item had captured the mixed and research runs again). The tickets workload and the pinned reference simulation (one task) are unchanged with it on. On the mixed and research workloads with it on (simulation, mock models, five seeds) the student serves less (final-day share 90–96% and 65–97%, against 92–98% and 96–98% pooled) at a higher lowest daily audit agreement; README and HACKATHON_SUBMISSION give both settings' seed-7 numbers.
  - 26 new tests in the new `tests/test_calibration.py` and one in `tests/test_system.py` (22 and 728 in total at first; the review fixes added five, 751 in total), among them the per-task gate at 9 of 10, 18 of 20, 36 of 40 and 91 of 100 right, a disabled task skipping the student, the alert written once by two processes racing on one file, and the switch. Docs: ARCHITECTURE.md (per-task calibration, the gate's step 4, the tick's per-task watch), CONFIGURATION.md (the three variables, a per-task calibration section), API.md (`tasks[]` keys, the fingerprint), RUNBOOK.md (`task_disabled`, a per-task alert playbook), ROADMAP.md (the multi-task item is done), `docs/lanes/c-invariants.md` (a proposed invariant).

### Added
- **Foundations for the evidence features** ([ADR 0024](docs/adr/0024-evidence-foundations.md); invariant 17 new). The shared pieces every v0.5 evidence feature (PRD §6.16, FR-15.5) builds on, built once and switched off, so no decision and no simulation number moved: the three reference workloads below reproduce v0.4.0 exactly, every float, event text and dataset hash.
- **`ratchet/stats.py`** (new, standard library only): exact binomial tails (the smaller tail summed in log space from one `lgamma` term, so tiny p-values keep their accuracy), one-sided Clopper-Pearson bounds (`cp_lower`, `cp_upper`), `precision_pvalue`, the sample-size planner `required_rows` (59 golden rows certify 95% with no error), the exact one-sided McNemar test, Learn-then-Test over the fixed `CERT_GRID` (`ltt_fixed_sequence`), mixture e-values for a rate (`alt_grid`, `log_e_bernoulli`, `e_bernoulli`: valid however often they are looked at, with no independence assumption) and the confidence sequence they imply, and the estimators `wilson` (moved from `release.py`, which still exports it), `kish_n_eff`, `hajek_mean` and `ratio_estimate`.
- **`ratchet/merkle.py`** (new, standard library only): `KeySet`, a collapsed sparse Merkle tree over 32-byte keys with membership and non-membership proofs that stay sound against whoever built the tree (`prove`, `verify` → `included`, `absent` or `invalid`, never an error), and RFC 9162 log trees (`mth`, `inclusion_path`, `verify_inclusion`, `LogTree`).
- **One schema change for every evidence feature**, in `SCHEMA` and `MIGRATIONS`, so no later item touches the migrations: `requests` gains `threshold`, `label_p`, `student_agree`, `baseline_est_usd` and `optional_failed`; `examples` gains `origin`, `job`, `contested` and `checked_epoch`; new tables `version_leaves`, `teacher_checks`, `meta`, `receipts`, `spend`, `backfill_jobs`, `tombstones` and `erasures`; new indexes on requests (`student_version`, `audited`, `id`), `shadow_version` and `day` (the gate's and the shadow's queries no longer scan the table), and on `version_leaves(key)`, `teacher_checks(epoch)` and `erasures(status)`. Nothing writes the new columns and tables yet. An old file migrates on open; an index on a column a hand-made partial file lacks is skipped.
- **Invariant 17: committed leaves and sealed receipts are append-only**, enforced by triggers that refuse UPDATE, DELETE and a replacing INSERT on `version_leaves` and `receipts` for every connection.
- **Reserved settings**: the evidence features' 13 settings (`config.RESERVED_SETTINGS`, e.g. `RATCHET_CALIBRATION`, `RATCHET_TAKE_RATE`, `RATCHET_DB_SYNC`) and 16 `ReleasePolicy` fields (`release.RESERVED_POLICY`, e.g. `RATCHET_SEQUENTIAL`, `RATCHET_DRIFT_ALARM`) are declared with defaults that keep today's behaviour; until a feature is built, any other value stops startup with an error naming the variable and the feature (`Settings.check_reserved()` in `Ratchet` and `python -m ratchet.live`), so no setting looks like it protects something it does not. CONFIGURATION.md lists them under "Reserved settings"; RUNBOOK has the playbook.
- **`ReleasePolicy` checks its values when it is built** (`live_floor` strictly between 0 and 1, fractions from 0 to 1, whole numbers, switches 0 or 1), and `from_env` names the variable on a value that does not parse.
- **BOM schema `ratchet.bom/v2`** (scaffold): every v1 field plus `redactor` (a SHA-256 over the redaction rules and whether redaction was on; `run_night(redact_pii=)`, passed by the gateway, the simulator and `python -m ratchet.live night`) and `training.origins` (`dataset.rows` reports each row's `origin`, `live` when not recorded); `bom.manifest(commitments=, extra=)` take the later features' sections (set commitments, `teacher`, `backfill_jobs`, `erasures_honored`; any other key is refused). `bom.verify` accepts v1 and v2 and refuses any other schema; stored v1 documents are never rewritten.
- **Fixed places for later features**: `ReleaseGate.tick` is five steps (`_tick_drift`, `_tick_live`, `_tick_shadow`, `_tick_canary`, `_tick_watchers`) with identical behaviour; `run_night` has one `bom_extra` dict and documented places for early-night checks, commitments and paired evidence; `Result.request_id` carries the request's ledger row id.
- **Three reference workloads pinned to v0.4.0** (`scripts/reference_check.py`, `tests/fixtures/reference.json`, `make reference`, a CI step): tickets (seed 7, the reference simulation), mixed (seed 1) and research (seed 7), captured from v0.4.0 (commit 1f9b18c) and checked on every v0.4 day stat, the totals, each version's final state, size and dataset hash, and the event log (text may gain evidence, never change). Simulation output from mock models.

- **A task registry** (PRD FR-2.15 new, FR-1.3 and FR-2.9 extended, invariants 10 and 13 extended, [ADR 0022](docs/adr/0022-task-registry.md)).
