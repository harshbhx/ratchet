- **Two hung full runs and four CI failures, fixed at the cause** (found on PR #10; three CI jobs were still running after 35 to 55 minutes while their siblings finished in 13 to 26).
  - **A deadlock between a test's read and the sidecar's write** (ADR 0072). The ledger's writer connection has a Python function on it (`ratchet_written`, for the TEMP triggers that keep the hot-path caches fresh). SQLite runs it with the connection's mutex held and the GIL released, so it waits for the GIL; a thread that holds the GIL and reads the same connection (`execute(...).fetchone()` takes the mutex to read columns) waits for the mutex, and neither gives way (0% CPU, every thread stuck). Every `Ledger` method runs under `Ledger.locked()` for this reason. `test_serve_student_mode_answers_degraded_with_a_flag_and_a_header` called `_last_request`, which read `led.db` unlocked while a shadow job's `update_request` ran in a sidecar thread: 1 hang in 80 runs under load, with the stacks CI showed. The helper now reads under the lock, and `tests/conftest.py`'s `LedgerGuard` fails any unsynchronised use of a ledger's connection once a sidecar took a job and was not drained, so the next one is a failure and not a hang. The guard found three more readers (`test_admin`'s `audited`, `test_attribution`'s `_rows`, `test_offpath`'s `_row`, each reading a row while a job could be writing it), now under the lock too.
  - **Production had one such read, `Ledger.last_ids`**: a `_reads` method (run under the reader's lock, which the writer's does not share) that used the writer's connection. Against a thread inside `update_request` on a WAL ledger it froze a stress process 5 times in 5 in under a second. It now reads through the reader connection, the one `_reads` allows. Nothing on the request path called it (the live-run harness did, on a ledger of its own), so no request could hang; a test of the decorated methods and a child-process stress of every one that needs no arguments against `update_request` keep it so.
  - **`Runtime._purge` released the release gate's lock** (a merge in lane D2 left the end of `tick` at the end of the purge thread): `RuntimeError: release unlocked lock` in the thread when no tick ran (the warning CI showed), and when one did, the purge unlocked it, a second tick started beside it and the first one's own release failed inside a request. Removed; a test holds the lock across a purge, and `test_the_gateways_purge_never_folds_a_day_that_has_not_been_sealed`, which had acquired the lock again after the purge because it released it, no longer does (with the fix it would have waited for ever).
  - **A demo janitor thread outlived its test and reset the next test's gateway** (ADR 0133). `test_demo_caps_reset_on_click` starts the real thread with `RATCHET_DEMO_MAX_REQUESTS=250`; its callbacks read the gateway module's globals, which the `gw` fixtures rebind on reload, so a minute later, and every minute after, it reset whichever gateway ran with 250 requests logged. `test_student_learns_scout_calls_over_simulated_days` (the longest simulation, 15 s bare and about 50 s on CI) lost its live version when the wake-up fell inside it; reproduced by starting the simulation 2.5 s before the thread's first wake-up. `DemoJanitor.stop()` ends the thread at once and for good, the app's lifespan calls it, `gw` and `gw_env` end the janitor of the module they replace, and an autouse fixture fails a test that leaves one running. The simulation itself is deterministic (the same events under 7 hash seeds and with every core busy); no decision or simulation number moved.
  - **Two timing tests failed on a slow runner under coverage's tracer** (156 to 163 ms against 150, 2.3 s against 2.0, twice each): `Stream.observe` takes 47 ms bare and 123 ms traced here. The drift test's bound now stretches by how much slower a fixed yardstick loop of the same arithmetic runs in the same process (never below the 150 ms of NFR-55), and the validator test compares the exploding schema with an ordinary check of a fifth of the step budget, timed in the same rounds (it costs about 3 times as much, bare, traced or loaded; the budget raised 15 times fails).

### Fallback attribution
- **The hosted fallback student's answers are no version's** (FR-12.32, FR-8.3, NFR-2, NFR-8, [ADR 0073](docs/adr/0073-fallback-attribution.md)). Without `RATCHET_STUDENT_BASE` the fallback answered for every version, and its audited answers counted as the routed version's, so a canary could advance, be promoted or be rolled back, and the live alert fire, on another model's answers. ### Lane F2
- **Teacher watch** (PRD FR-16.7 now Done, new FR-5.40, FR-5.41, FR-6.42, FR-6.43 and NFR-57, [ADR 0033](docs/adr/0033-teacher-watch.md)). Every number Ratchet reports is agreement with the teacher, and a hosted teacher can change behind the same model name; Night School would then train on shifted labels and grade candidates against them. Repeated requests are labelled by the teacher again during escalations and audits, and `add_example` threw the second label away.
  - Checks: a stored request's first re-test in a check epoch is compared with its stored label under the task's comparators (`Ledger._check_label`, in the transaction the duplicate already writes) and recorded in `teacher_checks`; a disagreement marks the label `contested`. Only comparable labels count: the same configured teacher, temperature 0 without a reasoning effort (`router.comparable_label`; a sampled label is stored as `ledger.UNCHECKABLE`), no redaction placeholders on either side, a registered task with fields that is not pinned, both labels valid under its spec.
  - The first-re-test rule (at most one check per request per epoch) is what makes the freeze rule valid: comparing one stored label with several re-tests makes the checks dependent, and in a seeded Monte Carlo at exactly the tolerated 5% it alarmed in 30% of runs, the first re-test alone in none. For the same reason a contested label is not compared again in a later epoch, and an adjudicated label is UNCHECKABLE.
  - Freeze (FR-6.42): `ReleaseGate._tick_watchers` keeps the epoch's counts by ledger day (two indexed lookups per quiet tick) and, when a mixture over the epoch's days of `stats.e_bernoulli` against "disagreement at most `RATCHET_TEACHER_NOISE_MAX` (5%)" reaches 1/`RATCHET_ALPHA_TEACHER` (100), writes one `teacher_drift` event and sets `meta` `teacher_frozen` (once across processes). The day restarts (the spec had one e-process per epoch) catch a teacher that changes after weeks of agreeing: 129 checks after the change in the Monte Carlo, where the single e-process had not alarmed after 200. A stable teacher freezes Night School with probability at most 1% per epoch. Night School then writes `skip` ("teacher labels look unstable") and makes no teacher call until `POST /ratchet/teacher/ack` (admin key; open in mock mode) starts a new epoch (`teacher_ack`).
  - Model ids: a new `model` in the teacher's responses starts a new epoch with a `teacher_model_changed` event (`Ratchet._watch_model`, a string comparison per call; `Ledger.teacher_model_seen`). Once per id new to the epoch, so two backends that report different ids start one epoch, not one per response; a ledger error there never fails the answer; the fallback teacher is not watched.
  - Night School (FR-5.40, FR-5.41): unless frozen, up to `RATCHET_TEACHER_PROBES` (20) checkable stored labels not yet re-tested in the epoch are asked again (hash order, temperature 0, the stored conditions), also while a release is in flight; up to `RATCHET_ADJUDICATE_MAX` (50) contested labels get two more teacher answers, and a strict majority of the three becomes the label (same teacher, so provenance and license stay; INV-1, INV-2, INV-16). - **`Idempotency-Key`** (new, `ratchet/idem.py`): 1 to 255 printable ASCII characters (else a 400 `invalid_idempotency_key`), per API key (by its name, never the key). ## [0.2.0] - 2026-10-20

### Added
- **Scout**, a multi-agent research demo (`ratchet/scout/`, [docs/SCOUT.md](docs/SCOUT.md)): planner → searcher → triage → reader → writer. Every LLM call goes through Ratchet with a task name. Triage and reader calls run in a thread pool.
- Scout search: `TavilySearch` (Tavily Search API, `search_depth: basic`) in live mode, `MockSearch` (simulated results) in mock mode.
- Scout budget guard (`ratchet/scout/guard.py`): daily spend cap, daily run cap and per-IP hourly limit; spend is counted per step, so a failed run still counts.
- Scout endpoints: `GET /scout/examples`, `GET /scout/status`, `GET /scout/stream` (Server-Sent Events), `POST /scout/run` (502 when a run fails partway).
- Scout CLI: `python -m ratchet.scout "<question>" --base-url <gateway>/v1 [--api-key] [--max-results]`.
- **Pinned tasks** (`Task.pinned`): always answered by the teacher, logged, never stored as training examples.
- New tasks: `source-triage`, `page-read` (distillable), `research-plan`, `research-write` (pinned).
- **Landing page** at `/` and Scout page at `/scout` (`ratchet/web/`). The dashboard moved to `/dashboard`.
- Dashboard: navigation links, a **Traffic** selector (tickets, Scout research calls, both), a **By task** table, and error messages under the demo buttons.
- `tasks` in `GET /ratchet/stats` (`Ledger.stats_by_task`).
- `workload` parameter for `POST /ratchet/demo/day` (`tickets`, `research`, `mixed`).
- Mock research world (`sim/research.py`): 8 questions, 12 result templates × 6 variants on `example.org`. Workload streams and the shared mock item interface (`sim/world.py`). `--workload` flag for `python -m sim.simulate`.
- Mock warm-up at startup (`RATCHET_MOCK_WARMUP_DAYS`, `RATCHET_MOCK_WARMUP_REQUESTS`) and Scout pacing in mock mode (`RATCHET_MOCK_PACE`). `warmup` event kind.
- New settings: `TAVILY_API_KEY`, `RATCHET_SCOUT_DAILY_BUDGET_USD`, `RATCHET_SCOUT_RUNS_PER_HOUR`, `RATCHET_SCOUT_MAX_RUNS_PER_DAY`, `RATCHET_SCOUT_MAX_RESULTS`, `RATCHET_TRUST_PROXY`.
- **Nebius VM deploy kit** (`deploy/vm/`, [docs/DEPLOY_NEBIUS_VM.md](docs/DEPLOY_NEBIUS_VM.md)): `create_vm.sh`, `cloud-init.yaml`, Docker Compose with Caddy (automatic HTTPS, SSE pass-through, opt-in `RATCHET_API_GUARD` for `/v1/*` and `/ratchet/demo/*`), `update.sh`, `backup.sh`, `.env.vm.example`.
- `tests/test_scout.py` (14 tests). 49 tests in total.
- [ADR 0008](docs/adr/0008-pinned-tasks.md): pinned tasks.
- `pinned` per task in `/ratchet/stats` `tasks`; the Scout page labels simulated search as "Simulated search" instead of "Tavily".

### Changed
- Demo controls are safe to share: `day` and `reset` run one at a time (409 when busy) and `reset` has a 30-second cooldown (429).
- `Ledger` methods hold a re-entrant lock, because Scout's agents call the gateway from several threads.
- Mock models work on any mock item (tickets and research calls) through one interface: `labels`, `label_space`, `fragile`, `answer()`. The mock teacher also answers Scout's pinned planner and writer prompts. Ticket simulation numbers are unchanged.
- `Ratchet.handle` routes pinned tasks straight to the teacher.
- `ratchet/web/*.html` ships as package data. `.dockerignore` excludes `.env` files at any depth.
- Docs updated for all of the above: README, API, configuration, architecture, testing, deployment, threat model, glossary, PRD, roadmap, Devpost draft, demo script, runbook, AGENTS.md files.

### Added

- AGENTS.md files for the repo and each folder.
- CI (ruff, pytest on 3.10–3.13, simulation smoke test, Docker build), issue/PR templates, Dependabot, Makefile, gateway Dockerfile, `.env.example`.

- `train.py --targets` for Nemotron-H LoRA target modules.

### Fixed
- Live mode now advances the day (`Ledger(auto_day=True)`).
- Student endpoint errors fall back to the teacher; teacher errors return 502 instead of 500.
- The untuned fallback model uses the default threshold, not a tuned version's.
- Existing SQLite files are migrated on open.
- Live precision alerts fire once per version instead of every tick.
- Unknown task names no longer grow the task registry.
