## [Unreleased]

### Added
- **Generation parameters reach the models, by role** (PRD FR-1.13, FR-5.1 and NFR-3 extended, [ADR 0017](docs/adr/0017-generation-parameters-by-role.md)). Until now `max_tokens`, `stop`, `seed`, the penalties, `response_format`, `tools` and the rest were validated and dropped. New `providers.GenParams` (`from_request(chat_request)`, `from_stored(row_params)`, `only(allow)`, `to_body(allow)`) and `providers.GenPolicy` (`Settings.gen_policy()`), which gives each request a `GenPlan`: the student gets the fields in `RATCHET_STUDENT_PARAMS` (default `max_tokens,stop,seed,response_format,tools,tool_choice,logit_bias,top_logprobs`) and keeps its own `n`, temperature 0.7 and logprobs; the teacher serving an answer (escalation, cold start, pinned, teacher-only) gets the fields in `RATCHET_TEACHER_PARAMS` (default every standard field; `user`, `safety_identifier`, `store` and `metadata` never) at the client's temperature or 0; audits and arbitrations run at temperature 0 with the same limit, stops, format and tools, without `top_p`, `seed`, penalties, `logit_bias` and logprobs. `max_completion_tokens` is sent as `max_tokens`. An allowlist naming a field Ratchet sets itself (`model`, `n`, ...) stops startup; a vendor field (`top_k`) is forwarded only when listed.
- **Token caps on every model call**: `RATCHET_TEACHER_MAX_TOKENS` (8,192) and `RATCHET_STUDENT_MAX_TOKENS` (1,024); a larger client value is capped, none means the cap, 0 turns a cap off (threat model T11). `RATCHET_TEACHER_REASONING_HEADROOM` (0) adds tokens to the client's limit for a teacher that reasons before answering; a visible answer that then runs past the client's `max_tokens` is returned whole with `finish_reason: "length"` and not stored.
- `Provider.complete(messages, model, n, temperature, logprobs, response_format, params=None, **_)`: the explicit arguments win over the same fields in `params` (`logprobs=False` also drops `top_logprobs`). `OpenAICompatProvider(allow=)` narrows what a provider used on its own may send. A custom provider must accept `params`.
- **Conditions stored with each example**: new column `examples.params` (migrated on open) holds the `response_format`, `tools`, `tool_choice` and `stop` the teacher answered under (`ledger.STORED_PARAM_KEYS`, `ledger.target_params`; an audit stores its own), redacted with the new `redact.redact_json` (string values only, object keys kept; INV-12). `example_hash(task, messages, params=None)` adds them to the hashed object only when there are some, so every v0.4 hash and golden/train split is unchanged (`test_v04_example_hash_unchanged` pins two literals), and the same messages under other conditions are another example. `dataset.rows` returns `params`; `cascade_eval`'s sampler is now `sample(prompt, n, params)`, and `LiveEvaluator(policy=)` and `MockFleet(policy=)` sample the student exactly as the router would for that row.
- The response's `finish_reason` (and the last stream chunk's) is the served answer's: `stop`, `length`, `tool_calls` or `content_filter` (`Result.finish_reason`); it was always `stop`.
- `Ratchet.handle(messages, task=None, client=None, params=None, meta=None)`: `task` may be a `tasks.Task`; `router.RequestMeta(request_id, client_request_id, retry_count, storable, end_user, idempotency_key)` for later items, where `storable=False` keeps the request's teacher answers out of the training set. Scout's `handle(messages, task)` is unchanged. `teacher_only` takes `params` and `meta` too.
- The mock teacher and student honour `n`, `stop` and `max_tokens` (about 4 characters a token, `finish_reason` `length`); mock answers are short and have no stop strings, so the reference simulation is unchanged.
- 19 new tests (453 in total): 6 in `tests/test_core.py`, 5 in `tests/test_contract.py`, 4 in `tests/test_openai_compat.py` (request bodies over `MockTransport`, the real OpenAI SDK reading `length`), 2 in `tests/test_nightschool.py`, 2 in `tests/test_hardening.py`. The FR-5.1 tests now expect the student's `params` in every sampling call, and the test doubles with v0.4's fixed `complete` signature accept `params`.
- **Answer hygiene: only complete, valid teacher answers are stored** (invariant 16, PRD FR-2.13 and FR-2.7, [ADR 0016](docs/adr/0016-store-only-complete-valid-teacher-answers.md)). Storing moved from `Ratchet._call_teacher` into `Ratchet._store_example(task, messages, completion) -> bool`, now the only caller of `Ledger.add_example` (the INV-2 allowlist names it instead). It stores a teacher answer only when `router.answer_problem` finds nothing: `finish_reason` is `stop` or `tool_calls`, the answer is not empty once reasoning is stripped, and a structured task's answer is valid JSON, also after PII redaction. A skipped answer is still served, but it is not an audit (`audited=0`) and settles no shadow disagreement (`shadow_agree` NULL); a `skip_example` event (`ticket-triage: finish_reason length`) is written on the 1st, 10th, 100th and 1000th skip per reason, never quoting the answer. New column `requests.stored` (migrated on open): 1 when the request's teacher answer was inserted or bumped a duplicate's `seen`.
- `tasks.clean_answer(task, text)`: `strip_reasoning`, then for a structured task (`Task.structured`, i.e. `compare_keys`) the body of one code fence that is the whole answer when it parses as JSON; free-text answers keep their fences. `Task.canonical`, the served text (`Result.text`, on the pinned path too) and the stored completion all use it, so clients get bare JSON for structured tasks. `tasks.INVALID`.
- `Completion.finish_reason` (`stop` when the server leaves it out, `unknown` when it is not a short word) and `Completion.reasoning_tokens` (from `usage.completion_tokens_details.reasoning_tokens`), parsed per choice; `providers.COMPLETE` and `providers.CUT_OFF`. Each choice's `out_tokens` now follows its logprob count when every choice has one, and the parts always add up to `usage.completion_tokens` (split in proportion when the counts do not match it, evenly with the remainder on the first choices otherwise). `scripts/day1_check.py` prints each model's `finish_reason`; DAY1.md check 9.
- `RecordingProvider(finish_reason=...)` (a string or a scripted list) and `FakeOpenAIServer(finish_reason=...)`. 45 new tests: 18 in `tests/test_core.py` (37) and 27 in `tests/test_hardening.py` (54); 430 tests in total. The reference simulation is unchanged: mock answers are bare JSON that end with `stop`.
- **Student circuit breaker** (PRD FR-2.11, NFR-2, [ADR 0015](docs/adr/0015-student-circuit-breaker-and-adapter-reload.md)). A hung or dead student endpoint no longer costs every request its timeout: `resilience.Breaker(name, failure_threshold=5, open_s=30, max_open_s=300, clock, on_change)` opens after 5 endpoint failures in a row, and requests then go straight to the teacher (route `student_breaker`, `escalated=1`, `confidence` NULL, not counted as student errors). After `RATCHET_STUDENT_BREAKER_COOLDOWN_S` (30 s) exactly one request probes the endpoint; a failed probe doubles the wait up to 300 s, a successful one closes the breaker. Only timeouts, connection and protocol errors, unreadable answers, 5xx, 408 and 429 count (`resilience.endpoint_down`); another 4xx is the endpoint answering, and an error that is not an HTTP failure counts neither way. Breakers are made on first use per role and endpoint (`base_url`, else the provider's class): live and canary on one endpoint share `student`, and shadow calls have their own `shadow` breaker, so a bad staging adapter cannot open the live one. Every transition is a `circuit` event (`student: closed->open after 5 failures (ReadTimeout)`), and `Ratchet.health()` adds `breakers`. `RATCHET_STUDENT_BREAKER_FAILURES` (5; 0 = off) and `RATCHET_STUDENT_BREAKER_COOLDOWN_S` (30); a bad value stops startup. While closed the breaker takes no lock on the request path.
- **Automatic adapter reloads.** vLLM's 404 naming the version's adapter (an endpoint restart forgets runtime-loaded adapters) becomes `AdapterMissing`: it never counts against the breaker, the request escalates, and in live mode `live.AdapterReloader` loads the adapter again on one daemon thread, at most once per adapter per 60 s, writing `adapter_reloaded` or `adapter_reload_failed`. `python -m ratchet.live reload` stays as the manual fallback. `Ratchet(on_adapter_missing=)`, `Runtime(clock=)` and `Runtime.reloader`.
- **A route on every request**: new column `requests.route` (migrated on open): `student`, `confidence`, `cold_start`, `pinned`, `student_error`, `student_breaker`; `Result.route`; `/ratchet/stats` adds `tasks[].routes` (`{route: count}`, older rows as `unrecorded`), and `tests/fixtures/stats_keys.json` gains the key.
- Mock-only `POST /ratchet/demo/student-outage?seconds=60` (clamped to 5 to 300): the mock production endpoint refuses connections until the deadline (`MockFleet.student_outage`), so the release log shows the breaker open, the teacher answer, a probe, and the breaker close. 403 in live mode (INV-8).
- `FakeOpenAIServer(loaded=set())` plays vLLM's adapter state (404 for an adapter it does not have, `load_lora_adapter` adds it, `restart()` forgets them). 12 tests in `tests/test_resilience.py` (64 now) and `test_v04_database_gets_the_route_column` in `tests/test_hardening.py`; 377 tests in total. `test_shadow_sampling_error_counted` runs with the breaker off to keep checking the 10th-failure event, and the `health()` assertions compare the failure counters only.
- **Upstream resilience** (PRD FR-1.11, [ADR 0014](docs/adr/0014-upstream-failure-semantics.md)). New `ratchet/resilience.py`: `RetryPolicy(max_attempts=3, base_s=0.5, cap_s=8.0, deadline_s=180.0)` and `retry_call`, which retries connection failures (`ConnectError`, `ConnectTimeout`, `PoolTimeout`, `RemoteProtocolError`) and HTTP 408, 409, 429, 500, 502, 503 and 504 with full-jitter backoff or the server's `retry-after-ms` / `Retry-After` (seconds or an HTTP date); a `ReadTimeout` once at most, because its tokens may be billed; never another 4xx. A server wait over the 8 s cap, or any wait that would end past the deadline, returns the error at once, and the deadline caps each attempt's timeouts. `UpstreamError` (an `httpx.HTTPError`, re-exported from `ratchet.providers`) carries the status, the endpoint's OpenAI `type`, `code` and `param` (from OpenAI, vLLM and FastAPI error bodies), a message clipped to 300 characters and the wait; never the URL or headers. `OpenAICompatProvider(base_url, api_key, timeout, retry, transport, sleep, clock=, rng=)` raises nothing else: after its retries a timeout is 504 `upstream_timeout`, an unreachable endpoint 502 `upstream_unreachable`, and a 2xx body without choices 502 `bad_upstream_response` (not retried). Malformed usage or logprobs fields count as absent.
- Timeouts and retries per role: `RATCHET_TEACHER_TIMEOUT_S` (120), `RATCHET_TEACHER_RETRIES` (2) and `RATCHET_TEACHER_DEADLINE_S` (180) for the teacher and judge; `RATCHET_STUDENT_TIMEOUT_S` (15) and `RATCHET_STUDENT_CONNECT_TIMEOUT_S` (2) for the student, which is never retried on the request path (the teacher is its retry), so a hung endpoint costs a request seconds instead of two minutes. The hosted fallback student gets the student's settings on its own client; Night School's golden eval retries the student like the teacher. A bad value stops live mode at startup. `Runtime(settings, transports, sleep=)` injects the waits for tests.
- **Statuses a client can act on** (`gateway._map_upstream`) when the teacher's answer was needed and the teacher failed: an upstream 400, 413 or 422 is a 400 `invalid_request_error` with the teacher's message, param and code (for example `context_length_exceeded`); 401/403 a 502 `upstream_auth_error`; 404 a 502 `upstream_not_found`; 429 a 429 `upstream_rate_limited` with `Retry-After` clamped to 1 to 60 s; a timeout or 504 a 504 `teacher_timeout`; anything else a 502 `teacher_unavailable`. `X-Should-Retry: false` marks the ones no retry can fix, so OpenAI SDKs stop re-running three student samples for them. Optional-call events and Scout's error event name the status and code (`UpstreamError 504 upstream_timeout`, `a model or search call failed: upstream 503`).
- `X-RateLimit-Reset-Requests` (OpenAI's duration format, `3h12m5s`) on every response under a daily quota.
- `tests/test_resilience.py` grows from 8 to 52 tests: backoff, `Retry-After`, the deadline, the single read-timeout retry, bad bodies, error-body parsing, 14 upstream failures mapped through a live `Runtime`, the timeouts each role sends, the quota's headers at 23:00 UTC, and the real OpenAI SDK sending a refused request once. 364 tests in total.
- **Optional teacher calls fail open** (invariant 15, PRD FR-2.10, [ADR 0013](docs/adr/0013-optional-teacher-calls-fail-open.md)). When the teacher's audit, the shadow's samples or the teacher's shadow arbitration raise, `Ratchet.handle` serves the student's answer instead of failing the request; nothing is billed for the failed call. `Ratchet.health()` returns `student_errors`, `audit_errors` and `shadow_errors` (per process, counted under a lock because Scout calls `handle` from several threads), for the planned `/readyz` and `/metrics`. New `audit_error` and `shadow_error` (`sampling` or `arbitration`) events on the 1st, 10th, 100th and 1000th failure; their detail names the task or version, the exception class and the HTTP status, never the message (an httpx message carries the endpoint URL). If the audit failed, the same request's arbitration is not attempted. A teacher failure on the escalation, cold-start, pinned or teacher-only path is still a 502 (INV-7).
- `Ledger.shadow_quality` counts only rows with a shadow verdict (`shadow_serve` not NULL), returns `unarbitrated`, and counts an unarbitrated disagreement (`shadow_agree` NULL) as a disagreement in precision, because arbitration runs only on disagreements and dropping those rows would favour the candidate that disagrees most. The gate's shadow events say how many were counted that way. With no failures every number is unchanged, and so is the reference simulation.
- `tests/test_resilience.py` (8 tests): a failed audit (timeout, 503, unreadable body) still serves the student; counters and throttled events, exact under 8 threads; a failed arbitration and a failed shadow sample are silent; the same through the live gateway, where an escalation with the teacher down is still a 502. `test_shadow_gate_counts_unarbitrated_disagreements_against_the_candidate` in `tests/test_release.py`; the `_shadow` builder takes `unarbitrated_every`. 305 tests in total.
- **Strict OpenAI request validation and normalisation** (PRD FR-1.10, [ADR 0012](docs/adr/0012-openai-request-validation-and-error-envelope.md)). New `ratchet/openai_compat.py` (standard library only): `validate_chat_request` returns a typed `ChatRequest` (unknown top-level fields kept in `extra` and ignored, `max_completion_tokens` over `max_tokens`, a string `stop` as a list) and refuses malformed requests with a 400 naming the field as a JSON path in `param` and an OpenAI `code` (`invalid_type`, `invalid_value`, `missing_required_parameter`, `unsupported_value`, `invalid_json`, `context_length_exceeded`, `unsupported_content_type`): roles, content and content parts, tool messages, every sampling range, `n` (1 for now), `stop`, `logit_bias`, `logprobs`/`top_logprobs`, `metadata` (16 string values, `ratchet_task` a task name), `response_format` and `json_schema`, `tools`, `tool_choice` and the legacy function fields. `normalize_messages` turns `developer` into `system`, text content parts into one string, assistant refusal parts into text, drops message keys a role does not use (assistant `audio` and `annotations`, vendor fields), and with `RATCHET_MERGE_SYSTEM=1` merges leading system messages; plain messages come back as the same objects, so example hashes and the reference simulation are unchanged, and a request sent as text parts dedupes with its string form.
- **OpenAI's error envelope on `/v1/*` and `/openai/*`**: `{"error": {"message", "type", "param", "code"}}`, so OpenAI SDKs raise typed exceptions with `.code` and `.param`; the message is repeated as `detail` for one release. An unknown `/v1` path is 404 `unknown_url` (`Unknown request URL: POST /v1/foo.`), the API key 401 is `invalid_api_key`, the quota 429 is `rate_limit_error`, 5xx are `api_error`, FastAPI's validation errors are 400. Other routes keep `{"detail": ...}`.
- **Request limits**, checked before any model call (threat model T11): `RATCHET_MAX_BODY_BYTES` (2 MiB, 413 `request_too_large` from `Content-Length` or while counting a chunked body; `BodyLimitMiddleware`, every `POST`/`PUT`/`PATCH`), `RATCHET_MAX_MESSAGES` (256) and `RATCHET_MAX_INPUT_CHARS` (120,000; 400 `context_length_exceeded`).
- `RATCHET_TEACHER_MODALITIES` (default `text`): content part types such as `image_url` that the teacher accepts. Such a request goes to the teacher only through the new `Ratchet.teacher_only` (the pinned path: no student call, no audit, nothing stored); any other non-text part is a 400.
- An unhandled exception is a 500 `api_error` whose message never includes request text, and a `gateway_error` ledger event (class name only) at the 1st, 10th, 100th, ... occurrence.
- The daily-quota 429 carries `Retry-After` (seconds to 00:00 UTC) and `X-Should-Retry: false`, so OpenAI SDKs stop retrying it.

### Fixed
- Review fixes for the student circuit breaker (FR-2.11, [ADR 0015](docs/adr/0015-student-circuit-breaker-and-adapter-reload.md)). A probe that took longer than the cooldown (a hung endpoint with `RATCHET_STUDENT_TIMEOUT_S` above the cooldown, or a short cooldown) was presumed lost and replaced, and its failure was then ignored, so the breaker stayed half-open for the whole outage, never backed off, wrote no more `circuit` events, and put a request on the dead endpoint every cooldown. Now `Breaker(probe_timeout_s=)` keeps a probe for the longer of the wait and the call's own longest time, which the router takes from the provider (`OpenAICompatProvider.longest_call_s()`: pool, connect, write and read timeouts, 32 s by default, plus 5 s); and a lost probe that reports while the breaker is still half-open decides as the probe would, so a slow failure reopens it and doubles the wait. Once the wait is at 300 s, the repeated `open->half_open` / `half_open->open` pair is logged only for the 1st, 10th, 100th and 1000th probe at that wait (the event says which), so a long outage no longer fills the dashboard's last 40 events. `Ledger.shadow_quality` leaves requests the live student never answered (route `student_breaker` or `student_error`) out of `live_coverage`, which they lowered while the live breaker was open and the shadow's was not. The outage demo in API.md now promises one `student_error` event, not five. `_shadow(live_route=)` in `tests/fakes.py`; 4 tests (434 in total).
- Reasoning leaked into answers and training data. `strip_reasoning` removed only complete `<think>…</think>` blocks, so with a chat template that opens the reasoning in the prompt (output with only `</think>`) the whole reasoning was served and stored, and an answer cut off inside `<think>` kept it, letting a JSON object in the reasoning count as a structured answer. It now drops everything before the last `</think>` and an unterminated `<think>` with all that follows. A teacher answer cut off by the token limit, an empty one, or prose for a structured task was stored as a training target and counted as an audit; none is now (see Added). A student sample cut off by the token limit or a content filter no longer votes, an empty answer is invalid for every task, and a sample set with no valid answer is never served even with a threshold of 0. `parse_json` let `RecursionError` out on JSON nested too deeply, so such a student answer failed the request with a 500 instead of escalating; it returns None.
