## [Unreleased]

### Added
- **Optional teacher calls fail open** (invariant 15, PRD FR-2.10, [ADR 0013](docs/adr/0013-optional-teacher-calls-fail-open.md)). When the teacher's audit, the shadow's samples or the teacher's shadow arbitration raise, `Ratchet.handle` serves the student's answer instead of failing the request; nothing is billed for the failed call. `Ratchet.health()` returns `student_errors`, `audit_errors` and `shadow_errors` (per process, counted under a lock because Scout calls `handle` from several threads), for the planned `/readyz` and `/metrics`. New `audit_error` and `shadow_error` (`sampling` or `arbitration`) events on the 1st, 10th, 100th and 1000th failure; their detail names the task or version, the exception class and the HTTP status, never the message (an httpx message carries the endpoint URL). If the audit failed, the same request's arbitration is not attempted. A teacher failure on the escalation, cold-start, pinned or teacher-only path is still a 502 (INV-7).
- `Ledger.shadow_quality` counts only rows with a shadow verdict (`shadow_serve` not NULL), returns `unarbitrated`, and counts an unarbitrated disagreement (`shadow_agree` NULL) as a disagreement in precision, because arbitration runs only on disagreements and dropping those rows would favour the candidate that disagrees most. The gate's shadow events say how many were counted that way. With no failures every number is unchanged, and so is the reference simulation.
- `tests/test_resilience.py` (8 tests): a failed audit (timeout, 503, unreadable body) still serves the student; counters and throttled events, exact under 8 threads; a failed arbitration and a failed shadow sample are silent; the same through the live gateway, where an escalation with the teacher down is still a 502. `test_shadow_gate_counts_unarbitrated_disagreements_against_the_candidate` in `tests/test_release.py`; the `_shadow` builder takes `unarbitrated_every`. 305 tests in total.
- **Strict OpenAI request validation and normalisation** (PRD FR-1.10, [ADR 0012](docs/adr/0012-openai-request-validation-and-error-envelope.md)). New `ratchet/openai_compat.py` (standard library only): `validate_chat_request` returns a typed `ChatRequest` (unknown top-level fields kept in `extra` and ignored, `max_completion_tokens` over `max_tokens`, a string `stop` as a list) and refuses malformed requests with a 400 naming the field as a JSON path in `param` and an OpenAI `code` (`invalid_type`, `invalid_value`, `missing_required_parameter`, `unsupported_value`, `invalid_json`, `context_length_exceeded`, `unsupported_content_type`): roles, content and content parts, tool messages, every sampling range, `n` (1 for now), `stop`, `logit_bias`, `logprobs`/`top_logprobs`, `metadata` (16 string values, `ratchet_task` a task name), `response_format` and `json_schema`, `tools`, `tool_choice` and the legacy function fields. `normalize_messages` turns `developer` into `system`, text content parts into one string, assistant refusal parts into text, drops assistant `audio`, and with `RATCHET_MERGE_SYSTEM=1` merges leading system messages; plain messages come back as the same objects, so example hashes and the reference simulation are unchanged, and a request sent as text parts dedupes with its string form.
- **OpenAI's error envelope on `/v1/*` and `/openai/*`**: `{"error": {"message", "type", "param", "code"}}`, so OpenAI SDKs raise typed exceptions with `.code` and `.param`; the message is repeated as `detail` for one release. An unknown `/v1` path is 404 `unknown_url` (`Unknown request URL: POST /v1/foo.`), the API key 401 is `invalid_api_key`, the quota 429 is `rate_limit_error`, 5xx are `api_error`, FastAPI's validation errors are 400. Other routes keep `{"detail": ...}`.
- **Request limits**, checked before any model call (threat model T11): `RATCHET_MAX_BODY_BYTES` (2 MiB, 413 `request_too_large` from `Content-Length` or while counting a chunked body; `BodyLimitMiddleware`, every `POST`/`PUT`/`PATCH`), `RATCHET_MAX_MESSAGES` (256) and `RATCHET_MAX_INPUT_CHARS` (120,000; 400 `context_length_exceeded`).
- `RATCHET_TEACHER_MODALITIES` (default `text`): content part types such as `image_url` that the teacher accepts. Such a request goes to the teacher only through the new `Ratchet.teacher_only` (the pinned path: no student call, no audit, nothing stored); any other non-text part is a 400.
- An unhandled exception is a 500 `api_error` whose message never includes request text, and a `gateway_error` ledger event (class name only) at the 1st, 10th, 100th, ... occurrence.
- The daily-quota 429 carries `Retry-After` (seconds to 00:00 UTC) and `X-Should-Retry: false`, so OpenAI SDKs stop retrying it.
- `tests/test_openai_compat.py` (116 tests, including one case per validation rule and a sweep that swaps every field of a full request for junk and expects a 400, never a 500) and `tests/sdk_bridge.py` (`make_openai_client(app)`: the real OpenAI SDK, httpx or httpx2 as the installed version uses, against the gateway in-process). `openai>=1.40` joins the `dev` extra; `anyio` is now a declared dependency.

### Fixed
- With an audit due, a teacher error or timeout failed the whole request with a 502 although the student had a confident answer (the RUNBOOK's "planned fix" since v0.3); a teacher failure during a shadow arbitration did the same. Both now serve the student's answer, and a failed audit is logged with `audited=0` rather than not at all. A failed shadow sample was skipped without a trace; it is now counted and logged.
- Client mistakes on `/v1/chat/completions` no longer give HTTP 500: `{"messages": ["hi"]}`, a non-object `metadata` or a non-string `metadata.ratchet_task`, an unknown role, a number or `null` as user content, and OpenAI text content parts (now answered like the string form) are 400s or 200s; the four strict xfails in `tests/test_contract.py` that named API-VALIDATE-NORMALIZE pass and lost their marks. A body that is not JSON is a 400 `invalid_json` instead of FastAPI's 422. A refused request writes no ledger row and uses no quota.
- In mock mode, a request with no user message (a `StopIteration` in `sim.world.lookup`) and a Scout writer request without readable facts gave 500; both are now the mock's 400 (`mock mode only answers demo requests`). In live mode a `KeyError` from the cascade is a 500 instead of being reported as a mock-mode 400.
- `tasks.get` accepted a name with a trailing newline (`re.match` with `$`), creating a task named `"ticket-triage\n"`; names now match in full (`tasks.valid_name`, `test_task_names_match_in_full`).
- `NebiusTrainer` checked `RATCHET_STUDENT_BASE` only after it had synced the data and run the paid training job; it now checks first. `python -m ratchet.live reload` with adapters to load and no endpoint gives the same clear error instead of an httpx URL error (`test_live_night_checks_the_student_endpoint_before_paid_work`).
- Review fixes for the Night School and release-gate safety net (tests only; no production code changed). `test_retrain_from_base_on_cumulative_data` now releases every night's candidate to live through the gate, so nights 2 and 3 train while the previous adapter is the champion, and asserts every `TrainCall.base_model` and `Version.base_model` is the base model; before, every night was rejected, no version was ever live, and training on top of the live adapter (adapter stacking, FR-4.2) passed the whole suite. `test_champion_rescored_on_same_golden_set` also checks the challenger's base model. `test_shadow_promotes_and_both_rejections` tells would-serve answers apart from shadowed requests (150 requests with 75 would-serve answers stay in shadow, FR-6.4). `test_canary_holds_without_strong_evidence` pins the rollback boundary: 16 of 20 audits (Wilson upper bound 91.9%) roll back, 17 of 20 (94.8%) hold (FR-6.6).
- The reference simulation test compares only the inputs the fixture pins, so a new simulator flag whose default keeps the old behaviour no longer forces a regeneration; a changed or removed pinned input still fails. `regen_sim_reference.py --check` applies the same rule (`pinned_inputs()`, `matches()`). The fixture is unchanged.
- `RecordingProvider(exc=...)` picks the error a model in `raise_on` raises (`httpx.ConnectError` by default). `test_add_example_guard_sees_indirect_uses` drops its INV-2 marker (it tests the scanner, not the invariant). tests/CLAUDE.md says that moving an `add_example` call site replaces its `ALLOWED_ADD_EXAMPLE_CALLERS` entry, and describes how `_version` names adapters correctly.

### Added
- **PII redaction before training** (`ratchet/redact.py`, [ADR 0009](docs/adr/0009-pattern-based-pii-redaction.md)): emails, phone numbers, card numbers (Luhn), IBANs (mod-97), Aadhaar (Verhoeff), US SSNs, Indian PANs, IPv4 addresses and API secrets become `[LABEL]` placeholders in the request and the teacher's answer before `add_example`. - Endpoints: `GET /healthz`, `GET /ratchet/versions/{id}/bom`, `GET /ratchet/bom/public-key`, `POST /ratchet/redact` (preview, stores nothing).
