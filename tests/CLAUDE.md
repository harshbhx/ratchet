## The reference simulation fixture

`tests/fixtures/sim_reference_seed7.json` pins one run of the simulator (seed 7, 10 days × 2,000 requests, drift day 5, corrupted v3, mock models): every input (defaults included), the daily requests, student share, escalation rate, savings and audited agreement (4 decimal places), the ordered Night School and release events as (day, kind, version), and each version's final state and training-set size. `test_reference_simulation_unchanged` compares a fresh run with it exactly. It is the one exception to "assert on trends": later changes use it to show that legacy behaviour is byte-identical.

- A change that is not meant to alter the simulation must leave it passing. If it fails, find out why before anything else.
- A change that is meant to alter it: run `python scripts/regen_sim_reference.py`, review the diff of the JSON (one day or event per line), commit it with the change, and add a CHANGELOG line that says why the reference moved. Never edit the JSON by hand.
- Only the inputs the fixture pins are compared. A simulator flag added later, whose default keeps the old behaviour, leaves the test passing; a changed or removed pinned input fails it.
- `python scripts/regen_sim_reference.py --check` compares without writing, with the same rule (exit 1 on a difference).
- The run unsets every `RATCHET_*` variable while it runs (and restores them after), so a variable in your shell, such as `RATCHET_TEACHER_REASONING_TOKENS`, cannot move it.
- The numbers are simulation output from mock models, not measurements.

## Rules

- No network, no GPU, no API keys. The suite must pass offline in about 80 s on the CI machines' class of hardware (the reference simulation is about 10 s of that). A new test takes at most a second; a longer Monte Carlo run gets a quick version in the default suite and a full-size one marked `@pytest.mark.slow`, which is collected (so the counts in the docs still hold) but skipped unless pytest gets `--runslow` (CI passes it). Do not cite requirements from a slow test.
- Assert on trends and invariants (share rises, escalations fall after drift, rollback happens), not exact simulation numbers, except in `test_reference_simulation_unchanged`.
- Every bug fix gets a test in `test_hardening.py`; one about upstream failures (a provider erroring or timing out) goes in `test_resilience.py`.
- Gateway tests that depend on request limits or modalities pin them (`PINNED_ENV` in `test_openai_compat.py`), like the other `RATCHET_*` settings. A test that expects a 500 builds its client with `TestClient(app, raise_server_exceptions=False)`; the gateway re-raises unhandled errors after answering, so the server logs them.
- `ALLOWED_ADD_EXAMPLE_CALLERS` in `test_nightschool.py` changes only in a reviewed edit, together with the code that adds or removes a caller. The test also fails when an allowed caller stops calling `add_example`, so the list never goes stale. Moving a call site therefore means replacing its entry, not adding the new one beside it: when storing moved from `Ratchet._call_teacher` into `Ratchet._store_example` (answer hygiene, INV-16), the entry was replaced, so today the list is `ratchet.router:Ratchet._store_example` alone.
- Mark each test with the requirements it proves: `@pytest.mark.req("FR-2.1", "INV-7")` (string literals only, so the AST scan can read them), or a module- or class-level `pytestmark`. Ids come from [docs/PRD.md](../docs/PRD.md) (FR, NFR, US, SM) and the invariants in [CLAUDE.md](../CLAUDE.md) (INV-n). Never cite an unknown or replaced id; a test for a `Planned` requirement or a `Not met` metric must be `@pytest.mark.xfail(strict=True, reason=...)`. An xfail or `@pytest.mark.skip` test never counts as proof. After adding or renaming a marked test, run `make trace` and commit `docs/REQUIREMENTS.md`; if the id was in `KNOWN_GAPS` in `scripts/reqtrace.py`, remove it there.
- Keep `parametrize` argument lists literal (or a module-level list literal) so the suite size in the docs can be counted statically. Update the "N tests" lines in the docs when the count changes; `make lint` names every stale one.
- Tests that reload `ratchet.gateway` must restore state (`gw.rt.reset()`). Set `RATCHET_MOCK_WARMUP_DAYS=0` when you reload it, so a warm-up in your shell does not slow tests or change their numbers.
- Pass explicit values to `Settings(...)` for anything a test depends on (`audit_rate`, `samples`, `teacher_model`), so environment variables in your shell cannot change the result.
- Guard and breaker tests use an injected clock (`FakeClock`), never `time.sleep`. A test that makes `AdapterReloader` work waits for its thread with `reloader.join(timeout)`, never a sleep.
- Live-mode code takes its network, commands and clients as default arguments (`transport=`, `transports=`, `client=`, `http=`, `run=`, `provider_factory=`), and its waits the same way (`sleep=`, `clock=`, `rng=` on `OpenAICompatProvider`, `sleep=` on `Runtime`), so a test of retries never really waits. Use them with the fakes above; never monkeypatch `httpx` or `subprocess`. Clear the `RATCHET_*` variables a live test does not set (`_live_env` in `test_live.py`), because `Settings(mode="live")` and `ReleasePolicy.from_env()` read them.
- The deploy scripts run against `FakeNebius` and a stub `ratchet.cost`, never the real `nebius` CLI. `fixtures/nebius_endpoint_list.json` has the shape of `nebius ai endpoint list --format json` as the Nebius API defines it (`items`, `metadata.id`, `metadata.name`, `status.state`, `next_page_token`) with made-up ids; replace it with the real output (ids redacted) after the day-1 run ([docs/DAY1.md](../docs/DAY1.md) check 11).
- **`fixtures/stats_keys.json` only grows.** It lists every key the dashboard reads from `/ratchet/stats` (mirroring `Stats` in `web/src/lib/api.ts`) with its JSON type, and `test_stats_contract` checks it recursively. When the payload gains a key, add it here; never remove or retype a key, or the React dashboard and other clients break.
- **`fixtures/cost_keys.json` only grows**, by the same rule: every key the dashboard's Economics panel reads from `GET /ratchet/cost` (mirroring `CostReport`), checked by `test_cost_report_contract`.
- **`fixtures/tasks_keys.json` only grows**, by the same rule: every key the dashboard's Task registry panel reads from the task API (mirroring `TaskRegistry`, `TaskEntry` and the write results), checked by `test_task_registry_contract`. The Resilience panel's regexes are read from `web/src/pages/dashboard/*.ts` by `test_resilience_panel_contract`; keep each `export const *_RE = /.../;` on one line.
- A known bug that a planned item will fix gets a strict xfail whose reason names that item (`fixed by TASK-COMPARATORS`). The fixing change removes the marker. Write xfail marks literally (`@pytest.mark.xfail(strict=True, reason=...)`, or `marks=pytest.mark.xfail(...)` in a `pytest.param`), never through a variable: the traceability scan reads them from the source, and a hidden xfail would count as proof.
