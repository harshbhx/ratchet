# CLAUDE.md: Ratchet

Guidance for Claude (and humans) working in this repo. Read this first; per-folder CLAUDE.md files add detail.

## What this is

Ratchet is an OpenAI-compatible gateway for **license-clean distillation on open models**:

- A small student model (NVIDIA Nemotron 3 Nano 4B + LoRA, vLLM on a Nebius Serverless Endpoint) answers each request first.
- When it is unsure, the request escalates to the teacher (Nemotron 3 Ultra on Nebius Token Factory).
- Every teacher answer is logged with its provenance (teacher + license).
- Every night, Night School fine-tunes a new student, gates it on a golden set, and releases it through shadow → canary 10% → 50% → 100% with automatic rollback.
- **Scout** ([docs/SCOUT.md](docs/SCOUT.md)) is a multi-agent research demo on top: its triage and reader calls are distilled; its planner and writer calls are pinned to the teacher.

Built for the **Nebius x NVIDIA Global AI Hackathon** (deadline Oct 30, 2026, 10:30 PM IST; target submission Oct 29). Owner: Harsh Bhanushali (DualMind Labs). The product spec is [docs/PRD.md](docs/PRD.md).

## Commands

```bash
make install        # pip install -e ".[dev]"
make test           # pytest -q (794 tests, ~75 s, no network, no GPU; slow Monte Carlo runs only with --runslow)
make lint           # ruff check + ruff format --check + python scripts/reqtrace.py --check
make fmt            # ruff format + ruff check --fix
make trace          # regenerate docs/REQUIREMENTS.md after changing PRD rows, invariants or test markers
make reference      # three pinned workloads (tickets, mixed, research) must reproduce v0.4.0's behaviour (~25 s)
make sim            # 10-day simulation with a corrupted deploy (mock models)
make demo           # mock gateway (4-day warm-up) on http://localhost:8000: / story, /scout, /dashboard

make web-dev        # UI hot reload on :5173 against the gateway on :8000
make day1           # live Token Factory checks (needs NEBIUS_API_KEY; costs cents)
make docker         # build the gateway image (ratchet-gateway)
make clean          # remove caches, build output, sim_results.json, ratchet.db
```

## Invariants (do not break these)

1. **Only distillable teachers.** Every teacher goes through `licenses.require_distillable`. Never add a closed model (GPT, Claude, Gemini) as a teacher; their terms forbid training competing models. See [ADR 0001](docs/adr/0001-open-teacher-only.md).
2. **Never train on student outputs.** Training targets are teacher answers only (avoids model collapse).
3. **Golden examples are never trained on**, except requests seen `FREQUENT` (3) or more times, which move to training and leave the golden set. See [ADR 0007](docs/adr/0007-golden-set-split-and-frequent-requests.md).
4. **Champion vs challenger on the same data.** `run_night` re-scores the live version on the current golden set before comparing.
5. **No training while a release is in flight** (shadow or canary).
6. **Precision is measured on held-out data.** `cascade_eval` calibrates on even golden rows and measures on odd rows.
7. **Student failures fall back to the teacher**; a teacher failure on the serving path returns a mapped upstream status (400/429 for client causes, 502/503/504 otherwise). Never crash the request path on a student error. See [ADR 0014](docs/adr/0014-upstream-failure-semantics.md).
8. **Mock-only endpoints stay mock-only** (`_mock_only()` in `gateway.py`).
9. Model IDs and prices in `config.py` are **unverified until `scripts/day1_check.py` passes** with a real key.
10. **Pinned tasks never become training examples.** `Ratchet._teacher_only` (pinned tasks, teacher-only requests, unknown tasks under `RATCHET_UNKNOWN_TASKS=teacher`) must not call `add_example`, and pinned tasks never reach the student. Only an operator's spec (built-in, tasks file, admin API) pins a task, never a request; and Night School leaves out the stored rows of a task that is pinned now (`dataset.rows`, `cascade_eval`). See [docs/SCOUT.md](docs/SCOUT.md) and [ADR 0022](docs/adr/0022-task-registry.md).
11. **The demo budget guard must stay on in live mode.** Every Scout run goes through `Guard.admit` before it starts and `Guard.add_spend` after it ends (also on failure). Never pass `daily_budget_usd=None` or skip `_scout_precheck` in live mode. See [docs/DEPLOY_NEBIUS_VM.md](docs/DEPLOY_NEBIUS_VM.md#switching-from-mock-to-live).
12. **Redact before storing.** Everything passed to `Ledger.add_example` goes through `redact_messages` / `redact` (`redact_json` for the stored generation conditions) first when `Settings.redact_pii` is on (the default). Never store raw request text anywhere else (`requests` holds metadata only). See [ADR 0009](docs/adr/0009-pattern-based-pii-redaction.md).
13. **API keys are never stored or logged.** The ledger and `/ratchet/stats` see the key's *name* only; compare keys with `KeyRing.identify` (constant-time digests). The same holds for admin keys (`RATCHET_ADMIN_KEYS`): `tasks.updated_by` and the task events carry the admin's name. `/healthz` stays public.
14. **A BOM is written once, at training time,** from the exact train and golden rows (`run_night` → `bom.manifest`). Never rewrite a stored BOM; a signature covers the canonical JSON (`bom.canonical`), so any change must produce a new document. See [ADR 0010](docs/adr/0010-signed-adapter-bom.md).
15. **Optional teacher calls (audit, shadow arbitration) never fail a request the student already answered.** Neither do the shadow's own samples. A failure is counted (`Ratchet.health()`), logged as a throttled `audit_error` or `shadow_error` event naming the exception class (never its message), and the student's answer is served; a failed audit is not an audit, and an unarbitrated shadow disagreement counts against the shadow. A teacher failure on the escalation path still returns an upstream error. See [ADR 0013](docs/adr/0013-optional-teacher-calls-fail-open.md).
16. **Only complete, valid teacher answers are stored.** `Ratchet._store_example` (the one caller of `Ledger.add_example`) stores a teacher answer only when its `finish_reason` is `stop` or `tool_calls`, it is not empty once reasoning is stripped, and it is valid under the task's spec (it parses in the task's format, every required field is present and normalises, such as a label in its vocabulary; also after redaction; `Task.check`). Anything else is still served, but not stored, not counted as an audit and never the reference for a shadow; it is logged as a throttled `skip_example` event and `requests.stored = 0`. Clean answers with `tasks.clean_answer`, never by hand. See [ADR 0016](docs/adr/0016-store-only-complete-valid-teacher-answers.md).

17. **Committed leaves and sealed receipts are append-only.** The ledger's triggers refuse UPDATE, DELETE and a replacing INSERT on `version_leaves` (each adapter's committed training and golden sets) and `receipts` (sealed savings receipts), on every connection: a changed row would silently break the signed roots and chains built from it. A writer checks for an existing row first (`INSERT OR IGNORE` is refused too). See [ADR 0024](docs/adr/0024-evidence-foundations.md).

## Conventions

- Python ≥ 3.10, type hints, `from __future__ import annotations`. Ruff, line length 130.
- Plain, short docstrings that say *why*. No hype words in docs or UI copy.
- Tests: pure logic in `tests/test_core.py`; field comparators, task specs and what the cascade, the golden eval and the dataset do with an answer the spec refuses in `tests/test_tasks.py`; the task registry (tasks file, admin API and keys, unknown-task policy, client allow-lists, pinned rows at read time, spec changes) in `tests/test_registry.py`; Night School rules (INV-1 to INV-6, incl. the `add_example` allowlist) in `tests/test_nightschool.py`; the release gate, shadow arbitration and the canary split in `tests/test_release.py`; loop behaviour via `sim.simulate.run` in `tests/test_system.py`; regressions in `tests/test_hardening.py`; Scout, the research world and the guard in `tests/test_scout.py`; what clients, the dashboard and the license rules rely on (the gateway contract, the cascade's sampling, confidence, threshold, audit and cost semantics, the `/ratchet/stats` keys in `tests/fixtures/stats_keys.json`, which only grow) in `tests/test_contract.py`; OpenAI request validation, normalisation, the error envelope and the limits (incl. the real OpenAI SDK) in `tests/test_openai_compat.py`; upstream failures (a failed audit, arbitration or shadow sample around a served request; the provider's retries; the client statuses they map to; quota headers; the student and teacher breakers, degraded mode and the fallback teacher) in `tests/test_resilience.py`; the traceability check in `tests/test_traceability.py`; live mode, the CLIs and the deploy scripts, run offline through default-argument seams (`transport=`, `transports=`, `client=`, `run=`), in `tests/test_live.py`; cost accounting (the per-request split, compute intervals, the cost report and its recommendation, `/ratchet/cost`, the CLI) in `tests/test_cost.py`; the exact statistics of `ratchet/stats.py` (against hand-computed values, brute force and seeded Monte Carlo) in `tests/test_stats.py`; Merkle trees and the BOM v2 scaffold in `tests/test_provenance.py`; the hot path in `tests/test_perf.py`; endpoint access, scrubbed public stats, the live-mode auth guard and security headers in `tests/test_security.py`; request ids, the failures table, structured logs, `/metrics` and trace forwarding in `tests/test_observability.py`; spend and rate limits (key budgets and quotas, the spend meter and its alerts, the gateway budget's modes, rates, concurrency, the in-flight cap, key scopes) in `tests/test_limits.py`. A Monte Carlo check runs in under a second in the default suite; a full-size version is marked `slow` and runs with `--runslow`. Shared fixtures are in `tests/conftest.py`, fakes and ledger builders in `tests/fakes.py`. Assert on trends, not exact simulation numbers; the exceptions are `test_reference_simulation_unchanged`, which pins the reference run exactly (regenerate it only with `scripts/regen_sim_reference.py` and a CHANGELOG line), and `scripts/reference_check.py`, which pins three workloads to v0.4.0's behaviour (`make reference`; regenerate only with `--write` and a CHANGELOG line). Never call real APIs in tests (use `httpx.MockTransport` or `RecordingProvider`).
- A new call to `Ledger.add_example` under `ratchet/` fails `test_add_example_called_only_from_allowed_callers` until it is added to `ALLOWED_ADD_EXAMPLE_CALLERS` in a reviewed change (INV-2, INV-10).
- Behaviour change: update the PRD row and mark the proving test with `@pytest.mark.req("FR-a.b")`, then run `make trace`. A new requirement or invariant needs a `CODE` entry in `scripts/reqtrace.py`; ids never change (INV-n is the list number). Statuses follow the grammar in [PRD §6](docs/PRD.md#6-functional-requirements). `KNOWN_GAPS` only shrinks: remove an id when its test lands. See [docs/TESTING.md](docs/TESTING.md#traceability).
- Simulation numbers are **mock**. Label them as simulation anywhere they appear (README, docs, video).
- Database changes: add the column to `SCHEMA` **and** to `MIGRATIONS` in `ledger.py`; an index goes in `INDEXES`. The evidence features' columns and tables are already there (ADR 0024).
- A setting or `ReleasePolicy` field reserved for a feature not built yet (`config.RESERVED_SETTINGS`, `release.RESERVED_POLICY`) stops startup at any value but its default; the item that builds the feature removes its entries and adds its own checks.
- New env var: read it in `config.py` (or `ReleasePolicy.from_env`) and document it in [docs/CONFIGURATION.md](docs/CONFIGURATION.md).
- New endpoint: document it in [docs/API.md](docs/API.md), with its access level in the Access column, and give it a level in `ratchet/access.py` (`test_every_route_has_an_access_level` fails until both agree; an unclassified route is private in live mode).
- Architectural decision: add an ADR in `docs/adr/` and link it from `docs/adr/README.md`.
