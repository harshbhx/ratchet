# CLAUDE.md: Ratchet

Guidance for Claude (and humans) working in this repo. Read this first; per-folder CLAUDE.md files add detail.

## What this is

Ratchet is an OpenAI-compatible gateway for **license-clean distillation on open models**:

- A small student model (NVIDIA Nemotron 3 Nano 4B + LoRA, vLLM on a Nebius Serverless Endpoint) answers each request first.
- When it is unsure, the request escalates to the teacher (Nemotron 3 Ultra on Nebius Token Factory).
- Every teacher answer is logged with its provenance (teacher + license).
- Every night, Night School fine-tunes a new student, gates it on a golden set, and releases it through shadow → canary 10% → 50% → 100% with automatic rollback.
- **Scout** ([docs/SCOUT.md](docs/SCOUT.md)) is a multi-agent research demo on top: its triage and reader calls are distilled; its planner and writer calls are pinned to the teacher.

Built for the **Nebius x NVIDIA Global AI Hackathon** (deadline Oct 30, 2026, 10:30 PM IST; target submission Oct 29). Owner: Harsh Bhanushali (DualMind Labs). The product spec is [docs/PRD.md](docs/PRD.md).

## Commands

```bash
make install        # pip install -e ".[dev]"
make test           # pytest -q (1769 tests, ~120 s, no network, no GPU; slow Monte Carlo runs only with --runslow)
make lint           # ruff check + ruff format --check + python scripts/reqtrace.py --check
make fmt            # ruff format + ruff check --fix
make trace          # regenerate docs/REQUIREMENTS.md after changing PRD rows, invariants or test markers
make reference      # three pinned workloads (tickets, mixed, research) must reproduce v0.4.0's behaviour (~25 s)
make sim            # 10-day simulation with a corrupted deploy (mock models)
make demo           # mock gateway (4-day warm-up) on http://localhost:8000: / story, /scout, /dashboard
make web            # rebuild the React UI into ratchet/web/dist (commit the result)
make web-dev        # UI hot reload on :5173 against the gateway on :8000
make day1           # live Token Factory checks (needs NEBIUS_API_KEY; costs cents); DAY1_CHECKS="all --json evidence/day1/day1.json" for every probe
make live-plan      # live-run plan: requests per release stage, golden size, USD per round (free, no call)
make live-smoke     # 20 requests through the live gateway, about 5 control calls, no nights (cents; RATCHET_LIVERUN_KEY)
make live-run       # rounds of synthetic traffic with nights between (MAX_USD=30); never part of test, lint or CI
make docker         # build the gateway image (ratchet-gateway)
make clean          # remove caches, build output, sim_results.json, ratchet.db
```

No Make targets for these (run them directly):

```bash
RATCHET_MODE=mock RATCHET_MOCK_WARMUP_DAYS=4 uvicorn ratchet.gateway:app --port 8000   # demo with a trained student
python -m ratchet.scout "What is LoRA fine-tuning?" --base-url http://localhost:8000/v1   # Scout CLI

python -m ratchet.cost report [--days 7] [--json]                                         # cost report: per token vs GPU-hours, break-even
python -m ratchet.cost endpoint up|down                                                   # record the student endpoint's uptime (RATCHET_DB)
python -m ratchet.stats plan --target 0.95 --delta 0.05                                  # golden rows a certificate needs (also bound, mcnemar)
python -m ratchet.stats check bom.json --public-key <key>                                 # verify a BOM and recompute its certificate
python -m ratchet.proof verify proof.json --bom bom.json --public-key <key>               # check a training-set proof (also heldout, key)
python -m ratchet.replay --db ratchet.db [--version 3] [--sweep 0.3:0.95:0.05]            # replay a version's traffic at other thresholds
python -m sim.simulate --db sim.db                                                        # keep a simulated run's ledger (for the replay)
python -m ratchet.admin erase --reason "..." --client acme [--apply]                       # erase stored examples (dry run without --apply)
python -m ratchet.admin export examples [--client acme] [--out FILE]                       # a table as NDJSON (also requests, versions, events, erasures)
python -m ratchet.live purge [--client X] [--older-than-days N] [--dry-run]                # apply the retention windows now
python -m ratchet.live export --version N --out DIR                                      # an adapter with its BOM and NOTICE.md
python -m ratchet.importer labels.jsonl --task T --source human --attest "..." [--golden-only] [--dry-run]  # import labelled data (or --source teacher:<open model>)
python -m ratchet.receipt verify r.json --public-key <key> [--prev p.json] [--proof x.json] [--rows leaves.jsonl]  # check a savings receipt
python -m ratchet.receipt seal --db ratchet.db [--period N [--client NAME]]                # seal a ledger's receipts offline
python -m ratchet.live seal                                                               # seal every day that ended (hourly cron)
python -m sim.simulate --receipts --teacher-reasoning-mean 420                            # receipts vs the true cost (simulation)
python -m ratchet.config check [--json]                                                   # the startup config check: exit 0 clean, 1 warnings, 2 errors
python -m ratchet.admin versions                                                         # versions, switches and task pins (RATCHET_DB); also audit-log
python -m ratchet.admin rollback 7 --reason "..."                                        # also retire, promote --to canary|live, flag, pin, unpin (ADR 0064)
pytest -q --cov=ratchet --cov=sim                                                        # coverage, as in CI
python scripts/regen_sim_reference.py [--check]                                          # pinned reference simulation fixture
python scripts/reference_check.py [--only NAME]                                           # the three pinned workloads (make reference)
pytest -q --runslow                                                                      # also the slow Monte Carlo runs, as in CI
python -m ratchet.liverun plan|smoke|run [--max-usd X] [--resume DIR] [--repeat-of DIR]   # the live-run harness (ADR 0121)
python -m ratchet.liverun report DIR [--bill-usd X --bill-note T] [--repeat DIR2] [--publish]   # bill, repeat, publish
python -m ratchet.liverun verify evidence/live                                           # recompute a results file's client-side numbers
```

Always run `make lint test reference` before committing.

## Invariants (do not break these)

1. **Only distillable teachers.** Every teacher goes through `licenses.require_distillable`. Never add a closed model (GPT, Claude, Gemini) as a teacher; their terms forbid training competing models. Open teachers may also come from `RATCHET_TEACHER_LICENSES` (`licenses.install`, merged into a copy of `BUILTIN` at startup), but only under a license in `licenses.ALLOWED_LICENSES` and for a model id that is no closed family and no router alias (`licenses.closed_family`); a configured entry never replaces a built-in one, a bad file stops startup, and every BOM and NOTICE marks such a teacher `config`. Never widen the allowlist or loosen the closed-family check without a reviewed ADR. Provenance that is not a model (`licenses.SOURCES`: `human`) is never a teacher: `require_distillable` refuses it in any case, a `RATCHET_TEACHER_LICENSES` entry may not use it, and readers of stored rows ask `licenses.lookup_source`; an import of a teacher's outputs (`--source teacher:<model>`) passes `require_distillable` and the closed-family check. See [ADR 0001](docs/adr/0001-open-teacher-only.md), [ADR 0090](docs/adr/0090-licenses-travel-with-the-adapter.md) and [ADR 0091](docs/adr/0091-human-labels-as-a-provenance-source.md).
2. **Never train on student outputs.** Training targets are teacher answers or customer-attested human labels (provenance `human`: feedback corrections and attested imports, [ADR 0091](docs/adr/0091-human-labels-as-a-provenance-source.md)), never student outputs (avoids model collapse). A verdict is never a label: a `correct` verdict stores nothing.
3. **Golden examples are never trained on**, except requests seen `FREQUENT` (3) or more times, which move to training and leave the golden set. A row imported with `--golden-only` (`examples.golden_only`) is golden for good, never trained on even past `FREQUENT`, and so is every other variant of its prompt; it is refused for a prompt that may already have been trained on, checked inside the transaction that writes it (`feedback.held_out_ok`). A label that is no occurrence of its request (an import, or a correction of a request already counted) never counts toward `FREQUENT`: it starts at `seen` 0 (`ledger.seen_count`). See [ADR 0007](docs/adr/0007-golden-set-split-and-frequent-requests.md) and [ADR 0091](docs/adr/0091-human-labels-as-a-provenance-source.md).
4. **Champion vs challenger on the same data.** `run_night` re-scores the live version on the current golden set before comparing.
5. **No training while a release is in flight** (shadow or canary).
6. **Precision is measured on held-out data.** `cascade_eval` calibrates on even golden rows and measures on odd rows.
7. **Student failures fall back to the teacher**; a teacher failure on the serving path returns a mapped upstream status (400/429 for client causes, 502/503/504 otherwise). Never crash the request path on a student error. See [ADR 0014](docs/adr/0014-upstream-failure-semantics.md).
8. **Mock-only endpoints stay mock-only** (`_mock_only()` in `gateway.py`).
9. Model IDs and prices in `config.py` are **unverified until `scripts/day1_check.py` passes** with a real key.
10. **Pinned tasks never become training examples.** `Ratchet._teacher_only` (pinned tasks, teacher-only requests, unknown tasks under `RATCHET_UNKNOWN_TASKS=teacher`) must not call `add_example`, and pinned tasks never reach the student. Only an operator's spec (built-in, tasks file, admin API) pins a task, never a request; and Night School leaves out the stored rows of a task that is pinned now (`dataset.rows`, `cascade_eval`). A pinned task takes no human or imported label either (`feedback.store_label`; `python -m ratchet.importer` refuses it before it reads a row). See [docs/SCOUT.md](docs/SCOUT.md) and [ADR 0022](docs/adr/0022-task-registry.md).
11. **The demo budget guard must stay on in live mode.** Every Scout run, judge runs included, goes through `Guard.admit` before it starts and `Guard.add_spend` after it ends (also on failure). Never pass `daily_budget_usd=None` or skip `_scout_precheck` in live mode. Live mode restores the guard's daily counters from the ledger at startup (`Guard.restore`, `scout_run` spend rows), so a restart never resets them ([ADR 0120](docs/adr/0120-judge-access-and-a-persistent-scout-guard.md)). See [docs/DEPLOY_NEBIUS_VM.md](docs/DEPLOY_NEBIUS_VM.md#switching-from-mock-to-live).
12. **Redact before storing.** Everything passed to `Ledger.add_example` goes through `redact_messages` / `redact` (`redact_json` for the stored generation conditions) first when `Settings.redact_pii` is on (the default). Never store raw request text anywhere else (`requests` holds metadata only). See [ADR 0009](docs/adr/0009-pattern-based-pii-redaction.md).
13. **API keys are never stored or logged.** The ledger and `/ratchet/stats` see the key's *name* only; compare keys with `KeyRing.identify` (constant-time digests). The same holds for admin keys (`RATCHET_ADMIN_KEYS`): `tasks.updated_by` and the task events carry the admin's name. `/healthz` stays public.
14. **A BOM is written once, at training time,** from the exact train and golden rows (`run_night` → `bom.manifest`). Never rewrite a stored BOM; a signature covers the canonical JSON (`bom.canonical`), so any change must produce a new document. A BOM carries the base model's license and the exact `NOTICE.md` text with its SHA-256 (`notices`); whatever writes a NOTICE next to a trained adapter from its BOM (`live.publish_bom`, `python -m ratchet.live export`) writes the text the BOM signed (`notices.bom_notice`), never a re-rendered one. See [ADR 0010](docs/adr/0010-signed-adapter-bom.md) and [ADR 0090](docs/adr/0090-licenses-travel-with-the-adapter.md).
15. **Optional teacher calls (audit, shadow arbitration) never fail a request the student already answered.** Neither do the shadow's own samples. A failure is counted (`Ratchet.health()`), logged as a throttled `audit_error` or `shadow_error` event naming the exception class (never its message), and the student's answer is served; a failed audit is not an audit, and an unarbitrated shadow disagreement counts against the shadow. A teacher failure on the escalation path still returns an upstream error. See [ADR 0013](docs/adr/0013-optional-teacher-calls-fail-open.md).
16. **Only complete, valid teacher answers are stored.** `Ratchet._store_example` and `feedback.store_label` (human and imported labels, ADR 0091) are the only callers of `Ledger.add_example`. `_store_example` stores a teacher answer only when its `finish_reason` is `stop` or `tool_calls`, it is not empty once reasoning is stripped, and it is valid under the task's spec (it parses in the task's format, every required field is present and normalises, such as a label in its vocabulary; also after redaction; `Task.check`). Anything else is still served, but not stored, not counted as an audit and never the reference for a shadow; it is logged as a throttled `skip_example` event and `requests.stored = 0`. Clean answers with `tasks.clean_answer`, never by hand. `store_label` stores a label only when it is valid under the task's spec after `tasks.clean_answer` (`Task.check`, also after redaction; a correction the spec refuses is a 400, an imported row it refuses is counted as invalid), and on an existing example replaces the stored label only when it is stronger (teacher < a client's correction < an operator's import) or as strong and from the same writer, in one write transaction (`Ledger.atomic`). See [ADR 0016](docs/adr/0016-store-only-complete-valid-teacher-answers.md).

17. **Committed leaves and sealed receipts are append-only.** The ledger's triggers refuse UPDATE, DELETE and a replacing INSERT on `version_leaves` (each adapter's committed training and golden sets) and `receipts` (sealed savings receipts), on every connection: a changed row would silently break the signed roots and chains built from it. A writer checks for an existing row first (`INSERT OR IGNORE` is refused too). See [ADR 0024](docs/adr/0024-evidence-foundations.md).
18. **An admin key typed into the dashboard stays in the page's memory.** The web app never writes an admin key to `localStorage`, `sessionStorage`, IndexedDB, a cookie or a URL, and sends it only as an `Authorization: Bearer` header (`adminHeaders` in `web/src/lib/api.ts`); the theme is the only thing it keeps in browser storage. `test_dashboard_admin_key_stays_in_memory` scans `web/src`. See [ADR 0100](docs/adr/0100-dashboard-task-writes-and-derived-breaker-state.md).
19. **Dashboard status is what the gateway reports.** A breaker's state, the outage drill's countdown and a failed probe's wait come from a field or an event the gateway sent, parsed with the regexes in the dashboard's source (`CIRCUIT_RE`, `OUTAGE_RE`, `WAIT_RE`); a breaker no recent event moved shows "No recent change", never closed. Changing the text of a `circuit` event (`Ratchet._circuit_event`) or the drill's `fault` event changes that grammar in the same change; `test_resilience_panel_contract` checks it against the gateway's own events. See [ADR 0100](docs/adr/0100-dashboard-task-writes-and-derived-breaker-state.md).
20. **Every simulation number on the story page is the reference run's.** The literals in `web/src/lib/sim.ts` ("Watch it learn"'s days and totals, `SIM_COST_REPORT` with its explanation word for word) are a fresh run of the command the page prints, at the precision each is written with, and are labelled Simulation wherever they appear. A change that moves the simulator or the cost report updates them, and rebuilds `ratchet/web/dist`, in the same change (`test_story_simulation_numbers_match_reference_run`).
21. **The story's trust claims are what the code does.** The "Built to be checked" chapter (`web/src/pages/landing/trust-model.ts`, `sections/checked.tsx`) names only files that exist, the redactor's own rules, the release gate's defaults, invariants that say what it says, routes that are served and commands that print what it shows; work still being built is named only as v0.5, where the PRD plans it and its foundations are in the code (`test_story_trust_claims_match_code`).
22. **Opt-outs only reduce storage.** `store: false`, `X-Ratchet-Store: none`, `metadata.ratchet_store`, a key's `store=0`, no-store tasks, no-train end users and zero retention (`RATCHET_STORE_EXAMPLES=0`) never create or bump an example, and nothing in a request can undo one (`store: true` is the default spelled out). `Ratchet.store_opt_out` is the one rule: `handle` settles it once, and `_store_example`, like every other caller of `Ledger.add_example`, asks again before writing. The cascade runs as usual under an opt-out (audits and arbitrations included); pinned tasks are unchanged and redaction still applies. See [ADR 0080](docs/adr/0080-storage-opt-outs-and-pseudonymous-end-users.md).
23. **End-user identifiers are never stored or logged.** A request's `user` and `safety_identifier` are hashed in `gateway._request_meta` with `privacy.EndUsers.hash` (HMAC-SHA256 under the deployment's key, scoped to the API key name, 16 hex digits) and go no further: only the hash reaches the router, the ledger and the no-train table, and no error message, event or `/ratchet/stats` field quotes the value or the hash. Like invariant 13 for API keys. See [ADR 0080](docs/adr/0080-storage-opt-outs-and-pseudonymous-end-users.md).
24. **An erased example is gone for good and leaves hashes only.** An erasure (`privacy.erase`) removes an example's messages, answer, stored conditions and end-user hash and tombstones its hash: `Ledger.add_example` refuses that hash from then on, from any client, and nothing restores it (a retention purge, by contrast, may be undone by a storable duplicate). The erasure record (`erasures`, `erasure_items`, `tombstones`, the `erase` event) holds hashes, counts, names and a redacted reason, never request text or a raw end-user value. Versions that may have been trained on the erased examples are reported, never edited; their signed BOMs stay as written (invariant 14). Never hard-delete an example row: Night School's frequency rule and new-data count read the tombstone. See [ADR 0081](docs/adr/0081-retention-tombstones-erasure-and-export.md).
25. **Request retention never removes a release's evidence.** `Ledger.fold_requests` never folds or deletes a request row newer than the `stage_since` of a version in shadow or canary, nor a row such a version served or shadowed in an earlier stage (the anytime-valid rule counts its whole life, ADR 0025), and every stats reader adds the folded sums (`daily_rollup`) back, so a release decision and every figure but distinct end users are the same before and after a fold. The first fold records day 1's start in `meta`, so day numbers never shift. See [ADR 0081](docs/adr/0081-retention-tombstones-erasure-and-export.md).
26. **Human verdicts never promote or roll back a version.** Feedback (`POST /v1/ratchet/feedback`) feeds each task's `human_agreement` and each version's human precision on the answers it served itself, which `/ratchet/stats` reports and `feedback.check_human_alert` alerts on (one anytime-valid `human_alert` event per version); `ReleaseGate` never reads the `feedback` table, because clients report what they notice and the sample is biased. The audited precision stays the release signal. An API key gives verdicts on its own requests only; any other request id is the same 404 as an unknown one. See [ADR 0091](docs/adr/0091-human-labels-as-a-provenance-source.md).
