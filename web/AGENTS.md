# AGENTS.md: `web/` (React app)

The UI for `/` (the story), `/scout` and `/dashboard`. Vite 8, React 19, TypeScript, Tailwind v4, motion, lucide-react, recharts, react-router v8. Read [DESIGN.md](DESIGN.md) before changing anything visual.

## Commands

```bash
make web                                         # npm ci && npm run build -> ratchet/web/dist
make demo                                        # gateway on :8000 (serves the built UI)
make web-dev                                     # hot reload on :5173, API proxied to :8000
RATCHET_API=http://localhost:8831 npx vite       # dev server against another gateway
npx tsc --noEmit -p .                            # typecheck
npm test                                         # tests/*.test.mjs: pure helpers under Node's test runner (Node 22.6+)
```

## Rules

- **The build is committed.** `ratchet/web/dist` ships inside the Python package so `pip install .` and the Docker image serve the UI without Node. After any change in `web/`, run `make web` and commit `ratchet/web/dist`. CI fails if the committed build is stale.
- The gateway serves `dist/index.html` for `/`, `/scout`, `/dashboard` and mounts `/assets`. If `dist` is missing, it falls back to the hand-written pages, which also stay at `/lite`, `/lite/scout`, `/lite/dashboard`. New top-level routes need a matching route in `ratchet/gateway.py`.
- **Pure helpers get tests.** A `*-model.ts` file that turns report numbers into what the page prints (scales, tick labels, labels, empty states) can be tested in `tests/*.test.mjs` with `node:test`; `tests/ts-hooks.mjs` resolves `@/` and strips the types, so the module must not import JSX. `npm test` runs them, CI's `web` job runs it, and `test_economics_panel_helpers`, `test_story_page_helpers` and `test_who_model_helpers` run them from `make test` when Node 22.6+ and `node_modules` are present.
- **Simulation numbers are pinned to the run.** Every number in `src/lib/sim.ts` (the days, totals and `SIM_COST_REPORT`) is checked against a fresh reference run at the precision its literal is written with (`test_story_simulation_numbers_match_reference_run`); when the simulator or the cost report moves, update the literals from `python -m sim.simulate --days 10 --requests 2000 --bad-deploy-version 3` (`cost` in its JSON). The story's trust claims (`trust-model.ts`) are held to the code the same way (`test_story_trust_claims_match_code`).
- **The daily limit shows recorded results, never a dead end.** The live demo's edge gives each visitor 3 "Try a real request" calls and 3 Scout runs a day (`deploy/cloudflare-live`). On a 429 with `error.code` `daily_limit_reached` ("Try a real request", `isDailyLimit` in `try-request-model.ts`) the box says so and offers the four answers in `src/data/recorded-tries.json` (recorded from the live demo on 27 Oct 2026, labelled "Recorded on ... · not a live call", same badge as a live answer); on Scout, a run error that starts "Daily limit reached" (`isScoutDailyLimit`) shows `DailyLimitNotice` with the gateway's recorded runs. Other 429s keep the generic message. Never edit the recorded texts; add an entry only from a real call, with its date.
- **Links to an anchor on another page** (`/dashboard#redactor`) work: `Layout` waits for the element, scrolls to it, and keeps it in place for a few seconds while panels above it load, unless the reader scrolls first.
- API types live in `src/lib/api.ts` and mirror [docs/API.md](../docs/API.md) and [docs/SCOUT.md](../docs/SCOUT.md). Change both sides together.
- Color carries meaning: `owned` (blue) = the student (Nano with the adapter you own), `rented` (orange) = the teacher you rent. Who answered a call is always `WhoBadge` (`whoLabel`): pass the call's `model`, because only it tells our adapter from the hosted fallback. Status colors (`good`/`warn`/`bad`) are for state only and always come with an icon or a word.
- Every number is live from the API, labelled **Simulation** (`src/lib/sim.ts`), or a linked third-party fact. No invented numbers, testimonials or logos.
- Web content (Scout search results) is rendered as React text only; links go through `safeHref`. Never use `dangerouslySetInnerHTML`.
- No external scripts, fonts or CDNs at runtime: fonts are bundled from `@fontsource-variable`.
- Browser storage holds the theme and nothing else. A key the operator types (the admin key) lives in React state and goes out only as an `Authorization: Bearer` header (`adminHeaders` in `api.ts`); `test_dashboard_admin_key_stays_in_memory` scans `src/` for this.
