# Publication audit: harshbhx/ratchet (Oct 22, 2026)

**Verdict: fix first. You don't need to rotate any keys.**
1. No real credential, private key, `.env`, database or personal file appears in the working tree or the history of any public ref (28 branches and 22 PR refs, 619 commits, all scanned).
2. AI attribution is public. Three stale branches and eight GitHub PR refs carry 62 commits authored by `Claude <noreply@anthropic.com>`, 63 `Co-Authored-By: Claude` trailers and 59 `Claude-Session` links. Two PR descriptions say "Generated by Claude Code". `main` is clean: 0 such commits or trailers, and its only contributor is harshbhx.
3. Two licensing problems to settle before the submission. The React Bits code in `docs-site/` goes against the repo's own license register, and the Aceternity ports have no license notice. The README's claims and simulation numbers check out from a clean clone.

Method: I made a mirror clone of `https://github.com/harshbhx/ratchet`, which brings `refs/pull/*` too. On it I ran gitleaks 8.21.2 over `--all`, then regex sweeps over every revision of every ref (`git rev-list --all | xargs git grep`) for credential shapes (AWS, GitHub, GitLab, Slack, SendGrid, Twilio, Anthropic, OpenAI `sk-proj`, HF `hf_`, Tavily `tvly-`, Google `AIza`, JWT, npm, PyPI, NVIDIA `nvapi-`, Replicate, DigitalOcean, private-key blocks, DB URLs with passwords, SSH keys), emails, IPs, home paths, internal hostnames and Nebius resource ids. I also tallied authors, committers and trailers per ref, and read PR bodies, PR comments and reviews through the REST API. Finally I collected the test count and ran the README simulation in a fresh clone of `main` (`3c9d063`).

### MEDIUM 1 (resolved 23 Oct): React Bits code in the repo contradicts the repo's own license analysis
- **Resolution:** the owner has the React Bits author's approval to use and redistribute these components in this repo, so no change is needed. Record the approval next to `docs-site/src/components/rb/LICENSE.md` and update `design/ASSET_AND_LICENSE_REGISTER.md` so the two no longer disagree.
- **Where:** `docs-site/src/components/rb/`: 12 components (BlurText, CountUp, FadeContent, GradientText, LogoLoop, ShapeGrid, ShinyText, SpotlightCard, Stepper, …) under "MIT + Commons Clause" (`rb/LICENSE.md`). Merged in PR #14.
- **Problem:** `design/ASSET_AND_LICENSE_REGISTER.md` §"Why React Bits code was not copied" says the Commons Clause forbids redistributing the components "whether alone, in a bundle, or as a ported version", and that "vendoring a port into this Apache-2.0 repository would be such a redistribution". `docs-site/` does exactly that. `rb/LICENSE.md` and `docs-site/README.md` do keep the license separate, which is the right shape. But a public GitHub repo that publishes the source is arguably a redistribution of the components themselves. The README badge and `pyproject.toml` also say Apache-2.0 for the whole repo without naming the exception.
- **Fix (owner's call):**
  - (a) Rewrite the 12 components from the idea only, as was done for `web/src/components/fx/`, then delete `rb/`. This is the cleanest option.
  - (b) Or get written permission from the author (David Haz).
  - Either way, add one line to the README's license section: "Except `docs-site/src/components/rb/` (MIT + Commons Clause)".

### MEDIUM 2: Aceternity UI ports carry no license notice
- **Where:** 10 files in `web/src/components/fx/` (`background-beams.tsx`, `bento-grid.tsx`, `compare.tsx`, `highlight.tsx`, `hover-grid.tsx`, `lamp.tsx`, `moving-border.tsx`, `text-generate.tsx`, `timeline.tsx`, `tracing-beam.tsx`). - **Problem:** each header says "ported from Aceternity UI's …, MIT". None includes a copyright line or the MIT permission notice, and `NOTICE` does not mention Aceternity. MIT requires the notice in copies. The register itself says the MIT status "rests on the site's statement rather than a file".
- **Fix:** confirm the license with Aceternity (Manu Arora). Then add a `THIRD_PARTY_NOTICES.md`, or a NOTICE section, with Aceternity's copyright line and the MIT text, and point each header at it. If the license can't be confirmed, replace the ports with original code, as the register already suggests.

  `.env.vm.example` stays tracked because it is already in the index. If you want `!` rules for the example files, add `!deploy/**/.env*.example`. The Dockerfile copies only named paths, so the image is not affected.
