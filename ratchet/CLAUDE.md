# CLAUDE.md: `ratchet/` (core package)

## Request path (`router.py`)

`Ratchet.handle(messages, task=None, client=None, params=None, meta=None, n=1)`: `task` is a name or a `tasks.Task`; `n` is the number of choices (FR-1.14, [ADR 0020](../docs/adr/0020-n-choices-and-token-logprobs.md)); `client` is the API key name; `params` are the client's generation parameters (`providers.GenParams.from_request(req)`); `meta` is a `RequestMeta` (request ids, `storable` and `store_opt_out`, the end user's hash; later items fill more). The gateway passes `client`, `params`, `meta` and `n`; Scout and the simulator call `handle(messages, task)`.

Storage opt-outs (FR-13.1, FR-13.2, [ADR 0080](../docs/adr/0080-storage-opt-outs-and-pseudonymous-end-users.md)). `Ratchet.store_opt_out(task, meta)` is the one rule: `global` (`Settings.store_examples` False), `task` (`task.store` False or `self.no_store_tasks`, RATCHET_NO_STORE_TASKS parsed in `__init__`), the caller's verdict (`meta.storable` False → `meta.store_opt_out` or `request`; the gateway's `_request_meta` sets `key` and `request`), else `end_user` when `meta.end_user` or any of `meta.end_user_aliases` (the request's `user` beside its `safety_identifier`, and the every-client scope; looked up, never stored) is in `no_train` (`Ledger.is_no_train(*hashes)`, one query). `handle` and `teacher_only` settle it once on the request's own copy of its meta (`_opted_out` never changes the caller's object) and log it as `requests.store_opt_out` with `requests.end_user`; `_store_example` asks again, so a registration made mid-request still holds, writes that late reason onto the request's meta (so `handle` logs and returns it), and an opted-out request does no second lookup. Opt-outs only remove storage: never add a path that stores despite one, never let a request field set `storable=True` over another opt-out, and keep the cascade identical under an opt-out (audits and arbitrations still run). `RequestMeta.end_user` is always the HMAC (`privacy.EndUsers.hash`, scoped to the API key name), never the raw `user` / `safety_identifier`, which goes no further than `gateway._request_meta` (invariants 22 and 23). `_call_teacher`, `_arbitrate` and `_store_example` take the request's `client`, which the example records.

0. Unknown task under `RATCHET_UNKNOWN_TASKS` (`self.unknown_tasks`, read in `__init__`, so a typo stops startup): `reject` raises `tasks.UnknownTask` (`_admit`); `teacher` → `_teacher_only(..., route="unknown_task")`. Pinned task (`tasks.get(name).pinned`) → `_teacher_only()` (route `pinned`): teacher answers, request logged, **no** `add_example`, no student/audit/shadow. Return. An unknown task is one whose `source` is `adhoc` (`tasks.get` made it up for the name); `distill` (the default) treats it like any other. `teacher_only` keeps route `unknown_task` for such a task under `teacher`. `task_for` (the gateway's admission) raises `UnknownTask(..., invalid=True)` for a name that is not a task name (an `X-Ratchet-Task` header) under `teacher` and `reject`; under `distill` it means `default`, as in v0.4.
1. `_pick_version(flags)`: canary gets `traffic_pct`% of requests, otherwise live; `None` on cold start → teacher, and `None` while an operator turned the student off (`student_disabled`: route `student_disabled`, no shadow either). `handle` reads `Ledger.flags()` once, first (ADR 0064): the switches for this request, and the runtime pins `_task` applies (a pinned task goes to `_teacher_only` above); the runtime `audit_rate` replaces `Settings.audit_rate` in step 4 (the draw is made either way).
2. Student: `n = max(Settings.samples, plan.n)` samples with `confidence.STUDENT_SAMPLING` (temperature 0.7, logprobs on) → `confidence.score()` on the first `Settings.samples` of them, exactly as calibrated (more samples raise the best sample's token probability, so never score the extras), and `confidence.majority(task, sc, samples, plan.n)` for the choices. The golden eval (`LiveEvaluator`, `MockFleet`) uses the same constant; change sampling in that constant, never inline. `_sample` goes through the endpoint's breaker first (below): when it is open, `CircuitOpen` → teacher, route `student_breaker`, not counted as a student error. Before that, a task whose current per-task record on the version serves nothing (`calibration.held_back`: disabled by the gate, or no held-out row) is not sampled at all → teacher, route `task_disabled`, so it costs no student call and degraded mode has no student answer to serve for it (FR-14.1).
3. Serve the student if `sc.valid` (at least one sample was a valid answer; a sample that did not end by itself, `finish_reason` other than `stop` or `tool_calls` as for the teacher, gets no vote), `confidence >= threshold(version, model, task)` and `majority` found `plan.n` agreeing samples (always, for one choice); a confident student without them escalates with route `n_choices`. Choice 0 is `sc.answer`, the sample a one-choice request serves. The threshold comes from the version's eval (calibrated); the untuned fallback model uses `Settings.confidence_threshold`. For a task whose spec changed since the version was scored (`spec_changed`: the version's `eval['spec_hashes']` records another `spec_hash` for it) it is `confidence.SERVE_NOTHING` (1.01), so the teacher answers (route `confidence`) until a night scores the version under the new spec (FR-2.15); the shadow's threshold follows the same rule. Pass the task wherever a threshold is read. `threshold` is per task since FR-14.1 (`calibration.threshold`, [ADR 0040](../docs/adr/0040-per-task-calibration.md)): the task's own record in the version's eval under its current spec, 1.01 when the spec changed or the gate disabled the task, else the global threshold; a dict lookup, keep it that way.
4. With probability `audit_rate` (for a canary, `Settings.canary_audit_rate` when set: audit focusing, [ADR 0025](../docs/adr/0025-anytime-valid-release-gate.md); still exactly one `rng.random()` draw per served answer), the teacher also answers a served request (quality signal + free training data). The rate drawn at is logged as `requests.label_p`, 1.0 when the student answered and the request escalated, NULL without a student answer: the designed labelling probability the ledger replay (FR-16.5) weights by. Never add a draw or change the rate without logging it there. If that call raises, the student's answer is served anyway: `audited=0`, `audit_errors` + 1, a throttled `audit_error` event (INV-15). A teacher answer that `answer_problem` rejects is not an audit either (`audited=0`, INV-16), and is no shadow reference (step 6).
5. Otherwise, or if the student call raised, escalate: teacher answers (when it is unavailable: the fallback teacher, then with `serve_student` the student's own valid answer, below; else the error). Every teacher call goes through `_call_teacher`, which calls `_store_example`, the one caller of `add_example` (INV-2). It stores only a complete, valid answer (INV-16, `answer_problem`: `finish_reason` `stop` or `tool_calls`, then `Task.check`: not empty after `tasks.clean_answer`, parseable in the task's format, every required field present and normalising, also after redaction), and nothing for a task with `store=False` (not a skip), cleaned with `tasks.clean_answer`, after `redact_messages`, `redact_json` and `redact` replace identifiers (when `Settings.redact_pii`) with one `redact.Pseudonymizer` per example in the task's style (`task.redact_style or self.redact_style`), messages, then conditions, then the answer, so the hash never depends on the answer (a detector failure stores nothing, `redaction failed`), with its license and the placeholder count. Anything else is served but skipped, with a `skip_example` event on the 1st, 10th, 100th and 1000th skip per reason (task and reason only, never the answer). It returns whether it stored (an insert, or a duplicate's `seen` bumped), which goes into `requests.stored`. The license recorded is the one `Ratchet.licenses` holds for the configured model that answered (the teacher's, or the fallback teacher's), never looked up from the response's `model` string.
6. Shadow: if a version is in `shadow`, it runs the same cascade silently. A would-serve answer that disagrees with a live-student answer is arbitrated by the teacher (`_arbitrate`). Neither can fail the request (INV-15): a failed shadow sample leaves no shadow record, a failed arbitration (or one skipped because the audit already failed) leaves `shadow_agree` NULL, which `Ledger.shadow_quality` counts as a disagreement. A failed shadow sample and a failed arbitration add to `shadow_errors` and write a throttled `shadow_error` event. An escalation or arbitration answer that `answer_problem` rejects (INV-16) also leaves `shadow_agree` NULL, without counting as an error or writing an event; an audit answer it rejects is ignored, so the shadow is compared with the served answer as if no audit had run.
7. `ledger.log_request(...)` (its return value, the row id, is `Result.request_id`, which receipts and replays name a request by; not `RequestMeta.request_id`, the caller's own id) with `wall_ms` (`self.timer()`, `time.perf_counter` by default, read once at the top of `handle` / `teacher_only` and once just before this call; `_teacher_only(t0=)` carries the start; ADR 0060), `cost_usd`, `baseline_cost_usd` (= the all-teacher cost of this request, one teacher answer per choice), its split `student_cost_usd` / `teacher_cost_usd` and the student calls' tokens (FR-15.1, below), `stored` and `route` (`ROUTES`: `student`, `confidence`, `cold_start`, `pinned`, `student_error`, `student_breaker`, `degraded`, `fallback_teacher`, `n_choices`, `unknown_task`; `Result.route` too). `Ledger.shadow_quality` counts an `n_choices` row as live-served (the shadow's verdict uses the one-choice rule). Every path that logs a request sets a route; a new path adds its value to `ROUTES`, API.md's routes table and `test_every_request_row_has_a_route`. The ledger replay's fields (FR-16.5, [ADR 0028](../docs/adr/0028-designed-propensity-replay.md)), logging only (no model call, no random draw): `threshold` (the value the student's answer was compared with; NULL without a student answer), `label_p` (the audit rate the served answer was drawn at, 1.0 on an escalation after a student answer; a change to how audits are drawn keeps one draw per served answer and sets this to the rate it used), `student_agree` (`task.agree` of the student's answer and the primary teacher's valid answer from the escalation or a random audit; equal to `audit_agree` on audited rows; never from an arbitration, the fallback teacher, a degraded answer, an invalid student or teacher answer, or an escalation the teacher answered under other conditions than an audit's: `_labels_like_audit(plan)` needs one choice and `plan.serve` equal to `plan.check` once `logprobs` and `top_logprobs` are set aside, so a client temperature, seed, `logit_bias`, penalty or n > 1 leaves it NULL; every label is the teacher's deterministic answer) and `baseline_est_usd` (`_formula_baseline` for every student answer: over `picked`, or the student's answer once per choice; the served baseline is that same value when no teacher answered, so `baseline_cost_usd` never moved).

Off-path checks ([ADR 0072](../docs/adr/0072-off-path-audits-and-shadow.md), FR-12.31). Steps 4 and 6 live in `_audit` and `_shadow`, which the request path and `_finish_offpath` both call; never put audit or shadow logic back inline in `handle`. `_offpath(meta)` (a `RequestMeta` with `offpath`, and `self.sidecar.accepting`) decides whether they run after the response: then the audit is still **drawn** in `handle` (every `self.rng` draw stays on the request path in its order), a place is reserved (`sidecar.reserve(priority=True, size=job_bytes(messages))` for a job with an audit; a shadow rides with it or reserves a plain place; the size counts against `max_bytes`, since the job keeps the messages), the row is logged with `audited` 1 / `audit_agree` NULL and `shadow_version` set / `shadow_serve` NULL, and the `OffPath` job is submitted after `log_request` (a failing `log_request` cancels the place; a refused submit runs the job inline). No place: the audit runs inline (`_sidecar_full("audit")`; an audit is never dropped), the shadow is skipped (`_sidecar_full("shadow")`). `_finish_offpath` ends with one `Ledger.update_request(row, ...)`: verdicts (written only while pending), `add_<column>` lists summed in the request path's order (so the floats equal an inline run's), `stored`, the audit's baseline; it adds the overhead to `ratchet_cost_usd_total` and, only for a job with an audit, the request's baseline to `ratchet_baseline_usd_total` (which `_count_request` skipped for it; a shadow-only request's baseline was counted on the request path). An audit that ran inline before a shadow got a place is the shadow job's reference (`OffPath.reference`, `OffPath.teacher_failed`), as on the request path. The arbitration off the path passes `deadline_s=ARBITRATION_DEADLINE_S` down to the provider (`OpenAICompatProvider.complete(deadline_s=)` only shortens the retry deadline); the audit never gets a shorter deadline (a slow audit dropped more often would bias the sample). Callers without meta (Scout, the simulator, the warm-up) stay inline, so the reference runs cannot move; keep it that way. `test_offpath_checks_leave_the_rows_an_inline_run_writes` compares the two paths row for row: extend its script when the audit or shadow rules change.

Fallback attribution ([ADR 0073](../docs/adr/0073-fallback-attribution.md), FR-12.32). An answer is a version's only when the resolver named its `adapter_uri` (`_own`); the hosted fallback student names its own id. `handle` logs `student_model` (and `shadow_model` with `shadow_version`), and for another model's answer returns `version` None, `model` the configured id and `_student_fingerprint` without a version. The shadow is resolved once per request in `_shadow_student`, before any sidecar place, and does not run when it is not its adapter (a raising resolver is a shadow failure, INV-15); `_shadow` and `_sample` take that `target`. The gate's queries filter with `ledger.OWN_STUDENT` / `OWN_SHADOW`. A new resolver must name the version's adapter for its own answers, or they never count toward a release.

Generation parameters ([ADR 0017](../docs/adr/0017-generation-parameters-by-role.md)). `self.gen = Settings.gen_policy()` (`providers.GenPolicy`, built in `__init__`, so a bad `RATCHET_*_PARAMS` or cap stops startup) and `plan(params)` gives a `GenPlan` once per request (`_plain`, built at startup, when `params` is None): `student` for `_sample` (live, canary and shadow), `serve` for the teacher whose answer is served (escalation, cold start, `_teacher_only`), `check` for audits and arbitrations (temperature 0, without `providers.CHECK_DROPS`), and `visible_max`. Every teacher call goes through `_ask_teacher(task, messages, gen, visible_max)`, which passes `temperature=gen.temperature`, `logprobs=bool(gen.logprobs)` and `params=gen`, and marks an answer `length` when the reasoning headroom let the teacher exceed the client's `max_tokens` and the visible answer does (`approx_tokens(clean_answer(...))`). Never send a client parameter to a model any other way, and never let one choose the model (INV-1) or the student's `n`, temperature or logprobs (`STUDENT_SAMPLING`). `_store_example(task, messages, c, gen, meta)` stores `ledger.target_params` of the call's `gen` (`STORED_PARAM_KEYS`: `response_format`, `tools`, `tool_choice`, `stop`) with the example, redacted with `redact_json`; `meta.storable=False` stores nothing and is not a skip. An answer whose `gen` has label-altering sampling (`GenParams.unstorable`: a client's `logit_bias`, a non-zero penalty, a temperature above 1, a vendor field) is served but skipped (`skip_example` `client logit_bias`, ...): a client chooses its answer, never the label (threat model T2); keep any new sampling field that can force tokens in that check. `Result.finish_reason` is the served answer's (`CLIENT_FINISH`: `stop`, `length`, `content_filter`, `tool_calls`, else `stop`; `_client_finish` gives `tool_calls` only to a choice with `tool_calls`). A tool request (`uses_tools`: `params.tools`, or tool calls or results in the messages) goes to `_teacher_only` with route `tools` after the pinned and unknown-task checks, never to the cascade (FR-1.41, ADR 0043); only that path passes `tool_calls=True` to `_serve_teacher` / `_ask_teacher`, and anywhere else a teacher tool call raises `UpstreamError` 502 `tool_calls_unsupported`. Never store a tool request's answer, never send the student tools, and never repair a tool call (`_repair` skips it). The teacher's default allowlist is every standard field (`DEFAULT_TEACHER_PARAMS`), tools included. The serving teacher gets the client's `logprobs` and `top_logprobs` (in the default allowlist since FR-1.14, so only when a client sends them); `CHECK_DROPS` keeps them out of audits and arbitrations. Providers take `complete(messages, model, n, temperature, logprobs, response_format, params=None, **_)`; the explicit arguments win.

Choices and logprobs ([ADR 0020](../docs/adr/0020-n-choices-and-token-logprobs.md), FR-1.14). `plan(params, n)` puts `n` in the `GenPlan` (`plan.n`; `GenPolicy.plan` refuses one below 1) and gives the serving teacher `CHOICES_TEMPERATURE` (0.7) for `n` > 1 when no client temperature reaches it. `_teacher_complete`, `_ask_teacher` and `_serve_teacher` take `n` and return lists of at most `n` choices (fewer when the server returns fewer; never padded); `_call_teacher` asks for `plan.n` only in the `serve` role, stores only choice 0 and returns every choice in `TeacherAnswer.choices`. Audits and arbitrations are one answer judged against choice 0; the shadow samples `Settings.samples`; `_may_degrade` needs `majority`'s choices. `Result.choices` (`Choice(text, finish_reason, logprobs)`, built by `_choices`) has every choice; `Result.text` and `finish_reason` are choice 0's, and `_usage` adds up the choices (the prompt once), `_breakdown`'s `served` is all of them, `_call_cost` prices a whole call. Logprobs are computed only for a client that asked (`params.logprobs`): `providers.served_logprobs(c, text, top)` checks `Completion.logprobs_content` (the server's list, kept as it came; never mutate it), keeps only the tokens that spell the served text (a token is cut only by the whitespace `clean_answer` strips) and returns None when that cannot be done, so a client's tokens always spell its content and reasoning tokens never reach it.

Structured outputs (FR-1.40, FR-14.2, [ADR 0042](../docs/adr/0042-auto-tasks-from-response-format-schemas.md)). `handle`, `teacher_only` and the gateway's `task_for` start with `resolve(task, params)`: a `response_format` becomes a `schema_tasks.Contract` bound to the task (`Task.bound`, same rules and `spec_hash`), and a json_schema request without a registered name gets its auto task (`_auto_task`: derived with `schema_tasks.auto_task`, registered and saved under `tasks_lock`, the gateway's lock for admin writes; capped by `RATCHET_MAX_AUTO_TASKS`; a known schema is a dict lookup). Then `params = schema_tasks.forwardable(params)` strips `x-ratchet` annotations before any model or the ledger sees them. A bound task makes an answer that breaks the contract invalid (`Task.check`), so the INV-16 rules cover it unchanged, and `clean_answer` serves the JSON the answer holds (`tasks.json_span`). `_repair` gives a complete, invalid teacher answer one more call (`RATCHET_SCHEMA_REPAIR`; a cut-off or empty repair answer keeps the first) and returns the unused answer (`TeacherAnswer.rejected`), which every caller prices into `cost`/`teacher_cost` and lists in `usage_breakdown.repair`, and the first call's answer (`TeacherAnswer.first`): the baseline and the client's usage read its prompt counts (`_asked`), never the repair call's, and `latency_ms` adds both calls; the repair conversation never reaches `_store_example`, which keeps the request's own messages. A repair is a user turn, never a system message. `_teacher_complete` retries a json_schema 400 (`refuses_json_schema`) once as json_object (`schema_tasks.downgrade`) and remembers the refused schema per endpoint; after `JSON_SCHEMA_STRIKES` it probes the endpoint once (`_probe_json_schema`), and only a refused probe turns json_schema off for it. `resolve` uses a registered auto task only for a schema that derives its `spec_hash` (`_derives`); never look an auto task up by name alone. `Contract.problem` is memoised by the answer's digest: call it freely, but never add a schema check that bypasses it. Night School binds rows with `tasks.for_row`; any new code that grades a stored row must too.

Keep `handle` free of I/O beyond the providers and the ledger. Anything slow belongs in Night School. `Result.text` is `tasks.clean_answer(task, served.text)` on every path (`_teacher_only` too): reasoning never reaches a client, and a structured answer is bare JSON.

Usage and fingerprint ([ADR 0018](../docs/adr/0018-usage-reports-the-served-answer.md), FR-1.12). Every `Result` (`_teacher_only` too) carries `prompt_tokens`, `completion_tokens`, `reasoning_tokens` and `cached_tokens` from `_usage(messages, served, text)`: the served completion's own counts, as if its model had answered alone (an estimate at about 4 characters a token only for a count it did not report; reasoning and cached never above their totals), `usage_breakdown` from `_breakdown(...)` (every call by `USAGE_PARTS`, as the models reported them, `None` for a call not made or failed) and `fingerprint` (`router.fingerprint("student", model, version.id, version.dataset_hash, threshold)` or `fingerprint("teacher", teacher_model)`). They come from completions already in hand: no extra call, lock or column. A new model call in `handle` adds a `USAGE_PARTS` entry, and `test_usage_is_the_served_answer_and_the_breakdown_every_call` checks that `cost_usd` is exactly the price of the breakdown. `Completion.cached_tokens` is `usage.prompt_tokens_details.cached_tokens` (every choice of a call carries it, like `in_tokens`).

Failures. Only a teacher call whose answer is needed may fail a request: escalation, cold start, pinned and teacher-only (the gateway maps its `UpstreamError` to 400, 429, 502, 503 or 504 in `_map_upstream`, INV-7), unless a fallback teacher or degraded mode stands in (below). Every other upstream call (the student, the audit, the shadow's samples, the arbitration) is wrapped, counted under `_errors_lock` (`student_errors`, `audit_errors`, `shadow_errors`; `Ratchet.health()` returns them) and logged by `_count_failure` on the 1st, 10th, 100th and 1000th occurrence. These events (`student_error` too) name the exception class, HTTP status and upstream code (`resilience.describe_failure`), never the message, which can hold the endpoint URL or quote the request (vLLM's validation errors do), and `/ratchet/stats` serves events to anyone (INV-12). A new optional call must follow the same pattern ([ADR 0013](../docs/adr/0013-optional-teacher-calls-fail-open.md)).

Upstream calls (`providers.py`, `resilience.py`, [ADR 0014](../docs/adr/0014-upstream-failure-semantics.md)). `OpenAICompatProvider.complete` raises only `UpstreamError` (an `httpx.HTTPError`: status, OpenAI `type`/`code`/`param`, a clipped message, `retry_after`; never the URL or headers). It retries through `retry_call` with the provider's `RetryPolicy`: connection failures and 408/409/429/5xx, a `ReadTimeout` once, never another 4xx; waits are full jitter or the server's `Retry-After` (a wait over `cap_s` returns the error at once, and `_map_upstream` passes it on as the client's `Retry-After` on a 429, 502 or 504); the deadline caps each attempt's timeouts. A 2xx body is parsed after the retries and never retried (`bad_upstream_response`). `_completions` reads per choice the message's `content` only (never `reasoning_content` or `reasoning`), `finish_reason` (`stop` when absent, null or empty, `unknown` when it is not a short word; `providers.COMPLETE` names the values the router stores and `confidence.score` counts as votes), its share of `reasoning_tokens`, and `out_tokens` that always add up to `usage.completion_tokens`, split by the choices' logprob counts when every choice has them, else evenly. Roles get their own `Settings.teacher_timeout()` / `student_timeout()` and `teacher_retry()`: the teacher and judge are retried, the student on the request path is not (the teacher is its retry), the golden eval's student is. New upstream calls take `sleep=` (and `clock=`, `rng=`) as default arguments so tests never wait.

Student breakers (`resilience.Breaker`, [ADR 0015](../docs/adr/0015-student-circuit-breaker-and-adapter-reload.md)). `Ratchet._breaker(role, provider)` makes one per role (`student` for live and canary, `shadow`) and endpoint (the provider's `base_url`, else its class; never `id()`, because a resolver may build a provider per call) on first use, with `Settings.student_breaker()` (`RATCHET_STUDENT_BREAKER_FAILURES`, `RATCHET_STUDENT_BREAKER_COOLDOWN_S`) and `Ratchet(clock=)`. `_sample` calls `allow()` before and `record(ok)` / `release()` after every student call, from the same thread (only the probe's thread decides in half_open): `resilience.endpoint_down(e)` says whether a failure counts (timeouts, connection errors, 5xx, 408, 429), is the endpoint answering (other 4xx: `record(True)`), or says nothing (not an HTTP error: `release()`). A 404 naming the version's adapter becomes `AdapterMissing` (the test is `resilience.adapter_missing(e, model)`, shared with `scripts/day1_check.py`'s student probe: change the predicate there only); `handle` then calls `on_adapter_missing(version)` (the gateway's `live.AdapterReloader.request` in live mode; never let it fail the request). Each breaker gets `probe_timeout_s` from `_probe_timeout(provider)` (the provider's `longest_call_s()`, its pool, connect, write and read timeouts, plus `PROBE_MARGIN_S`), so a probe is never presumed lost while its call can still be running; a lost probe that reports while the breaker is half-open still decides, so the wait always doubles. Transitions write `circuit` events through `_circuit_event`; at the longest wait the breaker reports the repeated open<->half_open pair only for the 1st, 10th, 100th and 1000th probe (`REPORTED_REPEATS`). The dashboard's Resilience panel parses these events (`<breaker>: <old>-><new> <reason>`, a failed probe's `for <s> s after a failed probe`) and the drill's `fault` detail (`student endpoint down for <s> s`) with regexes in `web/src/pages/dashboard/`, because `health()` is not served over HTTP; `test_resilience_panel_contract` checks them against real events, so change the wording and those regexes together. `health()["breakers"]` has the snapshots. `Ledger.shadow_quality` leaves `student_breaker` and `student_error` rows out of `live_coverage`. Keep the closed path lock-free: `allow()` and a successful `record()` only read attributes.

When the teacher is down ([ADR 0019](../docs/adr/0019-teacher-breaker-degraded-mode-and-fallback-teacher.md)). Every teacher call goes through `_teacher_complete(messages, gen, fallback=False)`, which checks the teacher's breaker (`teacher_breaker`, or `fallback_breaker` for the fallback; made in `__init__` with `Settings.teacher_breaker()`, listed in `health()["breakers"]`) the way `_sample` checks the student's: `allow()` before, `record(ok)` / `release()` after, from the same thread, with `endpoint_down` deciding; never call a teacher provider any other way. While open it raises `CircuitOpen(..., retry_after=breaker.retry_in(), code=TEACHER_CIRCUIT_OPEN)`, which the gateway maps to 503 `teacher_circuit_open` with `Retry-After`; an audit or arbitration catches it before the generic handler, so it is skipped without counting as an `audit_error` or `shadow_error`. `_serve_teacher` (the only path to the fallback teacher, and only for an answer that is served) asks the fallback when `resilience.teacher_unavailable(e)` and raises the primary's error when the fallback fails as an upstream call too; `_call_teacher` returns a `TeacherAnswer(completion, stored, model, fallback)`, and `_store_example(..., fallback=True)` stores only with `Settings.store_fallback_teacher`. Degraded mode is `_may_degrade(sc, params, e)` on the escalation only (`serve_student_on_failure`, a valid student answer, no `tools`, `teacher_unavailable`): route `degraded`, `Result.degraded = TEACHER_UNAVAILABLE`, `audited` 0, nothing stored. A route in `STAND_IN_ROUTES` runs no shadow, so a stand-in's answer never reaches release statistics. Counters `degraded_answers` and `fallback_answers` (with throttled `degraded` / `fallback_teacher` events) are in `health()`.

`teacher_only(messages, task, client)` is the pinned path (`_teacher_only`) for a request the student cannot take (a multimodal part, `RATCHET_TEACHER_MODALITIES`): the teacher answers (the fallback teacher when it is unavailable, route `fallback_teacher`), the request is logged, nothing is stored, and it never degrades.

Cost split (FR-15.1, [ADR 0023](../docs/adr/0023-utilization-aware-cost-accounting.md)). `handle` keeps `student_cost` (live and shadow samples) and `teacher_cost` (audit, escalation, arbitration) beside `cost`, adding each call's price to its part right where it adds it to `cost`, and the student calls' `student_in` / `student_out` tokens (the prompt once per call, every sample's output); `_teacher_only` logs everything as teacher cost and 0 tokens. Never change how `cost` itself is summed (the order of additions included): it must stay what it was, so stored history and the reference simulation never move, and it equals the parts only up to float rounding. A new model call adds its price to `cost` **and** to one part. `Result.student_cost_usd` and `teacher_cost_usd` carry the parts.

## Cost accounting (`cost.py`)

Utilization-aware cost accounting (FR-15.2 to FR-15.4, NFR-11, ADR 0023). `Settings.cost_policy()` (`config.CostPolicy`, `GpuRate`) checks `RATCHET_STUDENT_COST_MODEL`, the GPU rates and `RATCHET_MOCK_ENDPOINT_HOURS`; `Runtime.reset`, `live.main`, the simulator and the CLI call it at startup, so a bad value names its variable before anything runs.

- **Compute intervals** (`Ledger.compute_start`, `compute_stop`, `compute_intervals`; `ledger.COMPUTE_KINDS`). Times are on the ledger's clock: `Ledger.now()` is wall-clock time with `auto_day` (live), else a synthetic clock where day N starts at N x 86400 s; `day_start(day)` and `day_of(ts)` map between days and that clock (a live ledger counts from its first request, as `_tick_day` does). `compute_start` for `student_endpoint` returns the open interval when one exists, inside `BEGIN IMMEDIATE` (`_begin`), so a second process cannot open another; `compute_stop` closes every open interval of a kind, or one by id, and refuses an explicit end before a start; `compute_record` inserts a closed interval and never touches an open one (the simulator's days). Each interval keeps the rate it was recorded at; `_check_compute` bounds rates to `config.MAX_USD_PER_GPU_HOUR` (1,000) and `MAX_GPUS` (1,024), as `Settings.cost_policy()` and `POST /ratchet/cost/endpoint` do, so no total can overflow. Before a live ledger's first request day 1 starts at the earliest interval (never after now), so `--days N` keeps recorded uptime.
- **Writers**: `record_endpoint` (the CLI's and `POST /ratchet/cost/endpoint`'s shared path; writes an `endpoint` event on a change, with the admin's name, never a key), `run_night(train_gpu=, clock=)` (live mode only: `live.main` passes `policy.train`; the wall-clock time of `trainer.train()`, closed in a `finally` and re-raised), `record_simulated_day` (the simulator and `Runtime.simulate_day`, after the night: closed synthetic intervals through `compute_record`, no events, no random draws, so the reference simulation never moves and an interval a visitor opened through the API stays open). Never let a mock or simulated path call `run_night` with `train_gpu`: its wall-clock interval would land on the synthetic clock's far future.
- **The report** (`cost_report(ledger, settings, since, until, now, days)`): `Ledger.cost_by_day` (one aggregate query) and the intervals clipped to the window's days; `segments` merges each kind (a sweep with a heap; overlapping records bill at the highest rate) and `split` divides segments over day windows in one pass. Pure, O(rows): no I/O beyond the ledger, no NaN or infinity in the result (it goes out as JSON). Formulas and the recommendation rules are in ADR 0023 and ARCHITECTURE §7. Break-even and the crossover use `endpoint_usd_per_hour` (the recorded rate; the configured one without uptime). Idle time, the observed volume and the hosted fallback's share are counted per bucket (`_traffic`, `idle_granularity`): hours on a live ledger (`Ledger.student_traffic_by_hour`), whole days on the synthetic clock (the `cost_by_day` rows). `_explain` says separately whether observed covers break-even (`covers`) and whether GPU-hour savings are negative (`loss`): never "below the break-even" above it, never "pays" at a loss, and `CROSSOVER_CAVEAT` (equal coverage assumed) with every `hosted_fallback`. `stats_block` is the `/ratchet/stats` `cost` block (add keys only, and to `tests/fixtures/stats_keys.json`). The dashboard's Economics panel reads the report itself; the keys it reads are in `tests/fixtures/cost_keys.json` (add only). `RECOMMENDATIONS` are the four outcomes; a fifth needs the ADR, API.md and RUNBOOK's table.
- **CLI** (`main(argv, out=, settings=)`): `report`, `endpoint up|down`, `close KIND`. It opens an existing ledger file only (`auto_day=True`) and exits 2 with `error: ...` on a bad input; `--at` refuses the future.

## Success metrics (`kpis.py`)

PRD §8.1's SM-1 to SM-5 and NFR-1's latency target (FR-7.9, [ADR 0083](../docs/adr/0083-success-metrics-from-the-ledger.md)). One pure function per metric over plain rows (`cost_reduction`, `audited_precision`, `student_share`, `bad_deploys`, `drift_recovery`, `student_latency`), each returning `{name, value, target, op, unit, met, detail}` with `met` `None` when the data cannot say; `report(ledger, window_days, min_audits, mode)` reads the rows (`Ledger.kpi_days`, `audit_totals`, `failed_cost`, `latency_quantile`, `events_of`, each under the lock on its own) and never writes. The window is the last `RATCHET_KPI_WINDOW_DAYS` days with traffic (`Settings.kpi_window()` checks it; `Runtime.reset` and the simulator call it at startup). SM-5's rate is over the requests the student judged (`answered`, rows with a confidence), so an outage is not drift; `daily_rollup` keeps `answered` and `answered_escalated`, so keep both in `ROLLUP_INSERT` if the request columns change. `SM_TARGETS` must match the PRD table (reqtrace rule j); change both together. A new metric adds a key under `metrics` and its types in `tests/fixtures/stats_keys.json`. The output goes out as JSON, so `report` turns any NaN or infinity into `None`.

## Release (`release.py`)

States: `candidate → rejected | shadow | canary(10) → canary(50) → live`; `canary → rolled_back`; old versions → `retired` (also an `inconclusive` canary under the sequential rule).

`tick()` is six steps, each owned by one feature and edited only in its own function (ADR 0024): `_tick_drift()` (the drift monitor, FR-16.6), `_tick_live(live)` (the live alert), `_tick_tasks(live)` (one alert per (version, task) for the live version and the canary, FR-14.1; once-only read from the events with `Ledger.has_event`, skipped for a version whose stage audits are all one task's, and its grouped query run only after a new audit, `Ledger.last_audit_id`, because `tick` runs after every gateway request), `_tick_shadow(live)`, `_tick_canary(live)` (a rollback returns from this step only) and `_tick_watchers()` (the teacher watch, FR-16.7: `check_teacher`, which freezes Night School and decides no release). `live` is read once, before any step, as before the split, so a canary promoted in the tick retires the version the tick started with; behaviour is byte-identical (the reference workloads). `ReleasePolicy` checks its values in `__post_init__` (ranges, whole numbers, switches 0 or 1; `ValueError` names `RATCHET_<FIELD>`), and `from_env` names the variable on a value that does not parse. The evidence features' fields were declared (`RESERVED_POLICY`) with defaults that keep today's decisions; any other value raises until the feature lands, and its item removes the entry (every one is built now; the mechanism stays for the next). `wilson` lives in `stats.py`; `release.wilson` still imports.

- `admit(vid)` runs after training: precision ≥ `min_precision`, coverage ≥ `min_coverage`, then the certified floor (`min_certified_precision` > 0: `_below_certified_floor` recomputes `cp_lower` from the certificate's counts and fails a candidate without one), then no regression vs live: with `paired_gate=1` and a readable `paired` record against this live version, `_paired_regression` (more than `tolerance` of the rows lost from coverage or newly wrong, each with McNemar p < `regression_alpha`, or the negative flip rate's Wilson lower bound above `max_nfr`; `_paired_counts` recomputes the p-values from the counts), else the unpaired rule within `tolerance` (v0.4's). Then per task (`task_failures`, FR-14.1, ADR 0040): a task with ≥ `min_task_test_n` held-out rows whose precision (a point estimate, as above) is below its floor (`policy.min_precision`), below live's precision on it less `tolerance`, or unmeasured (it answers none of them) is disabled on the candidate (`task_mode` `disable`: `Ledger.merge_task_eval`, event `task_disabled`) or rejects it (`reject`); a candidate with records that would answer under `min_coverage` of its held-out rows at its per-task thresholds is rejected (it would never finish shadow or canary, and no night trains meanwhile). Cold start (no live version) goes straight to canary 10%. The shadow event appends the paired counts, and the shadow and cold-start canary events append `_certified_text` (`; certified >= 95% (lcb 96.4%, delta 0.05)`, only when the recomputed bound reaches the target) after the old text, which the reference check requires ([ADR 0026](../docs/adr/0026-certified-thresholds-and-a-paired-release-gate.md)).
- `tick()` runs periodically: shadow decisions (unarbitrated disagreements count against the shadow; the event says how many), canary advance (needs `min_audits` audits **in the current stage**, tracked via `stage_since`), rollback when the Wilson upper bound < `live_floor`.
- The anytime-valid gate (FR-16.1, FR-16.2, [ADR 0025](../docs/adr/0025-anytime-valid-release-gate.md)). Every decision comes from two integers per version, `Ledger.audit_counts(vid, since_id)` (audits, agreements); never add gate state that cannot be recomputed from the ledger. With `sequential=1`, `_tick_canary` hands over to `_sequential_canary`: rollback when `log_e_bernoulli(s, n, floor, 'below') >= ln(1/alpha_rollback)` over **every** audit of the canary's life (`audit_counts(id)`; one e-process, never restarted per stage, so no union bound; no minimum count), then promotion on the stage's counts once there are `min_audits` (point estimate, or `'above'` e-value with `promote_evidence`), then futility at `max_stage_audits` (`retired`, event `inconclusive`). With `sequential=0` the Wilson code path is byte-for-byte as before (the reference workloads pin it). `_tick_live` alerts by the e-process on the audits since the version went live (`alert_eprocess=1`, the default; `alpha_alert`), else by Wilson. Compare in log space (`log_e >= math.log(1 / alpha)`), never the capped `e_bernoulli`. Events keep their old text as a prefix and append the evidence (`_e_text`, `_cs_text`: the counts, the e-value and its threshold, the 95% confidence sequence), because the reference check allows appended text only. `evidence(v)` recomputes everything for `/ratchet/stats` (canary and live versions; `EVIDENCE_STATES` in the gateway). `ReleasePolicy._check_sequential` refuses settings that decide nothing (`promote_evidence` without `sequential`, a cap below `min_audits` or too small for evidence-based promotion).
- Change thresholds through `ReleasePolicy` (or `RATCHET_<FIELD>` env vars), never inline. The gateway reads them in both modes (`from_env(defaults={"min_audits": 15})` in mock mode); the simulator passes its own flags.
- **Move versions with `Ledger.transition` and `Ledger.promote_live`, never `set_version`** (FR-12.9, [ADR 0064](../docs/adr/0064-admin-api-compare-and-set-and-audit-trail.md)). Each compares the state and share the caller saw and writes its event in the same transaction only when the row changed, so the gateway's tick, the cron tick and an admin never make one decision twice; `transition` refuses a move into shadow or canary while another version is in flight and raises for a move to live (`promote_live` retires the old live version with it). Pass the version's state and share as read; a False return means someone else moved it: drop the decision, the next tick decides again. `admit` is one `Ledger.transaction()` and acts only on a `candidate` (`conflict` event otherwise). `set_version` is for tests and migrations. `tests/test_observability.py::test_every_version_transition_writes_an_event` fails if the gate calls it.
- Operator holds (ADR 0064): `_held()` is `releases_frozen` or a runtime audit rate of 0; it keeps a cold start in shadow (against the teacher) and a ready shadow out of canary, and `releases_frozen` stops canary stages and promotion. A rollback, a rejection and the live alert run whatever is held: never put a hold in front of them.

## Ledger (`ledger.py`)

- Every write commits immediately (v0 simplicity; fine for a single gateway process). The caches below rely on it.
- Every public method that writes, or that the request path or the release gate reads, is wrapped in `@_locked` (one `threading.RLock`), because Scout's agents call `Ratchet.handle` from several threads and share one SQLite connection (`check_same_thread=False`). Re-entrant, so locked methods may call each other. The two exceptions are `replay_rows`, which reads a long history in chunks through the locked helpers `_replay_bounds` and `_replay_chunk`, and `period_rows` (a receipt's day, through `_period_chunk`), so the lock is free between chunks; neither runs a statement of its own. A read-only stats or report query is wrapped in `@_reads` instead and reads through `self._rdb`: on a WAL file that is the read-only connection (`mode=ro`, `isolation_level=None`), under `_ro_lock`, inside one read transaction; elsewhere the writer under `_lock`. A `_reads` method never writes, never takes `_lock` and never calls a `_locked` method (no lock-order cycle). Add one of the two decorators to every new public method.
- The journal (ADR 0060): `Ledger(path, sync=Settings.ledger_sync())` puts a file in WAL with `synchronous=NORMAL` (`NORMAL`, the default) or the rollback journal with `synchronous=FULL` (`FULL`); `:memory:` and `""` keep theirs. Every opener passes `sync` (the gateway, `live.build`, `cost._ledger`); `journal_mode` says what SQLite gave.
- **The ledger's caches** (ADR 0060). Generations (`_gen`) count writes on the writer's connection, bumped by TEMP triggers (`WATCHED`: every write to `versions`; UPDATE and DELETE on `requests`; UPDATE OF `hash` and DELETE on `examples`) that call `ratchet_written`; other connections' commits show in `PRAGMA data_version`. So any write through `ledger.db`, a Ledger method or raw SQL, invalidates what it must; never write the ledger through a second connection inside the gateway process. The routing snapshot (`_routed`: the newest live, canary and shadow rows, `ROUTED_STATES`) is keyed by (`versions` generation, data_version); `live()` and `by_state()` build a fresh `Version` from it per call, and `version(id)` is one query by id. `version_live_quality`'s `_Tally` per (version, stage) reads only ids above the last it saw (ids are assigned in commit order) and restarts on a `requests` generation or data_version change; it must stay equal to one `COUNT(audit_agree)`, `AVG(audit_agree)` over the stage (`test_live_quality_tally_matches_a_full_count`): a pending off-path audit (`audited` 1, `audit_agree` NULL) counts in neither number, and the tally keeps the pending ids it read (`_Tally.pending`, `AUDIT_PENDING_SQL`) and settles them on each call (`_settle_pending`). `update_request` (ADR 0072) writes only verdicts, `stored`, the baseline and `add_<column>` costs and tokens (`AUDIT_VERDICT`, `SHADOW_VERDICT`, `ADDABLE_COLUMNS`), none a cache keys on, so its bumps are subtracted from the `requests` generation (`_offpath_bumps` under `_gen_lock`, read through `_requests_gen`); a column a cache keys on must never be added to it. Reader-side caches (the BOM digest, `stats_by_day`'s per-day percentiles) key on row counts and highest ids read inside their snapshot plus `_settled(table)`, which is None (no caching) while the writer is in a transaction, because a trigger fires before its commit. A new cache follows the same rules; a new routed state goes into `ROUTED_STATES`; a new gate query goes into a named constant (`AUDIT_TALLY_SQL`, `SHADOW_QUALITY_SQL`, `ROUTED_SQL`) with an index-plan check in `tests/test_perf.py`.
- `requests.wall_ms` is the whole cascade (router); `latency_percentiles(day, served_by, qs)` is nearest rank (`_nearest_rank`) with `ORDER BY wall_ms LIMIT 1 OFFSET k`, and `stats_by_day` adds `p50_student_ms` and `p95_ms` (keys only grow). `events(last=n)` reads the newest n rows.
- `stats_by_task()` feeds `tasks` in `/ratchet/stats` and the dashboard's **By task** table; since FR-14.1 with each task's audits and, from the live version's eval, its threshold as the router applies it, precision, coverage, `calibrated` and `disabled` (`_live_calibration`).
- **The teacher watch** (FR-16.7, [ADR 0033](../docs/adr/0033-teacher-watch.md); the logic is in `teacher_watch.py`). `add_example`'s duplicate branch calls `_check_label` in the same transaction (the failed INSERT already holds the write lock): one comparison per example per check epoch (`checked_epoch`), only between comparable labels (same teacher, no redactions, `comparable=True`, a verifiable unpinned task, both valid, the stored one neither contested nor `UNCHECKABLE`). Never compare a stored label with a second re-test in the same epoch, never compare a contested or adjudicated label again, and never let a comparison raise into the write (a failing comparison is no check). `record_teacher_check` (probes), `teacher_model_seen`, `teacher_freeze` and `teacher_ack` each run in `BEGIN IMMEDIATE` and write their `meta` keys (`TEACHER_EPOCH`, `TEACHER_EPOCH_DAY`, `TEACHER_FROZEN`, `TEACHER_MODEL`, `TEACHER_MODEL_IDS`) together with their event, so two processes write one event. `contested` is 0, `CONTESTED` (1) or `UNRESOLVED` (2); `resolve_contested` makes the label `UNCHECKABLE`. `teacher_check_days(after_id)` is the gate's incremental read (a primary-key range with `+epoch`).
- `versions(states)` filters the states in SQL and `version(vid)` reads one row, so only the rows returned have their eval parsed: the request path reads the live and canary versions on every request, and an eval carries a certificate, a frontier and a per-task block (ADR 0026). Keep new version queries in SQL rather than filtering `versions()` in Python.
- `audit_counts(vid, since_id=0)` is the release gate's input: `(audits, agreements)` of answers the version served (`served_by='student'`, `audited=1`) after request id `since_id` (0: its whole life; `stage_since`: its current stage), on the `requests_version_audited` index. An audited row without a verdict is an off-path audit still running (ADR 0072) and counts in neither number until its verdict is written. `version_live_quality` is built on it (`s / n`, the same float as the old `AVG`). `served_counts()` is the answers each version served (stand-in answers included): a rolled-back version's exposure (the simulator's `exposure`).
- `merge_task_eval(vid, task, changes)` is the only partial write to a version's eval (the gate disabling a task): read and write in one `BEGIN IMMEDIATE` transaction. `has_event(kind, prefix)` compares a prefix with `substr`, never LIKE (task names may hold `_`).
- `examples.hash` is unique per (task, messages, conditions); duplicates increment `seen`. `example_hash` adds the conditions (`target_params`, `examples.params`) to the hashed object only when there are some, so hashes from before v0.5 never move (`test_v04_example_hash_unchanged`). Never add a key to the hashed object unconditionally. The split comes from the hash without conditions (`Ledger._split`), so every variant of a prompt shares it and v0.4 splits stay: the trainer sees only the messages, and variants in both sets would leak golden prompts into training (INV-3, INV-6).
- Only the functions in `ALLOWED_ADD_EXAMPLE_CALLERS` (`tests/test_nightschool.py`; today `Ratchet._store_example` and `feedback.store_label`) may call `add_example`. An AST test fails on any other use under `ratchet/` until the allowlist is changed in a reviewed edit (INV-2, INV-10).
- `split` is deterministic from the condition-free hash (`golden_fraction`), so an example never moves between sets, except via the `FREQUENT` rule applied in `nightschool/dataset.py` (which counts every variant of a prompt together).
- `cost_by_day(since, until)` feeds the cost report; the compute-interval methods and the ledger's clock are described under [Cost accounting](#cost-accounting-costpy).
- Schema changes need both `SCHEMA` and `MIGRATIONS`. Indexes go in `INDEXES` (created after migrations, as `CREATE INDEX IF NOT EXISTS <name> ON <table> (<columns>)`; `_migrate` skips one whose columns a hand-made partial file lacks, and `test_every_index_exists_on_a_new_ledger` catches a misspelled column), not in `SCHEMA`. A new table needs only `SCHEMA` (`CREATE TABLE IF NOT EXISTS` runs on every open).
- The evidence features' schema is in place before their logic (ADR 0024); each feature writes its own columns and tables and changes no migration. `requests`: `threshold`, `label_p`, `student_agree`, `baseline_est_usd` (FR-16.5) and `optional_failed`; `examples`: `origin`, `job` (FR-16.8), `contested`, `checked_epoch` (FR-16.7, defaults 0). Tables (`EVIDENCE_TABLES`): `version_leaves` (FR-16.4), `teacher_checks`, `meta` (FR-16.7), `receipts` (FR-15.5), `spend`, `backfill_jobs` (FR-16.8), `tombstones`, `erasures` (FR-16.9; ids never reused). `version_leaves` is written by committed training sets (below) and `receipts` by savings receipts ([below](#savings-receipts-receiptspy)); FR-13.3 writes `tombstones` and `erasures` (adding `actor`, `reason`, `scope`, `purged`, `kept`; `tainted` and `status` as documented) and leaves `key`, `replacement` and `certificate` to FR-16.9; nothing writes the others yet. Whether a request was served by the student, and why not, is `route`; no separate reason column. `student_cost_usd` is FR-15.1's (live and shadow samples).
- **INV-17: `version_leaves` and `receipts` are append-only** (`APPEND_ONLY_TABLES`), enforced by triggers in `SCHEMA` on every connection: UPDATE, DELETE and an INSERT that would replace a row (`INSERT OR REPLACE`, which skips DELETE triggers, and `INSERT OR IGNORE` alike) raise `sqlite3.IntegrityError`. Their key columns are NOT NULL (SQLite lets NULLs past a composite primary key). A writer checks for an existing row first; never drop or bypass the triggers.
- **Committed leaves** (FR-16.4, [ADR 0027](../docs/adr/0027-committed-training-sets.md)): `set_version_leaves(vid, split, pairs)` writes one split's (key hex, value hex) leaves in one transaction (`_begin`), and raises `ValueError` (writing nothing) when the split (`LEAF_SPLITS`: `train`, `golden`) already has leaves, the version does not exist, a key repeats or a pair is not 64 lowercase hex characters (`_hex32`): leaves are written once, and the INV-17 triggers stop any later edit. `version_leaves(vid, split)` reads them in key order; `versions_containing(key, split='train')` lists the versions whose set holds a key (the `version_leaves_key` index); `leaf_example(vid, split)` is the mock demo's sample (the first leaf whose example is still stored). Only `run_night` writes leaves, right after `create_version`, from `dataset.commitment(rows)` built before training (so a duplicate key stops the night before any GPU time); the BOM then signs each split's root and size (`bom.manifest(commitments=)`). Never write leaves for an existing version, and never sign a commitment whose leaves are not in the ledger.
- Data governance (ADR 0080): `requests.end_user` (indexed with `ts`) and `store_opt_out`; `examples.client` and `examples.end_user` (the first sender, filled by `add_example(..., client=, end_user=)`); `example_clients(hash, client)` gets a row when a duplicate comes from a client other than `examples.client` (`IS NOT`, so a first sender of NULL counts as other), never for an opted-out request (it never reaches `add_example`); `example_clients(h)` lists all of them. `no_train(end_user_hash, ts, client, admin)`: `no_train_add(entries, admin=, limit=)` (one transaction; an admin's registration also claims an existing one; `limit` raises `NoTrainFull` before writing when new entries would pass it), `no_train_remove(hashes, admin=)` (`removed`, `kept`, `absent`), `is_no_train(*hashes)`, `no_train_count`, `no_train_scopes_stored`, `no_train_unmatched(scopes)` (registrations in a scope no request can be hashed in now). `client` is a key name, NULL (keyless) or `*` (`privacy.EVERY_CLIENT`, an admin's registration for every client). `opt_out_stats()` (counts by reason and of no-train end users; never a hash) and `stats_by_client()`'s `end_users` and `stored_share` feed `/ratchet/stats`. `meta_get`, `meta_set`, `meta_setdefault` (atomic: the first writer wins) hold small ledger-wide values such as the generated end-user key.
- Retention and erasure (FR-13.3, FR-13.4, ADR 0081). A purge never deletes an example row: `purge_examples({hash: counted}, reason)` (and `_purge` inside `record_erasure`'s transaction) NULLs `messages`, `completion`, `params` and sets `purged_ts`, `purge_reason` (`PURGE_REASONS`), `purged_train` and, for a row with conditions, `prompt_hash`; an erasure also NULLs `end_user`. Anything that reads `examples` must skip a row with `purged_ts` set (no text) but keep counting its `seen` (`prompt_key`, `count_prompts`, `prompt_counts`: INV-3). `add_example` returns None for a tombstoned hash (`tombstones`, `_refuse_erased`), restores a `retention` row on a duplicate (with the new teacher and license) and moves `last_seen_ts` on every duplicate. `erasure_candidates` (selectors AND together; `contains` via `_like`, wildcards escaped, JSON-encoded for messages and params), `affected_versions` (leaves first, else time with `purged_train`), `record_erasure` (one transaction: `erasures`, `_purge`, `erasure_items`, `tombstones`, `_unlink`, request rows' `end_user`), `requests_of_end_users`, `end_user_scopes` (every scope an end-user hash is stored in: an erasure for every client), `train_rows_kept` (Night School's new-data count: each version measured against its own purges). `retention_candidates(cutoff, client, limit)`; `PURGE_CHUNK` examples per retention transaction. `fold_requests(cutoff, client)` folds request rows into `daily_rollup` (`ROLLUP_INSERT`, `ROLLUP_SUMS`) in `FOLD_CHUNK` transactions, never past the `stage_since` of a version in shadow or canary and never a row such a version served or shadowed in an earlier stage (`_fold_where`: the anytime-valid canary rule counts a version's whole life, ADR 0025), and first writes `meta` `day_origin` (`DAY_ORIGIN_META`, read in `__init__`). Every stats reader adds `daily_rollup` back through `_rollup_by` and `_merge` only when it has rows (`_has_rollup`), so its old query and numbers are unchanged otherwise; a new stats reader over `requests` must do the same. `export_page(kind, after, limit, ...)` pages a table for NDJSON (`EXPORT_KINDS`, `EXPORT_FILTERS`) and never exports an end-user hash. `locked()` returns the lock for callers that read, decide and write (`privacy.erase`, `apply_retention`). `BACKFILLS` fill a new column in old rows right after `_migrate` adds it.
- **Transactions and manual changes** (ADR 0064). `transaction()` is one `BEGIN IMMEDIATE ... COMMIT` under `_lock`; nested calls join; events written inside reach the listeners after the commit (never on a rollback, which also bumps every generation so no cache keeps a rolled-back row). Inside, call only reads, `event`, `transition`, `promote_live`, `set_flag`, the task-override writers and `record_admin`: any other writer commits by itself and the transaction raises at its end. `flags()` is the `RuntimeFlags` snapshot of `runtime_flags` and `task_overrides` (WATCHED, plus `PRAGMA data_version`), read once per request by the router; it also publishes the runtime pins to `tasks.OVERRIDES`. A bad row written by hand is ignored, never an error. `admin_actions` rows are written by `record_admin` only, from `ratchet/admin.py`, in the same transaction as the change; `admin_actions(limit)` reads them (`_reads`).
- `tasks` holds the admin API's tasks (and later auto tasks): `save_task(name, spec, spec_hash, source, updated_by)` (returns `(created, old_hash)`), `delete_task`, `saved_task`, `saved_tasks`. `spec` is `taskspec.document(task)` as JSON **in its own key order** (the order of `fields` is part of `spec_hash`, so never `sort_keys`); `updated_by` is the admin key's name (INV-13). Built-in and file tasks are never stored.

## Privacy, keys and BOMs

- `redact.py`: `redact_messages` covers every message field that can carry user text: content (strings and text parts), `name`, `refusal`, tool and function call arguments. `redact_json` redacts every string value of a JSON value (the stored generation conditions), keeping object keys; iterative, so nesting depth does not matter. `PATTERNS` is an ordered list of `(label, regex, check)`; earlier patterns win, so put specific formats (with checksums) before broad ones like `PHONE`. Every new pattern needs a positive test **and** must keep `test_redact_leaves_ordinary_text_alone` and `test_redaction_is_a_no_op_on_the_mock_world` passing (mock lookups match exact text). `spans(text, detector)` is the one place that finds what to replace (ADR 0082): `_pattern_spans` runs v0.4's pass (each pattern once, earlier matches masked with `_MASK`, the same length, so offsets stay the original's); the only retry is for the labels in `_RUNS` (`CARD`, `IBAN`): `_matches` tries a refused match shorter and keeps it only with a short tail of its run (`_TAIL`, `_free_before`, `_free_after`) or the next word after it (`_word_after`), and hides the tail from later rules. Never add a retry that tries more windows of a run: about one in ten passes a checksum by chance, so it cuts long reference numbers into pieces (`test_label_style_matches_v04` pins v0.4's output on 8,000 of them). `_merge` joins a detector's spans. `Pseudonymizer(style, detector)` turns spans into placeholders (`label`, `numbered`, `surrogate`; `_key` says when two spellings are one value, `_surrogate` the reserved values); make one per example and never share it across examples or threads. `redact_json` visits object members in key order (the example hash sorts keys), keeping the client's order in the copy. A writer of examples that redacts in another style or with the plugin passes `add_example` the key under the default redaction (`canon_hash`), as `_store_example` does, so erasures hold. `load_detector` is the only way to load `RATCHET_REDACT_PLUGIN`; `RedactionError` never carries the text or the plugin's own message.
- `auth.py`: `KeyRing(spec, env="RATCHET_API_KEYS")` raises `ValueError` naming `env` on a bad spec, so a typo stops the gateway at startup. `identify()` compares SHA-256 digests with `hmac.compare_digest` over every key. The gateway builds one ring for API keys and one for admin keys (`RATCHET_ADMIN_KEYS`) and refuses a key in both (`KeyRing.shared`). `parse_key_limits(spec, names)` reads RATCHET_KEY_LIMITS (`name:store=0;...`) into `KeyLimits`; `KEY_LIMIT_FIELDS` lists the fields built (only `store`), every other field is refused, and an unknown name is never quoted (it may be a pasted key). Spend and rate limits extend `KeyLimits` in the same syntax.
- `privacy.py` (ADR 0080): `OPT_OUTS`; `store_header` (`X-Ratchet-Store`; ValueError for a value it does not know) and `request_opts_out(store, metadata, header)` (any one opts out); `end_user_of(user, safety_identifier)` (the attributed value) and `end_user_ids` (every value a request carries, attributed first); `EndUsers(key, source).hash(value, client)` = HMAC-SHA256 over `client + NUL + value`, 16 hex digits (the whole value, any length), `hashes(value, clients)` for an admin acting on several scopes and `aliases(ids, client)` (the other hashes a no-train registration may use: further ids in the client's scope, every id in `EVERY_CLIENT`); `no_train_scopes(key_names)` and `check_no_train_scopes(ledger, key_names)` (startup: a `no_train_unmatched` event once per change for registrations no current scope matches); `end_users(ledger, configured)` picks RATCHET_END_USER_KEY or the ledger's generated key (`meta` `end_user_key`, created once with `meta_setdefault`) and writes an `end_user_key` event when the key id changed.
- `privacy.py` (ADR 0081): `erase(led, client=, end_user_raw=, hashes=, contains=, actor=, reason=, dry_run=True, shared=, hasher=, end_user_clients=)` checks the scope (`_check_erasure`: never quotes an end user or `contains`; the reason is stored `redact`ed; the actor is a name, `auth.valid_name`), hashes the end user in each scope, and under `led.locked()` selects, decides per row (`dataset.counts_as_train`; shared rows by `RATCHET_ERASURE_SHARED`), reports `affected_versions` and, unless a dry run, calls `Ledger.record_erasure` and writes the `erase` event (counts and names only). `apply_retention(led, retention, now=, client=, example_days=, request_days=, dry_run=, chunk=)`: the two windows (`config.Retention`), examples purged `chunk` per transaction with the lock free between chunks, one `purge` event. `recorded_end_users(led, configured)`: the gateway's `EndUsers` for a CLI, read-only, only when its key id is the ledger's `end_user_key_id` (ValueError otherwise; never `end_users`, which writes). `check_export` (before the first line) and `export_lines` (pages of `EXPORT_PAGE`). `parse_since` reads epoch seconds or ISO 8601.
- `admin.py`: `python -m ratchet.admin erase|export` (`run_erase`, `run_export`; `main(argv, stdin=, stdout=)` for tests); an end user without `--client` covers every scope the ledger holds end users in (`Ledger.end_user_scopes`) and is hashed with `privacy.recorded_end_users` (the gateway's key, checked against the ledger's key id; the CLI's environment may not be the gateway's, so it refuses rather than write or miss); `--end-user -` reads stdin; `--actor` is a name.
- `feedback.py` (ADR 0091): `submit(ledger, ratchet, request_id, client, verdict, correction, end_users=, key_store=, policy=)` records one verdict per request (`Ledger.record_feedback`) under `led.locked()`: `FeedbackNotFound` for another key's request as for an unknown one, `FeedbackError` (a 400: a correction with `correct`, a correction the spec refuses, end-user identifiers missing or not the request's) and `FeedbackConflict` (a 409: `correct` after a stored correction, a second correction of other messages); `_policy_reason` lists why a correction is kept out (`NOT_STORED`), broadest first. `prepare(task, messages, completion, params=, redact_pii=)` is string work (clean, `Task.check` raising `LabelError`, redact, hash), done outside the lock. `store_label` is the only writer of human and imported labels (the INV-2 allowlist): pinned and no-store tasks and zero retention refused, `licenses.SOURCES[human]` or `require_distillable(source)`, the golden-only check (`held_out_ok`: `Ledger.prompt_status` for that prompt, inside the transaction), then the read, the precedence decision (`_rank`: teacher 0, correction 1, import 2) and `add_example(verified=, golden_only=, origin=, replace=, bump=)` in one `Ledger.atomic()` transaction. `conditions(policy, params)` gives a label the teacher answer's stored conditions (the serving allowlist), so both hash alike. `check_human_alert` writes `human_alert` once per version (`meta_setdefault`) when the mixture e-value against 'precision >= live_floor' reaches 1 / `ALERT_ALPHA` (anytime-valid, since it runs after every verdict); nothing in `release.py` reads feedback. A correction must send every end-user identifier the request carried (`requests.end_user`, `requests.end_user_secondary`; `_end_user_check`). `bump=False` labels insert `seen` 0 (`ledger.seen_count`).
- `importer.py` (ADR 0091): `python -m ratchet.importer FILE --task T --source human --attest TEXT | --source teacher:<model> [--golden-only] [--client NAME] [--dry-run] [--db PATH]`. `run_import(ledger, settings, stream, ...)` refuses the whole import first (`parse_source`: `closed_family`, router aliases and `require_distillable`, the clause quoted; `check_attest`; `check_task`: registered, not pinned, not no-store, no zero retention), then reads lines of at most `RATCHET_MAX_BODY_BYTES` (`_lines`; a longer one is skipped without being kept), `parse_row` (OpenAI's format or Ratchet's `train.jsonl`, whose task and provenance must match), the chat route's `validate_chat_request` and `normalize_messages`, `feedback.prepare` and `feedback.store_label` with `bump=False` and `replace_same_rank=True`; in-file duplicates and conflicts are counted, the file is hashed as it is read, and one `import` event is written (never row text; the attestation redacted). `--dry-run` imports into an in-memory `backup` of the ledger (`_copy`). `main(argv, stdin=, stdout=)` for tests. `parse_key_limits(spec, names, defaults)` turns `RATCHET_KEY_LIMITS` into one frozen `KeyLimits` per key name (ADR 0063); an error names the key and field, never an unknown entry (it may be a key). A new limit field goes into `LIMIT_FIELDS`, `KeyLimits`, `_limit_value` and docs/CONFIGURATION.md.
- `spend.py` (ADR 0063): `SpendMeter` is the only place per-key and gateway spend is counted for the limits. It reads the ledger at startup only (`Ledger.api_usage_since`, gateway rows: `request_id` set) and on a clock moved back; never add a query to `usage()` or `add()`, which run on every request (`test_quota_path_issues_no_count_query`). Code that spends money for a gateway request after it was answered calls `add(client, usd, requests=0)` and records the cost where the startup read finds it (`requests.cost_usd` or `failures.cost_usd`). Alerts are written outside the meter's lock and never raise.
- `ratelimit.py` (ADR 0063): the limiter refuses at once (`Refused`), never waits. `Limiter.rate` takes a token before the body is read; `Limiter.hold` takes the in-flight slot, then the key's slot, once the body is in (never earlier: a slow body would hold a slot no worker uses), and gives back what it took when it refuses. Clocks are monotonic and injected (`Runtime(clock=)`).
- `bom.py`: `manifest()` from the exact train and golden rows, `document()` wraps it with `sha256` and an optional Ed25519 signature over `canonical()`. `Signer` imports `cryptography` lazily (the `sign` extra). Change the manifest shape only with a new `SCHEMA` version. Schema `ratchet.bom/v2` (ADR 0024): every v1 field, plus `redactor` (`redactor(redact_pii)`: a SHA-256 over `redact.PATTERNS`' labels, patterns, flags and checksum names, and whether redaction was on) and `training.origins`; `manifest(commitments={'training': (root, size), 'golden': ...})` adds `{alg: ratchet.smt/v1, root, size}` (the size must be the split's rows), `manifest(extra=)` the `EXTRA_KEYS` (`teacher`, `backfill_jobs`, `erasures_honored`) and refuses any other key. `verify` accepts `ACCEPTED` (v1 and v2) and refuses any other schema; `verify(doc, key, accepted=(receipts.SCHEMA,))` checks a savings receipt, which the same key signs the same way (never raises: a malformed signature is a failure). Stored v1 documents are never rewritten (INV-14). `commitment(m, split)` reads a manifest's commitment for `train` or `golden` (`COMMITMENT_SPLITS` maps sections to splits) for verifiers: `{alg, root, size}` or None for a v1 or malformed document, never an error. Every BOM `run_night` writes since v0.5 carries both commitments. The licenses travel with the adapter (NFR-9, [ADR 0090](../docs/adr/0090-licenses-travel-with-the-adapter.md)): every v2 manifest also has `base_model_license` (`notices.base_license`: `{name, url}` from `licenses.BASE_MODELS`, or both null and a `warning`), `notices` (`[{file: NOTICE.md, sha256, text}]`, rendered by `notices.render` from the manifest's own sources and generator) and each source's `license_origin` (`notices.sources`, which builds `sources`); `verify` does not depend on them, so v2 documents written before still verify. `check_notice(doc, bytes)` ties a NOTICE.md file to the BOM (SHA-256 against its `notices` entry; `verify --notice`).
- `stats.py` (ADR 0024): exact statistics, stdlib only, no package imports at module level (sim/ uses it alone; `main`'s `check` imports `ratchet.bom` and `ratchet.certificate` when it runs). `python -m ratchet.stats plan|bound|mcnemar|check` (`main(argv, out=)`): exit 0, 1 when `check` finds a failure or a number that does not follow from the signed counts (beyond 1e-9), 2 on bad input. Binomial tails sum the smaller tail from one `lgamma` term and a ratio recurrence (tiny values keep relative accuracy); `cp_lower` bisects and rounds down; `precision_pvalue`, `required_rows`, `mcnemar_one_sided`; `ltt_fixed_sequence` over a fixed grid (`CERT_GRID`, never one built from the data) returns `SERVE_NOTHING` when nothing is certified; `log_e_bernoulli` / `e_bernoulli` (a mixture over `alt_grid`, valid under the composite null with no independence assumption, capped at exp(690)) and `confidence_sequence` (on a 0.001 grid; checked arguments, then a scan cached by counts in `_confidence_sequence`, because the gate's events and `/ratchet/stats` ask again until a new audit lands); `wilson`, `kish_n_eff`, `hajek_mean`, `ratio_estimate` (`insufficient` below `min_n`). Inputs are checked (`ValueError`), nothing returns NaN. A new estimator or test here gets an oracle and a Monte Carlo check in `tests/test_stats.py`.
- `certificate.py` (FR-16.3, ADR 0026): the certificate arithmetic on (confidence, correct) points, stdlib and `stats` only. `certificate` (Clopper-Pearson at the threshold, `certified = lcb >= target`), `frontier` (each `CERT_GRID` threshold at delta / len(grid)), `per_task` (each at delta, a diagnostic), `outcome_vector` (the eval's `test_vector`, `S`/`W`/`E`), `paired` and `paired_stats` (McNemar on coverage and on wrong answers as a client sees them, an escalated row being right; the served negative flip rate with its Wilson interval), `section` and `status` (the endpoint's), `ASSUMPTIONS`, and `recheck(eval)`, which recomputes every number from the counts and returns (checked, problems); keep it in step with every key `cascade_eval` writes. Everything returned is JSON.
- `merkle.py` (ADR 0024): `KeySet(pairs)` is a collapsed sparse Merkle tree over 32-byte keys and values (bytes or hex; duplicates raise): `root`, `size`, `value(key)`, `prove(key)` in O(log n) from the node hashes kept at build (one per node with two keys or more, keyed by range and depth). `verify(root, key, proof)` returns `included`, `absent` or `invalid` and never raises (proofs come from untrusted files). RFC 9162: `LogTree(leaves)` (`root`, `path(i)`), `mth`, `inclusion_path`, `verify_inclusion` (False on malformed input; take the size from the same signed record as the root). `KeySet.items()` and `keys()` return the pairs and keys in order (what a verifier rebuilds the tree from). `prove` only reads the node hashes kept at build, so one `KeySet` serves proofs from several threads.
- `nightschool/dataset.py` (FR-16.4): `leaf_value(row)` is the SHA-256 of `bom.canonical({completion, teacher, license, redactions})` (the stored teacher answer, its teacher and license, the placeholder count); `commitment(rows)` returns (root hex, size, sorted (key hex, value hex) leaves) with key = `provenance.hash`. Changing either changes every root from then on: it needs a new `SMT_ALG` and an ADR.
- `proof.py` (FR-16.4, ADR 0027): `request_key(task, messages, params, redact_pii=, policy=)` computes the key `Ratchet._store_example` stores a teacher answer under (redacted messages and `STORED_PARAM_KEYS` of `policy.plan(params).serve`); `resolve_key(body, ...)` takes `{"key"}` or a chat request, validated and normalised with the gateway's `Limits`, modalities and `merge_system` (`ValueError` with a client message otherwise; a teacher-only part is refused because it is never stored). `test_request_key_is_the_stored_hash` keeps the two in step: change one, change both. `verify_proof` and `verify_heldout` check a file against the root the BOM signs (`bom.commitment`), never the file's own `root`, `result` or `value`, and return (ok, lines) for any input, never raising. `main(argv, out=)`: `key`, `verify`, `heldout`; exit 0, 1 on a failed check (also a file that is not JSON), 2 on bad input.
- Gateway: on `/v1/chat/completions`, `BodyLimitMiddleware` (413), `_client()` (401), `validate_chat_request` + `_request_meta` (a bad `X-Ratchet-Store`) + `normalize_messages` (400), `Ratchet.task_for` (400 `unknown_task` under `reject`, and for a header that is not a task name under `teacher` too; 403 `task_not_allowed` for a key the task's `clients` do not name, or outside the key's own `tasks` scope), then `_quota()` and `_budget()` (429, from the spend meter, no query) run before the cascade, so a refused request is never logged or counted; the request rate (`_rate`: 429 `rate_limit_exceeded`) runs earlier, on the event loop before the body is read, and the in-flight caps (`_hold`: 503 `overloaded`, 429) once the body is in, around the worker thread. A scrubbed `/ratchet/stats` read names no key and no dollar cap (`access.scrub_event`, `spend.public_alert`). `/healthz` is public. After the cascade `_complete` adds the request's `cost_usd` to the meter, or on any exception what the request spent (`RequestContext.spent_usd`). In `RATCHET_BUDGET_MODE=student_only`, a spent gateway budget sets `RequestMeta.student_only` per request (never a global flag: Scout must not see it); `handle` then raises `spend.BudgetExceeded` instead of any teacher call (`_budget_refused`). `GET /ratchet/versions/{vid}/certificate` (`version_certificate`, public like `/ratchet/stats`, 404 for an unknown version) reads the signed BOM's `manifest.eval` (`training`) and the version's eval (`current`, with `rechecked_day`) through `certificate.section`, the gate's evidence for `SERVED_STATES`, and leaves `drift` None for the drift alarm (FR-16.6) to fill: an open alarm (`drift['alarm']`) makes the status `suspended`. Streaming runs the cascade first, then yields chunks (`_chunks`), so errors are ordinary HTTP errors.

## Configuration checks (`config.py`, `readiness.py`)

ADR 0070. `config.load()` builds `Settings` with the helpers (`_int`, `_float`, `_float_or_none`, `_bool`) collecting a value that does not parse instead of raising (`_COLLECT`, a context variable; outside `load()` they raise `ConfigError(var, value, expected)` at once). `config.check(settings)` = `Settings.validate()` + in live mode `ReleasePolicy.env_issues()` (each `RATCHET_<FIELD>` on its own, then `validate()`); a reader that checks several variables runs again past each problem (`_every_problem`, with `config.defaults()`), and every setting `Runtime.reset()` reads must be checked there, so the CLI exits 2 exactly when the gateway would not start; `Runtime.__init__` runs it before `reset()` and raises `ConfigError.of(errors)` (a `ConfigLicenseError`, also a `LicenseError`, when a teacher is refused). Validation lives only there and in the CLI: `Settings()` and `ReleasePolicy()` themselves accept what the simulator and the tests use. A message names its variable and never holds a key's value or a URL (which may hold a password). `KNOWN_ENV` must list every variable the package reads (`reqtrace` rule `rule_env_known`); `DEPLOY_ENV` the deploy kit's. `/readyz`'s probes block, so they run on `readiness.pool(...)` threads, never on the event loop or AnyIO's request threads; whatever `Readiness.report` reads on the event loop (breaker states, `Guard.status`, the flags) must take only short locks. Leaving `not_ready` must never need a request (a 503 instance gets none): a teacher breaker whose probe is due counts as a way through (`_way_through`), and a busy ledger is `not_ready` only on two probes in a row. A new operational switch for `/readyz` registers in `readiness.FLAGS`.

## Reserved settings (`config.py`)

`RESERVED_SETTINGS` declares the evidence features' `Settings` fields (name → variable, default as the environment spells it, the feature) with defaults that keep today's behaviour; `KNOWN_ENV` lists their variables for the traceability check. `Settings.check_reserved()` raises `ValueError` naming the variable and the feature for any other value; `Ratchet.__init__` and `live.main` call it, so the gateway, the simulator and the nightly job refuse. `_float_or_none` reads an optional number (unset or empty: None; `scripts/reqtrace.py` sees its reads). The item that builds a feature removes its entries and adds its own validation; where its default differs from today's behaviour (none now), today's value stays the default until then. `RATCHET_DB_SYNC` left with the WAL journal (ADR 0060): `Settings.ledger_sync()` checks it (`NORMAL` default, `FULL`), next to `tick_interval()` and `stats_ttl()` (`_seconds`: 0 to `MAX_INTERVAL_S`, defaults by mode). The anytime-valid gate removed its entries (`canary_audit_rate`, read through `Settings.checked_canary_audit_rate()` in `Ratchet.__init__`; the seven `ReleasePolicy` fields) and made `alert_eprocess=1` the default. Savings receipts removed `take_rate`, `receipt_min_audits` and `mock_teacher_reasoning_mean` (read through `Settings.receipt_policy()`, a `ReceiptPolicy`, in `Runtime.reset`, `live.main`, the simulator and the receipt CLI, and `Settings.checked_mock_reasoning_mean()` in `Runtime.reset` and `live.main`, in every mode). Certified precision removed `calibration`, `cert_target` and `cert_delta` (read through `Settings.cert_policy()`, a `CertPolicy`, in `Runtime.reset` and `live.main`, which build `MockFleet` and `LiveEvaluator` from it) and its four `ReleasePolicy` fields. Lane G1 added `gateway_lease` (`RATCHET_GATEWAY_LEASE`, default `warn`) for the single-writer lease (NFR-60), which waits for lane D's leases table; `Settings.scout_policy()` (a `ScoutPolicy`, read in `Runtime.reset`) checks Scout's judge and Tavily credit settings, resolves the derived judge shares, and never prints the judge code (`scout_judge_code` is `repr=False`).

`KNOWN_ENV` lists exactly the variables the package reads (ADR 0070; `scripts/reqtrace.py` checks it), the live-run harness's `TOOL_ENV` included. `DEPLOY_ENV` lists the variables only the deploy scripts and the demo VM read (`deploy/train_job.sh`, `deploy/student_endpoint.sh`, `deploy/vm/.env`); the package never reads them, so they are not in `KNOWN_ENV`, the startup check does not call them unknown, the traceability check holds each to a row in docs/CONFIGURATION.md, and `test_deploy_variables_are_listed_and_documented` (tests/test_live.py) checks the list against the Nebius scripts.

## Licenses (`licenses.py`)

To add a teacher, add it to `BUILTIN` with its real license name and URL. `CLOSED` prefixes are refused. `Ratchet.__init__` calls `require_distillable` on the teacher and on the fallback teacher (`RATCHET_TEACHER_FALLBACK_MODEL`), so a bad config fails at startup, and keeps the results in `Ratchet.licenses` for `_store_example`.

Configured teachers (FR-3.53, [ADR 0090](../docs/adr/0090-licenses-travel-with-the-adapter.md)). `BUILTIN` is a read-only `MappingProxyType`; `REGISTRY` is the registry in force, published by `install(path)` as a new dict `{**BUILTIN, **configured}` in one assignment, so readers never lock; always read `licenses.REGISTRY` (never `from .licenses import REGISTRY`). `install` runs at every entry point's startup, before any lookup: `Runtime.reset` (first, before the ledger opens), `Ratchet.__init__` (the simulator, direct construction; before `require_distillable`), `live.main` and `admin.main`. `parse_entries` checks RATCHET_TEACHER_LICENSES' JSON list of `{model, license, url, note}` and raises `LicenseConfigError` (a `LicenseError`, so a `ValueError`) with every error as `[i].field: message`: a license outside `ALLOWED_LICENSES` (any case, stored canonical), a model id in a closed family (`closed_family`: any part of the id starting with a `CLOSED` prefix or `o` and a digit, or containing `gpt`, `claude`, `gemini` or a `CLOSED_NAMES` or `CLOSED_VENDORS` name; stricter than `lookup`'s last-segment rule) or a router alias (`closed_family` returns `ROUTER`: a part containing a `ROUTER_VENDORS` name, or a last path segment in `ROUTER_ALIASES`), a built-in teacher (in any case), a duplicate, a non-https URL, unknown keys, control characters, more than `MAX_CONFIGURED`. Configured entries have `TeacherLicense.origin` `config` (built-in ones `builtin`); `lookup` returns the closed terms for a configured entry that names a closed family, should one get in. Never widen `ALLOWED_LICENSES` or loosen `closed_family` without an ADR (INV-1). `closed_family` only knows the names it lists; any other id is admitted on the operator's claim (marked `config`), so docs must not say configuration cannot add a closed teacher, only that it cannot relabel one Ratchet knows of. `tests/conftest.py` resets the registry after every test (`reset_builtin`). `BASE_MODELS` maps known student base models to their license, matched in any case (`base_model_license`); an unknown base model is a warning in the BOM and NOTICE, never an error.

Provenance sources (FR-3.54, [ADR 0091](../docs/adr/0091-human-labels-as-a-provenance-source.md)). `SOURCES` (read-only) holds `human`, customer-provided labels: never in `REGISTRY`, refused by `require_distillable` and by `parse_entries` in any case (`is_source`). Readers of stored rows (`dataset.rows`, `counts_as_train`, `notices`) use `lookup_source` (the registry, then `SOURCES`); a teacher about to be called always goes through `require_distillable`. Every OpenAI family in `CLOSED` carries the Section 3.3(e) note (`OPENAI_TERMS`), so a refusal can quote it.

## Tasks (`tasks.py`)

`REGISTRY` holds the tasks a request can name. `Task.pinned=True` means always the teacher, never training data (`research-plan`, `research-write`). `stats_by_task()` reports `pinned` per task, which the dashboard's **By task** table shows. `get(name)` returns a registered task, or for an unknown valid name a new task without fields (`source` `adhoc`, never added to `REGISTRY`, never pinned); it applies no policy, because Night School needs a comparator for every stored name. `lookup(name)` returns only registered tasks. Runtime pins (ADR 0064): `OVERRIDES` holds the names an operator pinned with the admin API or CLI, published by `Ledger.flags()` (`set_overrides`, one assignment); `get` and `effective(task)` return a pinned copy of a registered operator task (`PINNABLE_SOURCES`) with its spec's own `spec_hash`, and the task as registered once the pin is gone, so the router and Night School need no code of their own for it. `reset_builtin` clears them.

The registry (FR-2.15, [ADR 0022](../docs/adr/0022-task-registry.md)). `BUILTIN` (read-only) holds the tasks defined in code; add a built-in task there. `taskspec.install(ledger, path, known_clients)` (the gateway's `Runtime.reset`, `live.main`) builds a new registry aside (`builtin_registry()`, then `add(registry, task)` with `register`'s rules for the tasks file's tasks and the ledger's stored API tasks) and publishes it in one assignment (`replace_all`), so a request never sees it half made and a bad file leaves it as it was; it returns a line per stored task it skipped (no longer valid, or its name taken by a built-in or file task) for the caller to log; a bad file raises `taskspec.SpecError` (a `ValueError`) with every error. `register(task, source=None)` follows `_REPLACES`: a file task replaces a built-in one; an API task replaces only an API or auto task; an auto task only an auto task; `builtin` and `adhoc` are never registered; `TaskConflict` names the owner, `RegistryFull` past `MAX_TASKS` (500, every source). `unregister` removes API and auto tasks only; `restore(name, previous)` undoes a write that could not be persisted. Writers take `_REGISTRY_LOCK` and publish a **new dict** (`global REGISTRY`), so readers never lock; always read `tasks.REGISTRY` (never `from .tasks import REGISTRY`). `tests/conftest.py` resets the registry after every test.

Specs as data (`taskspec.py`): `parse_spec(obj, source, lookup=, known_clients=, where=)` for one spec (an API body; `extends` any registered task) and `parse_document(doc, source, known_clients=, origin=)` for `{"tasks": [...]}`, checked as startup reads the tasks file: `extends` reaches the built-in tasks and the document's own (never an API task, which startup registers after the file), and the tasks with the built-in ones they do not replace fit in `MAX_TASKS`. `POST /ratchet/tasks/validate` uses the same function, so a document that validates starts. Fields are `{path: {type, ...options}}`; `OPTIONS` maps every `FieldSpec` option to its check (`_CHECKS`) and the types that take it (`compare.OPTION_TYPES`, which `FieldSpec` enforces too; `test_specs_round_trip_and_every_option_is_checked` fails when `FieldSpec` gains an option the table lacks), so an option for another type is refused instead of ignored. Every error is collected as `<path>: <message>` (paths `tasks[i].fields.total.abs_tol`, `fields["a.b"]` for dotted paths) and raised together; `FieldSpec` and `Task` build the result and check it again, so the parser can never admit what they refuse. Recursion is bounded (records 4 deep, `item` scalar only, `routing` 32 deep and checked iteratively); JSON is strict (`loads`: no NaN or Infinity). `extends` resolves at definition time (`_merge`: `fields`, `sql`, `policy`, `match` by key, null removes, `name` and `description` not inherited). `document(task)` writes a task back in `SPEC_KEYS` order; `parse_spec(document(t))` equals `t`. A task's `description`, `clients` and `match_rules` (a spec's `match`; `Task.match` is the comparator method) are outside `spec()` and `spec_hash`. `Task.allows(client)` is the allow-list check (no `clients`: everyone; with them, never a request without a key). `Task.verifiable` is true for a field other than `similarity`, or for a sql task that runs its answers on a fixture. `resolve_fixture(path, root)` (`sqlcheck.resolve_fixture`) keeps fixture files inside `RATCHET_FIXTURES_DIR`; a sql spec's fixture is read and loaded when the spec is parsed (`fixtures_dir=`).

Field comparators (FR-2.14, [ADR 0021](../docs/adr/0021-field-comparators-and-task-specs.md)). A task's spec is `format`, `fields` (a tuple of `compare.FieldSpec`), `policy`, `routing`, `store` and `tools`; `Task` and `FieldSpec` are frozen and validate everything in `__post_init__` (a bad spec raises `ValueError` when it is defined, never on the request path). `compare_keys` is only a constructor shortcut (optional `exact` fields; a key with `.`, `$` or nothing is refused, because it would be read as a path) whose `canonical()` is v0.4's string byte for byte; never read it to decide anything, read `fields`. The API: `key(text)` (each field's normalised value by path, or `compare.INVALID` = `tasks.NO_KEY`), `match(ka, kb)`, `agree(a, b)`, `valid(text)`, `check(text)` (the reason, `invalid field <path>`, which names the spec and never the answer, so it can go into an event) and `canonical(text)` (logs and legacy tests; `tasks.INVALID` is the string `<invalid>`). Compute a key once per answer and compare keys; `confidence.score` is pairwise (`votes[i]` = valid samples that `match` sample i, each pair compared once; the majority is the first with the most votes; the answer is the best-probability member among those with as many votes, so its agreement is its own; no vote at all scores 0), which equals the old `Counter` count for transitive comparators, so never reintroduce a count of canonical strings. Every matcher must be symmetric, and every value must match itself. Fields are required by default: an invalid answer gets no vote, is not stored, is not an audit or shadow reference, is skipped as a golden reference (`cascade_eval`'s `golden_invalid_refs`) and as a train row (`dataset.rows`, `skipped_invalid`). The built-in vocabularies live in `vocab.py`, imported by `sim/tickets.py` and `scout/prompts.py`; `ratchet/` never imports `sim/`. A task without fields compares canonical JSON when both answers are JSON objects or arrays (`_whole_key`), else the v0.4 text rule. `Task.structured` is `format == "json"`. `spec_hash` is derived from `spec()` (not settable). Every comparator is linear in its value and stdlib only (`compare.py`): numbers, dates and languages over 100 characters are refused at once, records pair by key or position in linear time, and otherwise by grouping on their fields without a tolerance (`FieldSpec._by_equality`, `compare._token`) and a maximum bipartite matching on the rest (`_perfect_matching`, quadratic in a group, within `MAX_RECORDS`: 200 per answer at any depth), so their order never decides; `language` takes a locale tag only as the whole value (`_LOCALE`, never prose that starts with a code); and `tool_calls` (a type and a format) is a reserved name a spec may not use until its item lands (`similarity` and `sql` were reserved the same way until FR-2.55 and FR-2.56). A new type adds a normaliser to `compare._NORMALIZE`, a matcher to `compare._MATCH`, the options it takes to `compare.OPTION_TYPES` (any other option must keep its default; `taskspec.OPTIONS` reads the same table), its option checks to `FieldSpec.__post_init__`, a row in CONFIGURATION.md's field-type table and a positive and negative test in `tests/test_tasks.py`.

Answers are cleaned in one place (FR-2.7): `strip_reasoning` removes complete `<think>` blocks (any case), everything up to a lone `</think>` and an unterminated `<think>` that opens what is left, with what follows; a `<think>` after answer text is content (an answer that mentions the tag), so never cut at a tag in the middle of an answer. `clean_answer(task, text)` adds, for structured tasks only, keeping an answer whole when it is one JSON object (`_whole_object`: bare or in one fence, as it is, after its first `</think>` or after `strip_reasoning`; a tag inside an object is in a string), else unwrapping one code fence that is the whole answer when its body is JSON. Cleaning twice gives the same text, because stored answers are cleaned again when compared. `Task.key` (and so `canonical`, `valid` and `check`) calls `clean_answer`, and an empty answer is invalid for every task. Compare, store and serve through these; never strip tags or fences by hand. `parse_json` tolerates reasoning, fences and surrounding text, and returns None (never raises) for JSON nested too deeply for the parser. All of these run on every sample on the request path, so keep them linear in the answer's length: no regex that can rescan from every position (`.*?` pairs, `\s*` before a literal), which a model's output can make take seconds (`test_answer_cleaning_is_linear_on_adversarial_answers`).

## Ledger replay (`replay.py`)

The ledger time machine (FR-16.5, [ADR 0028](../docs/adr/0028-designed-propensity-replay.md)). Reads only; standard library, `stats`, `tasks` and the ledger.

- `load(ledger, version, since_day, until_day)` → `History(version, rows, excluded)` from `Ledger.replay_rows` (read in chunks of `ledger.REPLAY_CHUNK` rows on the `requests_version_id` index, each under the lock, up to the last id when the read began, so `log_request` never waits for a whole history; rows with `confidence`, `label_p` and `threshold` set; `teacher_usd` is `baseline_cost_usd` for an audited row or an escalation the teacher answered); `excluded` counts `before_logging`, `no_student_answer`, `pinned_now` (a task pinned now, INV-10 at read time) and `malformed` (out-of-range values: nothing NaN ever reaches JSON). One version only, always: confidence scales differ between versions.
- `at(rows, t=None, audit_rate=None, *, r=, default_rate=)`: `t` None replays each row at its logged threshold (what happened). Coverage is exact; precision is Hajek over labelled served rows with weights 1 / `label_p`, null with a reason without positivity (`MIN_LABEL_P`), with nothing served or no label; the interval is `stats.wilson` at Kish's n_eff (approximate, and labelled so). Cost = student spend + unserved T_i + audit rate × served T_i (T_i known or `estimate_usd × R`). `Row.servable` excludes confidence 0, route `n_choices` and `Row.spec_changed` (logged at `SERVE_NOTHING` while the task's spec is still changed for the version, `Ratchet.spec_changed`; set by `load`) at every threshold. Not logged, so servable: an n > 1 request that escalated on route `confidence` with fewer than n samples agreeing (it would be `n_choices` at a lower threshold); ADR 0028 says so. `sweep(rows, thresholds)` computes many thresholds in one sorted pass and `at(rows, t)` is `sweep(rows, [t])[0]`, so frontier rows equal single replays to the bit.
- `ratio(rows)`: the calibrated baseline (`stats.ratio_estimate` on audited served rows, weights 1 / `label_p`, `MIN_RATIO_N` 30). `suggest(rows, target)`: fixed-sequence scan of `stats.CERT_GRID`, always with `ADVISORY` (never applied: thresholds change only through Night School). `money_left_on_table`, `report`, `frontier_report` (the endpoints' payloads), `render` and `main` (the CLI: exit 2 on bad input; it opens an existing file only).

## Savings receipts (`receipts.py`)

Verified savings receipts (FR-15.5, [ADR 0029](../docs/adr/0029-verified-savings-receipts.md)). Standard library, `stats`, `bom`, `merkle` and the ledger; `cost` only for the gateway-wide receipt's GPU view, imported when it is built. `ratchet/receipt.py` only runs `main` (`python -m ratchet.receipt`).

- **Leaves** (`leaf(row)` from `Ledger.period_rows`, `RECEIPT_COLUMNS`): exactly `LEAF_KEYS`, every value a whole number, a string or None: amounts in nano-USD (`nusd`: `round(usd * 1e9)`, None for a missing or non-finite value), `label_p_ppb`, `ts_ms`; never request text (INV-12), the key's name as `client` (INV-13). `leaf_bytes` is `bom.canonical`; `tree(leaves)` the RFC 9162 `LogTree` in id order. A new leaf key changes every root: it needs a new `SCHEMA`.
- **Groups** (`category`): `measured` (`served_by` teacher), `served` (the student on the audit design), `unverified` (`UNVERIFIED_ROUTES`, equal to `router.STAND_IN_ROUTES`: `degraded` and `fallback_teacher`). Only `served` answers are calibrated, only `measured` and calibrated `served` answers are billed; an `unverified` answer's loss (`stand_in_losses`: min(0, baseline − cost), never a gain) still counts against the billable savings.
- **Estimate** (`calibrate(leaves, min_audits)`, `_task`): per task, `stats.ratio_estimate` on its audited served answers (x = `baseline_est_nusd`, y = `baseline_nusd`, weight `NANO / label_p_ppb`, 1 for a row without `label_p`, skipped at rate 0), point `round(R * x_total)`, `se_nusd = ceil(sqrt(N^2 (1 - n/N) s2 / n_eff))`; statuses `ok`, `insufficient_audits`, `unlogged` (a served answer without an estimate). Ratios and n_eff are decimal strings.
- **Bill** (`compute(leaves, share=, min_audits=, spend_nusd=)`): pure, from the leaves alone, so `recheck` and anyone holding the leaves get the same numbers. `margin` = ceil(1.645 sqrt(sum se^2)); the fee is `floor(Fraction(share_text(share)) * max(0, net))`; with no `ok` task the basis is `FORMULA` and the fee 0. Keep every key `compute` writes recomputed by `recheck` (`ESTIMATED_KEYS` within `TOLERANCE_NUSD`, `DECIMAL_KEYS` within `TOLERANCE_REL`, everything else exactly).
- **Sealing** (`SealConfig.from_settings(settings, signer, label)` checks the settings; `seal_due(ledger, config, through=, closed=)`, `seal(ledger, period, client, config)`): days up to `closed_through(ledger)` (the simulated ledger's day − 1; a live ledger's day that ended `SEAL_GRACE_S` ago on the wall clock), oldest first (`Ledger.unsealed_days`), each client's receipt (`Ledger.period_counts`) then the gateway's, which marks the day done; a day's spend outside requests (`Ledger.period_spend`) is netted in full from the gateway's and by request count from each client's. `_seal_one` writes once (`Ledger.add_receipt` raises `ReceiptExists` when another process won; its document stands). `_SEAL_LOCK` serialises sealing in a process. Sealing reads the ledger and writes receipts only: no model call, no random draw, so no simulation number moves; never add either. `manifest` chains to `Ledger.last_receipt(client, before=period)`.
- **Request retention** (FR-13.4, ADR 0081) deletes request rows into `daily_rollup`, so a receipt must be sealed before its day's rows are folded: the gateway's hourly retention (`Runtime._purge`), `python -m ratchet.live purge` and a live night with a request window seal every day that has ended first (`live.seal_receipts`), and `_seal_period` never seals a day whose rows were already folded (`Ledger.period_folded`; one `receipt_skipped` event per day, meta `receipt_skipped:<day>`). After a fold a sealed receipt still verifies, but its leaves and proofs are gone: the gateway answers 410 (`_receipt_folded`), never the integrity 500.
- **Verifiers** (`verify_receipt`, `verify_chain`, `verify_proof`, `verify_rows` / `recheck`, `check_manifest`): untrusted input, return (ok, lines) and never raise. Read nested fields through checked helpers (`_manifest`, `_day`), never `(m.get(x) or {}).get(y)`, which raises on a string or number; the public verifiers also catch any exception as a FAIL line. The chain recomputes the previous manifest's hash; a proof is checked against the root and size the receipt signs, never the proof's own. `proof_for(ids, tree, request_id)` gives (index, path). `main(argv, out=)`: `verify` exits 0, 1 on a failed check or a file that is not JSON, 2 on a missing file; `seal` opens an existing ledger only (a simulator's ledger, `replay.simulated`, counts every logged day as over), exits 1 when the day asked for has no requests in scope and 2 on an open day or bad input.

## Live-run harness (`liverun.py`)

The live measurement driver (FR-8.20, FR-8.21, [ADR 0121](../docs/adr/0121-live-measurement-method.md)). It is a client of the gateway, not part of it: nothing in the request path calls it.

- Traffic only via `/v1/chat/completions`, with the harness's own key from `RATCHET_LIVERUN_KEY` (never a flag); on the gateway it calls `/healthz` and that route only, never `/ratchet/*` (INV-8), and it refuses a mock gateway. It reads the gateway's ledger file directly and writes to it only through `live.main` and `Ledger.event` (`liverun_start`, `liverun_round`, `liverun_stop`: key names, counts and reasons). No schema change, no new `add_example` caller.
- No text or key written: records, state, results, plan, log and stdout hold metadata, counts and measurements only (answers are scored, then dropped); a base URL is never written either (`UNSAVED_ARGS`: a resumed or repeated run takes it from its command line). Errors name the exception's class (`describe_failure`), never its message.
- `sim` is imported lazily (`make_workload`), as the gateway's mock mode does; `ratchet` never imports it at module level.
- Seams are default arguments of `main` (`client`, `provider_factory`, `run`, `http`, `tavily`, `clock`, `timer`, `sleep`, `out`); production code passes none.
- `_control_call` must mirror `Ratchet._teacher_complete` for the serving role (`validate_chat_request`, `normalize_messages` with the teacher's modalities, `GenPolicy.plan(...).serve`, one choice, `temperature or 0.0`, `logprobs`) and must change with it; `test_liverun_control_call_matches_the_serving_teacher` compares the two bodies. The control arm never touches the gateway or the ledger (INV-2, INV-10).
- Every percentile it writes is nearest rank (`nearest_rank`, lane D's rule). A value that could not be measured is left out of `values` with a reason in `sources`, never written as 0. `verify` recomputes every id in `CLIENT_VALUE_IDS` from `requests.ndjson.gz`, so keep each of them a function of the records alone (`client_values`, `client_block`), summed in `_sorted_records` order.
- Spend is checked before every batch (`_cap_check`) and the control arm reserves its next call (`_Metered.reserve`) so concurrent workers cannot overshoot its cap together.

Text-to-SQL tasks (FR-2.56, [ADR 0055](../docs/adr/0055-sql-tasks-compared-by-execution.md), `sqlcheck.py`, stdlib only). A task with format `sql` has `Task.sql` (a frozen `SqlSpec`) instead of fields, and `Task.key` returns `SqlSpec.key(clean)`: a `SqlKey` (result digests and the normalised text) or `compare.INVALID` with one of the module's fixed reasons, never SQLite's message (it can quote the query). Only `Sandbox` runs SQL: never open another connection on a fixture, never run model text anywhere else, and never loosen `_query_authorizer` (reads of the fixture's tables and views and `ALWAYS_READABLE`, recursive CTEs and `FUNCTIONS` only) or remove `query_only`, the progress handler, the size limits, the per-call time check (`_Watch`: LIKE, GLOB, the date functions, `_GUARDED`) or the clock refusals (`_clock_read` on the text, `reads_clock` in the date functions, `_refuser` for CURRENT_* and random() while a fixture loads); a new function goes into `FUNCTIONS` only if it is deterministic, cannot load or write anything, and does at most linear work in one call, since SQLite runs no progress handler inside a VM step or within one row (measure it with values at `VALUE_BYTES`; a quadratic one gets a linear version in `_GUARDED` whose results equal SQLite's, checked by `test_sql_quadratic_builtins_replaced_by_linear_ones`, or stays out, like `json_patch` and `unhex`). Python 3.10 cannot remove an authorizer (`set_authorizer(None)` denies everything there), so switch with `_allow_all`. `Connection.setlimit` is what bounds a value's size, so a sqlite `Sandbox` refuses to start without it (`CAN_LIMIT`, Python 3.10). Sandboxes are shared by fixture text through a weak map (`sandbox_for`) and serialise their queries under one lock; outcomes that do not depend on timing are cached by statement. `SqlSpec.spec()` (inside `Task.spec()` only for sql tasks, so no other hash moves) holds the options and the fixture's sha256, never its path. `taskspec` reads fixtures through `sqlcheck.read_fixture` (inside `RATCHET_FIXTURES_DIR`, at most 5 MB, a regular file, no symlink) and passes `fixtures_dir` down from `Settings.fixtures_dir` (`install`, `parse_spec`, `parse_document`, `load_file`; default `config.default_fixtures_dir()`).

## Gateway (`gateway.py`)

`Runtime` wires everything; `Runtime.reset()` rebuilds it (mock reset endpoint) and runs the mock warm-up (`RATCHET_MOCK_WARMUP_DAYS`) if set. Mock mode imports from `sim/` and keeps three seeded streams (`tickets`, `research`, `mixed`). Live mode uses `Ledger(auto_day=True, sync=...)`; both modes build the gate with `ReleasePolicy.from_env()` (mock mode with `defaults={"min_audits": 15}`). `rt.tick(force=False)` runs `gate.tick()` under `gate_lock` at most once per `rt.tick_interval_s` (`RATCHET_TICK_INTERVAL_S`, on `rt.clock`) and returns False without waiting while another thread holds the lock; interval 0 (mock) or `force=True` (`simulate_day`'s ticks, which stand for simulated time) runs every call, waiting, as before. `_last_tick` is set before the gate runs, so a failing gate is not retried per request. `/ratchet/stats` goes through `rt.stats_cache` (`SnapshotCache(Settings.stats_ttl(), clock=rt.clock)`, rebuilt by `reset`): one computation per TTL, single flight; build the payload in `_stats_payload` only.

`Runtime(settings, transports={"teacher": ..., "student": ..., "tavily": ...}, sleep=..., clock=..., wall_clock=...)` puts an `httpx.BaseTransport` under the live providers (the student's also carries adapter reloads), so tests (and later items) run live mode offline, and `sleep` replaces the teacher's waits between retries; any other transport key raises, and mock mode ignores both. `wall_clock` (default `time.time`) is the time of day Scout's guard, credit meter and judge sessions count UTC days by; the `tavily` transport goes under live mode's `TavilySearch` client. `clock` drives the student breakers, `rt.reloader` (`live.AdapterReloader`, live mode with a student endpoint only, else None; tests wait for it with `join(timeout)`) and the mock fleet's demo outage. With no student endpoint, the hosted fallback student gets its own client (on the teacher's transport) with the student's timeouts and no retries. A fallback teacher on another base URL (`RATCHET_TEACHER_FALLBACK_BASE`) gets its own client too, with the teacher's key, timeouts, retries and transport; on the teacher's base URL, `Ratchet` uses the teacher's client. The other live entry points take their network and commands the same way, as default arguments that production code never passes: `OpenAICompatProvider(transport=, sleep=, clock=, rng=)`, `live.load_adapter(client=)`, `NebiusTrainer(run=, http=)`, `live.reload_adapters(http=)`, `live.main(argv, provider_factory=, run=, http=)`, `scout.agents.http_caller(client=)` and the Scout CLI's `main(argv, client)`. `tests/test_live.py` uses them; keep new live code testable the same way.

Pages: the React build in `web/dist` (source in `/web`, see [web/CLAUDE.md](../web/CLAUDE.md)) at `/`, `/scout` and `/dashboard`. The hand-written static pages (`web/landing.html`, `web/scout.html`, `dashboard.html`) are served at `/lite*` and as a fallback when the build is missing. Both are package data (`pyproject.toml`).

**OpenAI compatibility (`openai_compat.py`, [ADR 0012](../docs/adr/0012-openai-request-validation-and-error-envelope.md)).** Standard library only. `chat` is `async`: it checks the key, reads the body, and runs `_complete` (parse, validate, normalise, quota, cascade, response) in one worker thread with `anyio.to_thread.run_sync`, on the default pool sync routes use.

- `rt.limits` is `Settings.limits()` (`Limits`: RATCHET_MAX_MESSAGES, RATCHET_MAX_INPUT_CHARS, RATCHET_MAX_N; a `max_n` outside 1 to 128 raises, so startup stops); `n` above it is a 400 `unsupported_value`, and the gateway passes `req.n` to `handle` and `teacher_only`.
- Validate everything Ratchet reads or will forward, with an OpenAI `code` and a JSON-path `param`; keep unknown top-level keys in `ChatRequest.extra` (never refuse them). `parse_body` also refuses a string with an unpaired UTF-16 surrogate (it cannot be written as UTF-8, so the teacher call or the ledger would crash later). New request fields go into `ChatRequest` and `validate_chat_request` together, with a case in `VALIDATION_CASES` (`tests/test_openai_compat.py`) and a row in API.md's validation table.
- Message keys outside `ROLE_KEYS` (by role; `MESSAGE_KEYS` otherwise) and unknown keys inside tool calls are dropped by `normalize_messages`, so they are neither forwarded nor stored. A new message field Ratchet forwards goes into `ROLE_KEYS`, is checked and counted toward `max_input_chars` in `_message`, and is redacted in `redact_messages` if it can carry user text.
- `normalize_messages` must return a plain message as the **same object** (and the same list when nothing changes), or example hashes, golden splits, mock lookups and the reference simulation move. `test_normalize_is_identity_on_the_mock_world` checks every mock request.
- Errors on `/v1/*` and `/openai/*` use the envelope (`APIError`, `_http_error`, `_validation_error`, `_unhandled_error`); every other route keeps `{"detail": ...}`, which the dashboard reads. Raise `APIError` for a client mistake; a plain `HTTPException` is mapped by status (`openai_compat.STATUS_TYPES`). Never let a client mistake reach `_unhandled_error`: that is a 500 and a `gateway_error` event.
- A `KeyError` from the cascade is a 400 only in mock mode, and there only with `RATCHET_MOCK_STRICT=1` (`sim.world.lookup` does not know the request; otherwise the generic mock world answers it, ADR 0041); in live mode it is a bug (500).
- A teacher failure is never a plain `HTTPException`: `_map_upstream` turns its `UpstreamError` into an `APIError` with a code (`context_length_exceeded` and the teacher's other 400 codes, `upstream_rate_limited`, `upstream_auth_error`, `upstream_not_found`, `teacher_timeout`, `teacher_unavailable`, and `teacher_circuit_open` (503, `Retry-After` from the breaker) for the teacher's own `CircuitOpen` only) and `X-Should-Retry: false` where a retry cannot help. The daily quota's 429 is `insufficient_quota` / `daily_quota_exceeded` with `Retry-After` and `X-RateLimit-Reset-Requests` (`_duration`).
- A content part listed in `RATCHET_TEACHER_MODALITIES` sends the request to `Ratchet.teacher_only` (the pinned path: no student, nothing stored).

Demo controls are shared by every visitor: `day` and `reset` take `_demo_lock` without blocking (busy → 409), and `reset` has a 30 s cooldown (429). `break-next` and `student-outage` (the mock production endpoint down for 5 to 300 s, `MockFleet.student_outage`) only set fault state and write a `fault` event. Every demo control calls `_mock_only()` first (INV-8).

**Responses.** `_complete` builds the body from `Result`: `_envelope(...)` (`id`, `object`, `created`, `model`, `system_fingerprint`, `service_tier` = `openai_compat.SERVICE_TIER`), one choice per `Result.choices` (`index`, the message with `refusal: null` and `annotations: []`, `logprobs` from `_logprobs`: null unless the client sent `logprobs: true`, then `{content, refusal: null}` with `content` null when the router could not give them, and the choice's own `finish_reason`), `usage` from `openai_compat.usage_object(...)`, and the `ratchet` block with `usage_breakdown` and `degraded` (`Result.degraded`, null unless the student's below-threshold answer stood in for an unavailable teacher; then also the `X-Ratchet-Degraded` header). Every stream chunk starts with the same envelope; choices stream one after the other, each with its own role chunk, content chunks (`_stream_pieces`: a few tokens and their logprobs per chunk when asked, else a few words and `logprobs: null`) and finish chunk, and the role and finish chunks have `logprobs: null`; with `ChatRequest.include_usage` (`stream_options.include_usage`, read only when streaming) every chunk has `usage: null` and the stream ends with `{choices: [], usage, ratchet}` before `[DONE]`, else the `ratchet` block rides on the last finish chunk. Responses and chunks must keep passing the OpenAI SDK's `ChatCompletion` and `ChatCompletionChunk` models (`tests/test_openai_compat.py`).

Tasks over HTTP (FR-2.15, [ADR 0022](../docs/adr/0022-task-registry.md)). `Runtime.reset` builds `admin_keys` (`KeyRing(..., env="RATCHET_ADMIN_KEYS")`; a key that is also an API key stops startup) and runs `taskspec.install` under `rt.tasks_lock` (created once in `__init__`), writing a `task_skipped` event per stored task it skipped; `known_clients()` is the API key names, or None when keys are off. `_admin` (a `Depends`; Bearer or `X-API-Key`) returns the admin's name: 401 for a missing or wrong key, 403 for an API key, 403 `admin API disabled: set RATCHET_ADMIN_KEYS` in live mode without admin keys, `MOCK_ADMIN` in mock mode without them. Every management write takes it; reads (`GET /ratchet/tasks`, `/ratchet/tasks/{name}`) are open like `/ratchet/stats`. `PUT /ratchet/tasks/{name}` (`_put_task`, in a worker thread) parses with `taskspec.loads` (strict JSON) and `parse_spec`, answers 422 `{detail, errors}` for any spec problem, 403 (`_not_yours`) for a built-in or file task, 409 past `MAX_TASKS` or `MOCK_MAX_API_TASKS` (50) API tasks in mock mode, and under `tasks_lock` registers, then saves (`Ledger.save_task`; a failed save restores the registry), then writes `task_registered` or `task_changed` (old and new hash) with the admin's name. An identical spec is a 200 with `changed: false` and no event. `DELETE` removes API tasks only and keeps their examples (`task_deleted`). `POST /ratchet/tasks/validate` is a dry run (a document as startup reads a tasks file, `parse_document`; one spec as PUT would take it, an API or auto task's name included) with no registry, ledger or event change. Never store or log an admin key (INV-13). The dashboard's Task registry panel reads `_task_entry`'s keys and the write results (`tests/fixtures/tasks_keys.json`: add keys, never remove one) and writes through these same endpoints.

Committed training sets over HTTP (FR-16.4, [ADR 0027](../docs/adr/0027-committed-training-sets.md)). `POST /ratchet/versions/{vid}/proof?split=` (`version_proof`) and `GET /ratchet/versions/{vid}/heldout` (`version_heldout`) take `_admin` (a membership oracle for guessable texts; open in mock mode without admin keys) and are defined after it. `_committed` gives 404 for an unknown version or one whose BOM has no commitment (`bomdoc.commitment`); `_keyset(vid, split)` returns a `merkle.KeySet` from `rt.keysets` (an `OrderedDict` per runtime, `KEYSET_CACHE` = 8 trees, least recently used out, under `rt.keysets_lock`; an entry remembers its ledger, because a demo reset makes a new ledger whose version ids start again), built from `version_leaves` and cached only when it rebuilds the root and size the BOM signs; otherwise a 500 and one `integrity` event per (version, split) per runtime (`rt.integrity_reported`), so a proof that would fail against the signed root is never served. `GET /ratchet/demo/sample-example` is mock-only (`_mock_only()` first) and returns a committed example's prompt and stored conditions, never its answer. `live.write_boms(led, vid, trainer)` (called by `live.main` after a night that trained) writes the BOM to `boms/student-vN.json` and `adapters/<name>/ratchet_bom.json` (only for a name that is one folder: `ADAPTER_NAME`) and runs `RATCHET_SYNC_CMD` again; a failed sync makes `main` exit non-zero after the night's report.

Opt-outs and end users over HTTP (FR-13.1, FR-13.2, [ADR 0080](../docs/adr/0080-storage-opt-outs-and-pseudonymous-end-users.md)). `Runtime.reset` builds `rt.key_limits` (`auth.parse_key_limits` over the API key names) and `rt.end_users` (`privacy.end_users(ledger, RATCHET_END_USER_KEY)`; a mock reset makes a new in-memory key). `_request_meta(req, client, header)` runs right after validation: a bad `X-Ratchet-Store` is a 400; the end user's hash (`rt.end_users.hash(value, client)`); and its aliases (`rt.end_users.aliases`, so a no-train registration made with either `user` or `safety_identifier` holds); then `key` (the key's `store=0`) before `request` (`privacy.request_opts_out`). `Runtime.reset` also calls `privacy.check_no_train_scopes` after the keys are known. The raw `user` / `safety_identifier` goes no further. The response's `ratchet` block adds `stored` and `store_opt_out`, and a request's `metadata` is echoed (top level; in a stream, on the chunk with the `ratchet` block); never store it. `/ratchet/stats`' `privacy` adds `Ledger.opt_out_stats()` and the opt-outs in force. `POST` / `DELETE /v1/ratchet/no-train` (`_no_train_caller`: an admin key, else `_client`, so 401 with keys on; `_no_train_body`: strict, never quoting the value; `_no_train_scopes`: a client its own scope only, an admin a named client or every key plus the keyless scope) register and remove hashes; an admin's `POST` without `client` registers one hash in `privacy.EVERY_CLIENT`, and its `DELETE` without `client` also reaches every stored scope and `*`; a scope the every-client registration still covers reports `kept`; `created` and `status` are `null` for a keyless caller (no oracle on an open endpoint); `DELETE` without API keys needs an admin key in live mode; mock mode caps new registrations (`MOCK_MAX_NO_TRAIN`, `Ledger.no_train_add(limit=)`, 409); events carry counts and names, never a hash (`/ratchet/stats` is public).

Erasure, retention and export over HTTP (FR-13.3 to FR-13.5, [ADR 0081](../docs/adr/0081-retention-tombstones-erasure-and-export.md)). `Runtime.reset` sets `rt.retention` (`Settings.retention()`, so a bad window stops startup). `Runtime.tick` (after every chat request) calls `maybe_purge`, which in live mode with a window set starts `_purge` on a daemon thread at most every `RETENTION_INTERVAL_S` on `rt.clock` (`purge_lock`, `purge_thread`; a failure is a `purge_failed` event with the class only); keep it off the request's path. `POST /ratchet/admin/privacy/erase` (`admin_erase`, `_admin`; a dry run by default; an end user without `client` covers every key and the keyless scope) and `DELETE /v1/ratchet/examples` (`erase_examples`: `_no_train_caller`, `_no_train_body(raw, ERASE_EXTRA_KEYS)`, `_no_train_scopes`; not a dry run by default; a URL with `end_user` is a 400 that never echoes it) go through `privacy.erase` with `rt.end_users` and `rt.retention.erasure_shared`. `GET /ratchet/admin/export/{kind}` (`admin_export`, `_admin`) checks with `privacy.check_export` before streaming `privacy.export_lines`. `/ratchet/stats`' `privacy` adds the windows, `erasure_shared` and `Ledger.retention_stats()`; `/ratchet/bom` counts `purged_examples`.

Cost over HTTP (FR-15.2, FR-15.3, [ADR 0023](../docs/adr/0023-utilization-aware-cost-accounting.md)). `Runtime.reset` sets `rt.cost_policy` (`Settings.cost_policy()`, so a bad rate stops startup); `simulate_day` calls `cost.record_simulated_day` after its night. `GET /ratchet/cost?days=N` is public like `/ratchet/stats` (400 outside 1 to `MAX_COST_DAYS`); `POST /ratchet/cost/endpoint` takes `_admin`, refuses unknown keys and bad values with 400, redacts its `note`, caps API records in mock mode (`MOCK_MAX_API_INTERVALS`, 409 on `up` only) and goes through `cost.record_endpoint`. `/ratchet/stats` has `cost` (`cost.stats_block`) and `totals.cost_model` (`per_token`, naming the view every other figure uses, NFR-11). Replay over HTTP (FR-16.5, [ADR 0028](../docs/adr/0028-designed-propensity-replay.md)). `GET /ratchet/replay` (`replay_version`) and `GET /ratchet/replay/frontier` (`replay_frontier`) are public and read-only like `/ratchet/stats`. `_replay_version(request)` reads `version` from the raw query (`getlist`), so a second value, a list or a word is a 400 that says versions are never pooled; no `version` means the live one (400 without one), an unknown id 404. `_replay_days` bounds the days; bad thresholds, rates and targets are the replay module's `ValueError`s turned into 400s. The current threshold is `_replay_current(v)`: `Ratchet.threshold(v, model)` with the hosted fallback student's model in live mode without a student endpoint (mirroring `Runtime.reset`'s resolver; the resolver itself is not called, because the mock fleet's builds a student). Receipts over HTTP (FR-15.5, [ADR 0029](../docs/adr/0029-verified-savings-receipts.md)). `Runtime.reset` builds `rt.receipt_config` (`receipts.SealConfig.from_settings`, so a bad take rate or audit minimum stops startup; labelled `simulation (mock models)` in mock mode) and checks `checked_mock_reasoning_mean()` in every mode (the mock teacher is built with it in mock mode); `simulate_day` seals every earlier day after its night. `_complete` adds `request_id` to the `ratchet` block (and so to the last stream chunk) and the `X-Ratchet-Request-Id` header. `GET /ratchet/receipts`, `/ratchet/receipts/{period}`, `/{period}/proof/{request_id}` and `/{period}/leaves` take `_receipt_reader` (None for an admin key or the open mock demo, else the API client's name; 401 for a missing or unknown key when keys are on; 403 in live mode without any keys) and `_receipt_scope` (an API client reads only its own; `?client=` naming another is 403); `_receipt` seals lazily (409 for a day not over, 404 for no requests in scope). `_receipt_tree` caches (period, client) → ids and `LogTree` in `rt.receipt_trees` (`RECEIPT_TREE_CACHE` = 8, least recently used out, under `rt.receipts_lock`, remembering its ledger and receipt sha256) only when the rows rebuild the signed root; the proof reads its row again (`Ledger.receipt_row`) and checks it with `merkle.verify_inclusion` before serving. Any mismatch is `_receipt_integrity`: a 500 and one `integrity` event per (day, client) per runtime (`rt.receipt_integrity_reported`).

The admin API (FR-12.1, [ADR 0064](../docs/adr/0064-admin-api-compare-and-set-and-audit-trail.md)). ## Simulation host and upstream calls (`demo.py`, `upstream.py`)

FR-11.30, FR-11.31, ADR 0133. `gateway._demo_limit` is an app-level dependency after `_access`: it acts only in mock mode, with `RATCHET_DEMO_RPM` set, on non-GET calls to a route whose path starts `/ratchet/demo/` (so demo routes other items add are covered without editing it); it never runs before `_mock_only()` answers in live mode (INV-8, `test_demo_limits_never_answer_before_the_mode_check`). `demo.DemoJanitor` is module-level in `gateway.py` (`_janitor`, beside `_last_reset`) so it survives `rt.reset()`; the day and request caps are enforced when a visitor clicks `/ratchet/demo/day` (`_reset_locked`, inside the lock it already holds), the idle and request caps also by one daemon thread started on the first mock demo action, never at import, in live mode or with the defaults. Every `RATCHET_DEMO_*` value is checked by `Settings.demo_policy()`, the URLs by `config.public_url` through `Settings.links()`.

`upstream.UpstreamRecorder` is the only record of the last real upstream call per role. `OpenAICompatProvider(observe=...)` and `TavilySearch(observe=...)` are keyword-only and call the observer in one `finally`, suppressing every exception; a new upstream client takes `observe=` the same way and never passes it a message, a body, a URL, a header or a key. The recorder keeps a model id only when `MODEL_ID` matches in full (a response's `model` is upstream-controlled text), an exception's class name and a fixed reason, never `str(e)` or the upstream's own error code. It is created once in `Runtime.__init__` (it survives resets) and bound in live mode only; mock mode records nothing. `TOKEN_FACTORY_HOST` is tied to `config.py`'s default `RATCHET_TEACHER_BASE` by a test.

## Scout (`scout/`)

Multi-agent research demo ([docs/SCOUT.md](../docs/SCOUT.md)).

| File | What |
|---|---|
| `agents.py` | `Scout.run(question, emit, mode, run_id)`: planner → searcher → triage → reader → writer; emits `start`/`step`/`done` events. A search that raises `SearchUnavailable` or an `httpx.HTTPError` ends the searching (searcher `detail.unavailable`, writer `detail.search_unavailable`, `done.search`), never the run. `Call` (what an agent learns back), `http_caller` (any gateway over HTTP) |
| `prompts.py` | System prompts, message builders (`plan_messages`, `triage_messages`, `read_messages`, `write_messages`), `EXAMPLE_QUESTIONS` |
| `search.py` | `TavilySearch` (live; `depth`, `CREDITS`, `search_with_usage` with `include_usage`), `MockSearch` (simulated results from `sim/research.py`), `SearchUnavailable` (a fixed `UNAVAILABLE_REASONS` string) |
| `guard.py` | `Guard`: daily budget, daily run cap, per-IP hourly limit, the judges' reserve (pool rule, ADR 0120); with a ledger (live mode) each run writes a `scout_run` spend row (`usd` 0), `progress` updates it after each model call, and `restore()` rebuilds today's counters at startup; resets at 00:00 UTC |
| `judge.py` | `JudgeAccess` (the code's digest and an HMAC key derived from it; `check`, `issue`, `verify` the `ratchet_judge` cookie), `AttemptLimiter` |
| `credits.py` | `CreditMeter` (monthly Tavily credits, paced per UTC day, a judge share; `reserve` before a call, `settle` after it with `settlement`'s charge; `tavily` spend rows; `restore`; `exhaust` after a 432 or 433), `MeteredSearch` |
| `__main__.py` | CLI: `python -m ratchet.scout "<question>" --base-url ... [--api-key] [--max-results]`; prints `search unavailable (<reason>)` for a failed search |

Rules:

- **`prompts.py` is shared with the simulator.** `sim/research.py` builds its mock requests with the same message builders, and the mock teacher recognises the planner and writer by their system prompts. The mock models look a request up by its exact user text, so if you change a prompt or a builder, mock lookups still work only because both sides call the same function. Never build Scout messages anywhere else.
- **Threads.** Triage and reader calls run in a `ThreadPoolExecutor` (6 workers). `Scout.run` serialises `emit` with its own lock; the ledger has its lock. `Ratchet.rng` is shared across threads, so the order of random draws (canary pick, audits) is not reproducible inside a Scout run. Tests on Scout must not depend on exact routing.
- **Budget.** The gateway runs `_scout_precheck` (which calls `Guard.admit`) before every run and `Guard.add_spend` in a `finally` after it, summing each finished step's `cost_usd`. Keep both on every run path in live mode, judge runs included (INV-11). The gateway makes the `run_id` before admission and passes it to `admit`, `progress`, `add_spend` (with the outcome: `done`, `error`, `search_unavailable`) and `Scout.run`. In live mode `Runtime.reset` builds the guard with the ledger and calls `restore()` (and `CreditMeter.restore()`); mock mode attaches no ledger and no meter, so it writes no spend rows.
- **Spend rows.** Scout's `spend` rows (`scout_run`, `tavily`) keep `usd` 0: their model calls are already in `requests.cost_usd`, and receipts subtract `spend.usd`. Amounts go in `detail`, which never holds an IP, the question, a URL, an error message or the judge code (INV-12). Only `scout_run` rows are updated (`Ledger.update_spend_detail`, `MUTABLE_SPEND_KINDS`). Restoring reads spend rows only, never `requests`.
- **Judge access.** A run is a judge run only when the request's `ratchet_judge` cookie verifies (`_judge_session`); a code in a URL or a body is ignored. The code is handled like a key (INV-13 in spirit): digest and derived key only, constant-time comparison, never stored, logged, echoed or in an error message (`Settings.scout_policy()` never prints it). `POST /scout/judge` parses its body by hand so no validation error can echo it. No refusal message hints that a code exists.
- **Search unavailable.** Credits never refuse a run: `MeteredSearch` raises `SearchUnavailable` and Scout answers without (more) sources, labelled. A failure's reason is `describe_failure(e)` (class and status), never the message (an httpx message carries the URL). `Runtime.note_search` counts failures (not credit refusals) and writes `search_error` on the 1st, 10th, 100th and 1000th. `/scout/run` answers 200 for such a run; 502 stays for a model failure.
- `/scout/stream` always returns HTTP 200 and reports failures as an `error` event; `/scout/run` uses status codes (400/429/502/503).
