How it works

Your traffic trains your adapter

Ratchet sits between your app and the models. A small model, NVIDIA's open Nano base with an adapter you own, answers what it can. A large open model answers the rest, and those answers become tomorrow's training data.

  1. Your adapter answers first

    A small model tries each request: NVIDIA Nemotron 3 Nano 4B with a LoRA adapter you own, served by vLLM (built for a Nebius Serverless Endpoint; scripted and ready to run).

  2. The teacher answers when it is unsure

    If the student is not confident, the request goes to NVIDIA Nemotron 3 Ultra on Nebius Token Factory.

  3. Every teacher answer keeps its provenance

    The ledger records which teacher wrote it and the license that permits training on it.

  4. Night School trains and releases a new student

    Each night Night School fine-tunes a new student (built to run as a Nebius Serverless Job; scripted and ready to run) and tests it on a held-out golden set. It then goes out step by step: shadow, canary 10% → 50% → 100%, with automatic rollback.

Your bill falls as your adapter takes over, and Ratchet tells you when a GPU would cost more than it saves. You own the LoRA adapter and its signed training lineage; the Nano base stays under NVIDIA's Nemotron Open Model License.

Why license-clean

Learn only from teachers that allow it

Most distillation tools learn from whatever model you already call. With closed models, that can break their terms.

Not allowed

Closed models forbid it

  • OpenAI Business Terms §3.3(e) forbids using outputs to train competing models.
  • Anthropic Commercial Terms §D.4(a) says the same.
  • A tool that learns from GPT or Claude traffic puts its users at risk.
Allowed

Ratchet uses open teachers only

  • Nemotron 3 Ultra is under OpenMDW-1.1, which puts no restrictions on outputs.
  • Closed teachers are refused in code (ratchet/licenses.py), so a bad config fails at startup.
  • GET /ratchet/bom exports a model bill of materials: every training source, its license, and a SHA-256 fingerprint of the dataset.

Not legal advice. Check the licenses yourself.

Safe releases

Nothing ships unless it holds up

A new student has to earn traffic. It can lose it again at any stage.

Golden gate

Precision must reach 95% on a held-out golden set. The live model is re-scored on the same set the same night: champion vs challenger.

Shadow mode

The candidate runs silently on real traffic. When it disagrees with the live student, the teacher decides, and that ruling becomes training data.

Canary

Traffic moves 10% → 50% → 100%. Each step waits for enough teacher audits of what the candidate served.

Rollback

If the 95% Wilson upper bound of audited precision falls below 92%, traffic goes back to the previous version automatically.

Scout, a multi-agent demo

Ratchet on real agent traffic

Scout is a small team of research agents that answers a question from the web. Every agent is a plain OpenAI client pointed at Ratchet. Two agents make many narrow, repeated calls, so Ratchet moves them to the student. The open-ended planning and writing stay on Ultra.

Built on Nebius and NVIDIA

Open models on Nebius infrastructure

Every model in the loop is an NVIDIA Nemotron model. The teacher runs on Nebius Token Factory. Training and serving on Nebius are scripted and ready to run with make nebius-plan; the adapters so far were trained on a borrowed GPU.

Models and services Ratchet uses, by role
RoleModel or service
TeacherNemotron 3 Ultra on Nebius Token Factory
JudgeNemotron 3 Super on Token Factory (scores free-text answers)
FallbackNemotron 3 Nano 30B on Token Factory (used when your endpoint is stopped)
StudentNemotron 3 Nano 4B + LoRA with vLLM (built for a Nebius Serverless Endpoint; scripted, ready to run)
Night SchoolNebius Serverless Jobs (scripted, ready to run)
StorageNebius Object Storage (dataset and adapters; scripted, ready to run)
SearchTavily (Scout demo only)

Quick start

Run the whole loop locally

No API keys. About a minute. It uses mock models, so it shows how the loop behaves, not real model quality.

bashfrom the repo root
pip install -e ".[dev]"
python -m sim.simulate --days 10 \
    --requests 2000 --bad-deploy-version 3
RATCHET_MODE=mock uvicorn \
    ratchet.gateway:app --port 8000
pytest -q

The second command runs the full loop with a corrupted deploy. The third serves this page, the dashboard and Scout at http://localhost:8000. Live mode on Token Factory and Nebius is in the docs.
