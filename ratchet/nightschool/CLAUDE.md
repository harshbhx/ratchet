# CLAUDE.md: `ratchet/nightschool/`

One night = `orchestrate.run_night(ledger, trainer, evaluator, gate, base_model)`:

0. With `retention` (live mode: `Settings.retention()`), apply the retention windows first (`privacy.apply_retention`), so the night never reads expired text (FR-13.4).
0. Skip if an operator paused training (`ledger.flags().training_paused`, the admin API or CLI; ADR 0064), with a `skip` event, before anything else. Reading the switches also publishes the runtime task pins, so `dataset.rows` and `cascade_eval` leave a task pinned at runtime out (`excluded_pinned`) exactly as one its spec pins (INV-10).
1. Skip if a version is in `shadow` or `canary` (release in flight).
2. Build the dataset (`dataset.build`): train rows + golden rows + `manifest.json` with the bill of materials.
3. Skip if fewer than `min_new_examples` new train examples, or no golden rows. New = train rows now − `Ledger.train_rows_kept(task)` (for each version, its `train_examples` less its own training rows purged since; the largest), so a deletion never stops training and never starts it (FR-4.4: measured against the largest version's purges instead, it retrained every night once a later version trained on fewer rows); without purges it is v0.4's count, which the reference workloads pin (event text included).
4. Re-score the **live** version on the current golden set (champion vs challenger), recording `spec_hashes` (`orchestrate.spec_hashes`: each golden task's current `spec_hash`) in its eval. A night skipped for too few new examples still re-scores the live version when its recorded hashes are stale (`stale_tasks`; event `rescored`, or `rescore_failed` without failing the night), because `Ratchet.threshold` keeps a changed task on the teacher until then (FR-2.15).
5. `trainer.train(...)` → adapter name (e.g. `student-v4`).
6. `evaluator.evaluate(adapter, golden_rows)` → `{precision, coverage, threshold, golden_agreement, tasks, ..., certificate, frontier, per_task, test_vector}`, plus `spec_hashes`. `tasks` holds one calibration record per task (FR-14.1, [ADR 0040](../../docs/adr/0040-per-task-calibration.md)); a re-score of the live version (`rescore`) keeps the tasks the gate disabled on it disabled (`calibration.keep_disabled`). With a live version, `paired_evidence(recheck, result, live.id)` adds `paired` (the exact comparison of the two test vectors, `certificate.paired`, with `against`) when both evals carry a non-empty vector of the same length, **before** `update_eval` and the BOM, so the signed BOM carries the paired counts (FR-6.30).
7. The adapter's BOM (`bom.manifest(..., extra=bom_extra or None, redact_pii=redact_pii)`, schema v2, with the base model's license and the NOTICE text), then `gate.admit(vid)`. In live mode `python -m ratchet.live night` then writes the BOM and NOTICE.md into `RATCHET_DATA_DIR/adapters/<name>/` (`live.write_boms` and `publish_bom`) and runs `RATCHET_SYNC_CMD` again.

Later features add their steps at fixed places (ADR 0024): early-night checks (teacher freeze, erasures, the drift-advanced night) before the `min_new_examples` gate; set commitments right after `create_version`; paired evidence (built: certified precision) right after the candidate's eval, before `update_eval` and the BOM; and BOM sections (`bom.EXTRA_KEYS`) into the one `bom_extra` dict. `run_night(redact_pii=)` takes `Settings.redact_pii` (the gateway, the simulator and `python -m ratchet.live night` pass it) for the BOM's `redactor`.

## Interfaces

- `Trainer.train(train_rows, base_model, name) -> adapter_uri`: mock = `sim.mock_models.MockFleet`; live = `ratchet.live.NebiusTrainer` (Serverless Job + runtime LoRA load).
- `Evaluator.evaluate(adapter_uri, golden_rows) -> dict`: both implementations use `evaluate.cascade_eval` and sample the student with `confidence.STUDENT_SAMPLING`, the router's parameters, and with `GenPolicy.student` applied to each row's stored conditions (`row["params"]`, from `examples.params`; `LiveEvaluator(policy=)`, `MockFleet(policy=)`, both `Settings.gen_policy()` in the gateway, `live.main` and the simulator), so mock, live and production agree (FR-5.1; `test_production_and_both_evaluators_share_student_sampling`, `test_golden_eval_runs_under_production_conditions`). `cascade_eval`'s sampler is `sample(prompt, n, params)`. A row the student endpoint refuses for what it asks (`evaluate.REFUSED`: 400, 413, 422, such as a stored condition it cannot serve) scores as confidence 0 and wrong, as production would escalate it (INV-7), and `refused_n` counts them; any other failure (401, 403, 404, 5xx, a timeout) refuses every row and still stops the night. `LiveEvaluator`'s judge loop treats a refused candidate as not passing.

## The eval's keys (`cascade_eval`)

v0.4's keys keep their meaning: `golden_n`, `golden_agreement`, `threshold` (stored exactly since v0.5: the router serves at it, so production serves what the eval measured; a 4-decimal rounding could round up past the confidence it was calibrated at), `coverage`, `precision`, `test_n`, `refused_n`, `golden_invalid_refs`, `excluded_pinned` (only when some). Certified precision (FR-16.3, [ADR 0026](../../docs/adr/0026-certified-thresholds-and-a-paired-release-gate.md), `ratchet/certificate.py`) adds, all from the held-out (odd) rows at the same threshold:

- `certificate`: `{method: 'clopper-pearson', calibration, delta, target, threshold, served, errors, precision, lcb, certified}`, plus `ltt_trace` with `calibration='ltt'`. `lcb = stats.cp_lower(served - errors, served, delta)`; `certified = lcb >= target`. `precision` equals the eval's own. One exact test, because the odd half played no part in choosing the threshold (INV-6).
- `frontier`: one row per threshold of `stats.CERT_GRID` (highest first): `{threshold, coverage, served, errors, precision, lcb, delta}`, each `lcb` at `delta / len(CERT_GRID)` (Bonferroni), so all hold at once.
- `per_task`: `{task: {n_test, served, errors, coverage, precision, lcb}}` at the threshold, each at `delta`: a diagnostic, not multiplicity-corrected, never used for routing.
- `test_vector`: one letter per held-out row in golden order (`S` served and right, `W` served and wrong, `E` escalated); the input of `paired`. Its length is `test_n`.

`cascade_eval(..., calibration='point', cert_target=0.95, cert_delta=0.05)`: `calibration='ltt'` replaces the point rule with `stats.ltt_fixed_sequence(calib, CERT_GRID, cert_target, cert_delta)`, clamped the same way. `LiveEvaluator` and `MockFleet` take the same three and pass them through; the gateway, `live.main` and the simulator build them from `Settings.cert_policy()` (or the simulator's flags). Nothing here draws a random number, so the simulation does not move. `certificate.recheck(eval)` recomputes every number from the counts (`python -m ratchet.stats check`); keep the keys and their arithmetic in step with it.

## Rules

- `cascade_eval` calibrates the threshold on even-indexed golden rows and reports precision/coverage on odd-indexed rows. Do not grade on calibration data, and never build a certificate from calibration rows or a grid from observed confidences.
- Per task (`_task_record`, FR-14.1): the same global parity, so the global numbers never move and one task's record equals them. A task's threshold is calibrated to its `policy.target_precision`; with fewer than `min_task_n` (`RATCHET_MIN_TASK_GOLDEN`, passed as `LiveEvaluator(min_task_n=)` and `MockFleet(min_task_n=)`) calibration rows it is never below the global one; with no held-out row it is 1.01. `spec_hash` in each record is the spec it was scored under; `run_night` still writes `spec_hashes`, which does not depend on the evaluator.
- Thresholds are clamped to `[floor=0.5, 1.01]`; 1.01 means "serve nothing" (keeps JSON finite).
- Train from the base model on the cumulative dataset every night; do not stack adapters.
- `train.py` runs inside the GPU container only, and `main` is excluded from tests. Its arguments (`parse_args`), the row contract (`load_rows` reads what `NebiusTrainer` writes) and `manifest` (`ratchet_manifest.json`) are tested offline in `tests/test_live.py`; `write_metadata` (`ratchet_manifest.json` and NOTICE.md after `save_pretrained`) in `tests/test_licensing.py`. LoRA target modules for Nemotron-H must be confirmed on day 1 (`--targets`; `TARGETS_ATTENTION_MLP` is the fallback if vLLM refuses the Mamba projections). From the package it imports only `notices` (the training image has no httpx).
- `notices.py` (NFR-9, [ADR 0090](../../docs/adr/0090-licenses-travel-with-the-adapter.md)) imports only the standard library and `ratchet.licenses`, because `train.py` imports it in the container. `render(base_model, sources, version=)` is deterministic (sources sorted, cells on one line, pipes escaped) and is what `bom.manifest` signs (`notices`), so change its wording knowing that later BOMs carry the new text while stored ones keep theirs; `sources(rows)` builds the BOM's `sources` (with `license_origin`); `bom_notice(doc)` is the text a BOM signed (rendered from its fields only for a BOM without `notices`); `write_adapter_files(dir, doc)` writes `ratchet_bom.json` (`bom_bytes`, the same bytes as `data/boms/`) and that NOTICE, as exact bytes. Anything that writes a NOTICE from a BOM uses `bom_notice`, never `render`.
- **The student trains on the prompt it is served** (FR-8.42, [ADR 0145](../../docs/adr/0145-train-on-the-served-prompt.md)). The training file is TRL's conversational prompt-completion format: `dataset.write_training` (the one writer, used by `NebiusTrainer` and `dataset.build`) turns each row into `prompt` (its messages without the answer), `completion` (`[{"role": "assistant", "content": <stored teacher answer>}]`) and `chat_template_kwargs: {"enable_thinking": false}` (`dataset.TRAIN_TEMPLATE_KWARGS`), keeping the row's other keys. Why the kwarg: Nemotron 3 Nano's template turns thinking on unless told otherwise, so without it TRL renders the prompt ending in `<think>\n` while the endpoint (`--default-chat-template-kwargs '{"enable_thinking":false}'`) serves one ending in `<think></think>`, and TRL only logs a warning. `dataset.TRAIN_TEMPLATE_KWARGS`, `train.TEMPLATE_KWARGS` and `DEFAULT_TEMPLATE_KWARGS` in `deploy/student_endpoint.sh` must stay equal (`test_training_rows_carry_reasoning_off`); change all three together. `train.py` trains with `completion_only_loss=True` (never `assistant_only_loss`: the template has no `{% generation %}` markers), gives TRL only the three columns (`columns`), refuses a bad row before the model loads (`check_rows`: names the row and the field, never the text) and stops when the tokenizer's prompt is not a prefix of prompt + answer or differs from the served one (`check_prefix`, `TemplateMismatch`). `dataset.rows` leaves out train rows whose answer holds a literal `<think>` or `</think>` (the template renders those without the empty think block) and counts them (`skipped_think_tag` in `manifest.json` and the night's event); they stay golden. In-memory rows (`dataset.rows`, the golden eval, the set commitments, the BOM) and `golden.jsonl` keep `messages`. `python -m ratchet.importer` reads both formats.
- **The training image is pinned.** `deploy/Dockerfile.train` installs exactly the versions in `deploy/train-versions.txt` (the pip steps after torch read it as constraints) and fails its build when the Mamba kernels do not import; `train.LIBRARIES` names the same packages, and `train.py` writes `versions.json` beside the adapter before training (not in the BOM: `bom.EXTRA_KEYS` has no section for it, INV-14). Change a version in both files and in `train.LIBRARIES` if a package is added (`test_dockerfile_is_pinned`).
- `ratchet.live.NebiusTrainer` checks `RATCHET_STUDENT_BASE` before it syncs or starts the paid job; keep checks that can fail before any spend at the top.
- Rows carry `provenance` (teacher, license, hash, redactions, and `origin`: `examples.origin`, or `live` when the row did not record one; the BOM counts them in `training.origins`) and `params` (the stored conditions, or None). Keep `provenance` all the way to `ratchet_manifest.json` next to the adapter. `train.py` renders the messages only (TRL gets `prompt`, `completion` and `chat_template_kwargs`) and ignores every stored condition (`stop`, `response_format`, `tools`, `tool_choice`), so `dataset.rows` leaves a row with a `stop` out of training (the answer ends where the client's stop cut it, and the student would learn to stop there on the bare prompt); it still serves as a golden row. Change that rule only together with `train.py`.
- A train row whose answer is not valid under its task's current spec (`Task.valid`, FR-2.14) is left out and counted (`rows(..., counts=)`, `skipped_invalid` in `manifest.json`); golden rows stay, and `cascade_eval` skips a row whose reference is invalid before sampling the student and reports `golden_invalid_refs` (the halves alternate over the scored rows). The ledger keeps such rows, so loosening a spec brings them back.
- A row of a task that is pinned **now** is left out of both sets (`dataset.rows`, counted as `excluded_pinned` in `manifest.json`) and out of `cascade_eval` (`excluded_pinned` in the eval, only when there are some): INV-10 at read time, so pinning a task that already has data keeps it from the student and from the threshold. The ledger keeps the rows; unpinning brings them back. The registry decides (`tasks.get(name).pinned`), so Night School runs after `taskspec.install` (`live.main` calls it).
- Every variant of a prompt (the same task and messages under other conditions) shares its split (`Ledger._split`) and, for the frequent rule, its `seen` count: `dataset.rows` sums `seen` over the hash without conditions (`ledger.prompt_key`).
- A purged row (FR-13.3, FR-13.4: `purged_ts` set, no text) is in neither set, but its `seen` still counts toward its prompt's frequency (`prompt_key` reads its `prompt_hash`), so a purge never moves another variant of a frequent request back to golden (INV-3). `effective_split(row, seen)` and `counts_as_train(row, seen)` (effective train, a distillable teacher, no `stop`; no spec or pin check, so it errs toward counting: a purged row outside a version's set raises the next night's new-data count by one, once) are what a purge records as `purged_train`; `cascade_eval` only sees `dataset.rows`' output, so it never meets purged text.
- Human labels (FR-3.54, [ADR 0091](../../docs/adr/0091-human-labels-as-a-provenance-source.md)): rows with provenance `human` (a feedback correction or an attested import) are training rows like a teacher's; `rows` and `counts_as_train` read licenses with `licenses.lookup_source`, never `lookup`, which does not know `human`. `notices.sources` leaves them out (they are not teachers) and `notices.label_sources` lists them for the BOM's `label_sources` and NOTICE.md's Human labels section (absent, and the text unchanged, without any); `train.write_metadata` passes both.
- A golden-only row (`examples.golden_only`, FR-4.50) is golden whatever its split or `seen` count (`effective_split`), and `rows` holds out every variant of its prompt (the trainer sees only the messages); `counts_as_train` still counts such a variant by its own split, erring toward counting.
- Each rule above has a direct test in `tests/test_nightschool.py` (skip reasons, held-out golden rows, variants sharing a split and a count, stop rows held out of training, cumulative retraining from the base, held-out grading, refused rows, champion re-score, the certificate on the held-out half, Learn-then-Test's grid thresholds, the paired comparison signed with the BOM, the training rows' template arguments and the vendored template's prefix and serving parity, `train.py`'s loss and checks, the pinned image). Use `RecordingTrainer` and `RecordingEvaluator` from `tests/fakes.py` to test a new rule.
