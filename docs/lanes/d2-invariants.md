# Lane D2: proposed invariants

Lane D2 (config readiness, idempotency, off-path quality checks, fallback attribution) does not number invariants in CLAUDE.md while the lanes build in parallel, because the numbers would collide. Each proposal below names its text, the code that enforces it and the tests that prove it. The integrator gives each one the next free number when the lanes merge, adds it to CLAUDE.md's list and to `CODE` in `scripts/reqtrace.py`, and marks the tests with `@pytest.mark.req("INV-n")`.

## A bad configuration stops the gateway before anything opens, and every setting is known (OPS-CONFIG-READINESS, ADR 0070)

**Text.** `Runtime.__init__` runs `config.check` before `reset()` opens the ledger or builds a provider, and raises one `ConfigError` that lists every error, each naming its variable; a teacher, judge or fallback teacher the license registry refuses is one of them (INV-1), and the error is then also a `LicenseError`. No message of a `ConfigIssue`, a `config_warning` log line or `/readyz` holds a key's value or a URL. A rule a setting must follow goes in `Settings.validate` (or `ReleasePolicy.validate` across policy fields), never only in the code that reads the setting later, so `python -m ratchet.config check` exits 2 exactly when the gateway would not start. Every variable the package reads is in `config.KNOWN_ENV` (a deploy-only variable in `config.DEPLOY_ENV`), so the unknown-variable warning never calls a real setting unknown.

**Why.** A gateway that starts with a bad value fails later, per request, in ways that cost money (every teacher call refused for a missing key) or corrupt the evidence (a golden set that takes every example, a canary that can never collect audits). A gateway that stops one variable at a time costs a restart, and on the demo VM a rebuild, per typo.

**Enforcing code.** `ratchet/config.py`: `load`, `check`, `Settings.validate`, `_every_problem`, `defaults`, `ConfigError`, `ConfigLicenseError`, `KNOWN_ENV`, `DEPLOY_ENV`, `known_env`, `main`; `ratchet/release.py`: `ReleasePolicy.env_issues`, `ReleasePolicy.validate`; `ratchet/gateway.py`: `Runtime._check_config`; `scripts/reqtrace.py`: `rule_env_known`.

**Proving tests.** `tests/test_readiness.py`: `test_bad_setting_stops_startup_naming_the_variable` (31 cases; no ledger file exists after the refusal), `test_every_error_is_listed_at_once`, `test_readers_that_check_several_variables_report_each_one`, `test_config_check_and_startup_agree_on_every_variable` (every known variable, two bad values, both modes), `test_misspelled_variable_warns_with_a_suggestion_and_strict_mode_stops`, `test_config_check_cli_exit_codes`, `test_known_env_covers_every_variable_the_deploy_kit_sets`; `tests/test_traceability.py`: `test_every_env_var_documented`, `test_env_known_rule_catches_drift`.

## Liveness asks nothing; readiness probes are bounded and off the request path (OPS-CONFIG-READINESS, ADR 0070)

**Text.** `/healthz` and `/livez` are `async def` routes that read only the settings: never the ledger, an endpoint or a worker thread. `/readyz` runs every blocking probe on a `readiness.pool(...)` thread (the ledger's own, or the two endpoint threads), never on the event loop or AnyIO's request threads; a caller waits at most `PROBE_TIMEOUT_S` and a result is reused for `PROBE_TTL_S`, so a dependency sees at most one probe per TTL however often `/readyz` is asked; a probe never spends model tokens; a shared run is never cancelled. `/readyz` is 503 only when the ledger cannot be written or no teacher can answer; a dependency the gateway works around makes it `degraded`, still 200. Leaving `not_ready` never needs a request: a teacher breaker whose probe is due counts as a way through while its endpoint answers, and a busy ledger is `not_ready` only on two probes in a row.

**Why.** A liveness check that waits for threads or dependencies restarts working processes under load or turns an outage into a restart loop; a readiness check that runs on the request path, spends tokens or is not rate-bounded becomes a load on the very dependencies it watches.

**Enforcing code.** `ratchet/gateway.py`: `healthz`, `livez`, `readyz`; `ratchet/readiness.py`: `pool`, `POOLS`, `ProbeCache`, `Readiness`, `_way_through`, `BUSY`, `list_models`; `ratchet/ledger.py`: `Ledger.probe`.

**Proving tests.** `tests/test_readiness.py`: `test_healthz_answers_with_every_worker_thread_busy`, `test_hung_endpoints_never_make_the_ledger_look_unwritable`, `test_probe_cache_shares_runs_times_out_and_names_classes`, `test_readyz_503_when_the_ledger_cannot_be_written`, `test_readyz_reports_missing_adapters_and_queues_their_reload` (one `/models` call per TTL), `test_readyz_follows_the_teacher`, `test_readyz_recovers_from_an_open_teacher_breaker_without_traffic`.

## A client's retry is never a repeat, and a replayed answer never touches disk (OPS-IDEMPOTENCY, ADR 0071)

This one amends INV-3 rather than taking a new number: the integrator can append it to INV-3's text ("Golden examples are never trained on, except requests seen `FREQUENT` (3) or more times ...") and keep `INV-3`'s id.

**Text.** `seen` counts how often traffic asks a request, never how often one client retried it. `Ratchet._store_example` passes `count_seen=False` to `Ledger.add_example` when `RequestMeta.retry_count` (the gateway's reading of `x-stainless-retry-count`) is above 0, and the API key's name of the gateway request it serves as `sender` (None for internal traffic); the ledger bumps a duplicate's `seen` only when `count_seen` is true and its `seen_window` (RATCHET_SEEN_DEDUP_S) has not counted that (example, sender) within the window, deciding and writing under its lock. A response kept for an `Idempotency-Key` (`gateway._complete_idempotent`, `idem.IdemCache`) lives in process memory only, never in the ledger, a log line or a file (INV-12), is keyed by the API key's name, never the key (INV-13), and an error is never kept.

**Why.** Three retries of one escalated request used to reach `FREQUENT` and move a golden example into training, so a client that retries hard could drain the held-out set the release gate measures on. A kept answer holds request-derived text.

**Enforcing code.** `ratchet/ledger.py`: `Ledger.add_example`, `Ledger.seen_window`; `ratchet/idem.py`: `SeenWindow`, `IdemCache`, `retry_count`; `ratchet/router.py`: `Ratchet._store_example`, `Ratchet._sender`; `ratchet/gateway.py`: `chat`, `_complete_idempotent`, `_cacheable`, `_replay`.

**Proving tests.** `tests/test_idempotency.py`, marked `INV-3` already: `test_sdk_retries_do_not_drain_the_golden_set`, `test_the_same_request_minutes_later_still_counts`, `test_openai_sdk_retry_after_a_server_error_is_not_a_repeat`, `test_add_example_skips_retries_and_repeats_within_the_window`, `test_concurrent_retries_count_once`, `test_seen_window_counts_once_per_window_per_sender`; and for the rest: `test_internal_traffic_and_mock_mode_count_every_repeat`, `test_failed_first_request_releases_the_key`, `test_replay_log_line_says_it_replayed` (the client's key is never logged).
