# Day-1 checklist (Oct 19–20)

Run these before building more. Each one is a known risk from the stress test. Each has a fallback.

| # | Check | How | If it fails |
|---|---|---|---|
| 1 | Model IDs and prices on Token Factory | `python scripts/day1_check.py` | Update `ratchet/config.py` with the IDs it prints |
| 2 | Logprobs returned | same script | Confidence falls back to sample agreement (already supported) |
| 3 | JSON mode works | same script | Rely on prompt + `tasks.parse_json` (already tolerant) |
| 4 | Nano 4B LoRA trains on a Serverless Job (L40S): the smoke job (Oct 22) | build `deploy/Dockerfile.train` (the build itself fails when a pin conflicts or the Mamba kernels do not import), run `deploy/train_job.sh test` on ~200 rows; the job log shows no `TemplateMismatch` and no TRL warning "trained on a context that differs"; copy `adapters/test/versions.json` from the bucket and make `deploy/train-versions.txt` and the pins in `Dockerfile.train` match it (they are candidates until then) | Build from an NGC PyTorch base image with the same pins, or use the official Nebius Axolotl tutorial image (`axolotlai/axolotl:main-20260309-py3.11-cu128-2.9.1`) and record its `versions.json`; or use H100 for Nano 30B |

| 8 | Terms 5(f) of Token Factory ("competing service") | Ask Nebius DevRel in Discord | Position as "built on Nebius end to end" (it is) |
| 9 | Answers end with `finish_reason=stop` | `python scripts/day1_check.py` prints it per model | Only complete answers are stored (invariant 16): with `length`, raise the script's `max_tokens` to see whether reasoning eats the budget; see [RUNBOOK.md](RUNBOOK.md#teacher-answers-not-stored) |
| 10 | The teacher honours `n` and returns logprobs for its choices | one request with `"n": 2, "logprobs": true` to `RATCHET_TEACHER_MODEL` (curl), or through the gateway in live mode | With fewer choices than asked, clients get fewer on escalated requests (set `RATCHET_MAX_N=1` to refuse `n` > 1); if it refuses `logprobs`, remove `logprobs` and `top_logprobs` from `RATCHET_TEACHER_PARAMS` (teacher-served choices then carry `logprobs.content: null`) |
| 11 | The deploy scripts' `nebius` commands (Oct 22, before any GPU is paid for) | `DRY_RUN=1 bash deploy/train_job.sh test` and `DRY_RUN=1 bash deploy/student_endpoint.sh create` (nebius validates both requests with `--dry-run` and creates nothing); compare with `nebius ai job create --help` and `nebius ai endpoint create\|start\|stop --help`; paste the output of `nebius ai endpoint list --format json` (ids redacted) into `tests/fixtures/nebius_endpoint_list.json` and run `pytest -q tests/test_live.py tests/test_cost.py` | Fix the flag in `deploy/` and in its test (`test_train_job_uses_job_create`, `test_endpoint_args_carry_the_model_card_flags`). If the list has no `items`, `metadata.name` or `status.state`, set `RATCHET_ENDPOINT_ID` (start and stop then skip the lookup) and fix `LOOKUP_PY` in `student_endpoint.sh` |
| 12 | vLLM starts with the endpoint's arguments, and the student answers without reasoning | after `bash deploy/student_endpoint.sh create`: `bash deploy/student_endpoint.sh status` reaches `RUNNING`; a request without `chat_template_kwargs` returns no `<think>` (`--dry-run` cannot show how the container splits `--args`) | Endpoint stuck or in `ERROR` (see `nebius ai endpoint logs`): with a CUDA error, set `RATCHET_VLLM_IMAGE=vllm/vllm-openai:v0.18.0`; if the single-quoted JSON is refused, recreate it with `RATCHET_SERVE_TEMPLATE_KWARGS=` and rely on each request's `chat_template_kwargs` |

Stop the endpoint after each check (`bash deploy/student_endpoint.sh stop`; `start` brings the same one back): a stopped endpoint is not billed for compute or its own storage, but the mounted bucket still is.

After `scripts/day1_check.py` passes and the student endpoint is up, run `make live-smoke` (20 requests through the live gateway, about 5 control calls to Ultra, no nights: cents); it checks the key, the ledger and the gateway end to end before the real run ([RUNBOOK.md](RUNBOOK.md#live-measurement-run)).
| 11 | The teacher takes `response_format` json_schema (strict) and answers inside the schema | `python scripts/day1_check.py`: `[ok]`, or `[warn]` when it refuses the format (HTTP 400) or its answer does not match | Nothing to change: the gateway asks a teacher that refuses json_schema again with json_object and the schema in its system message, and repairs an answer that breaks the schema once (`RATCHET_SCHEMA_REPAIR`); neither kind of answer is stored unless it matches ([ADR 0042](adr/0042-auto-tasks-from-response-format-schemas.md)) |
| 11 | The embeddings model behind `/v1/embeddings` answers | `python scripts/day1_check.py` lists `RATCHET_EMBEDDINGS_MODEL` (default `Qwen/Qwen3-Embedding-8B`) and embeds two inputs at `RATCHET_EMBEDDINGS_BASE` (default: the teacher's endpoint); `off` skips it | Set `RATCHET_EMBEDDINGS_MODEL` to an embeddings model the script lists (and its price in `EMBEDDING_PRICES`), point `RATCHET_EMBEDDINGS_BASE` (and `RATCHET_EMBEDDINGS_KEY`) at another provider, or set `RATCHET_EMBEDDINGS_BASE=off` |

Budget guess: about $40–80 total, assuming L40S at about $1.55/hour (training runs under an hour, endpoint only while testing and recording, $20–30 of Ultra calls). The Builder Program gives $25 of Token Factory credit; ask in Discord for more.
