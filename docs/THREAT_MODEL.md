# Threat model: security and privacy

Scope: Ratchet v0.4.0 in live mode, made up of the gateway, the SQLite ledger, the Night School driver, the Nebius bucket, the vLLM endpoint, the Token Factory calls, and the Scout demo with Tavily search, as hosted on the demo VM ([DEPLOY_NEBIUS_VM.md](DEPLOY_NEBIUS_VM.md)). Mock mode handles only synthetic data. Each threat below says plainly what exists today and what is planned.

## Assets

| Asset | Where | Why it matters |
|---|---|---|
| Customer request text | `examples.messages`, `night/train.jsonl` in the bucket, adapters (memorised) | May contain personal or confidential data |
| Teacher outputs (training data) | `examples.completion`, bucket | Business value, and license provenance |
| Student adapters | Bucket `/data/adapters/*` | The product the customer owns |
| Ledger | `RATCHET_DB` | Provenance, version state, audit trail |
| API keys | `NEBIUS_API_KEY`, `RATCHET_STUDENT_KEY`, `TAVILY_API_KEY`, `RATCHET_ADMIN_TOKEN`, `RATCHET_API_KEYS`, `RATCHET_ADMIN_KEYS`, Nebius CLI and S3 credentials | Spend, data access, and (admin keys) what the gateway distils |
| BOM signing key | `RATCHET_BOM_SIGNING_KEY` | Whoever holds it can sign a bill of materials that claims any provenance |
| Demo budget | Scout's daily spend and Tavily credits | Real money and free-plan quota on a public URL |
| Release decisions | `versions.state` | Control which model answers users |

## Trust boundaries

```
[Client app] --(1)--> [Gateway + ledger host] --(2)--> [Token Factory]
                               |  \--(3)--> [vLLM Serverless Endpoint] <--(5)-- [Bucket]
                               \--(4) cron: ratchet.live --> [Serverless Job] --(5)--> [Bucket]
```

1. Client to gateway: optional API keys on `/v1/*` (`RATCHET_API_KEYS`, off by default). Plain HTTP unless you add a TLS proxy (Caddy on the demo VM).
2. Gateway to Token Factory: HTTPS with a bearer key.
3. Gateway to vLLM: HTTPS with a bearer token (`--auth token`), if the endpoint is configured that way.
4. Cron host to the Nebius CLI: local CLI credentials.
5. Job and endpoint to bucket: a Nebius-managed mount.
6. Gateway to Tavily (live Scout only): HTTPS with a bearer key. Search results are **untrusted web content** that flows into agent prompts.
7. On the demo VM, internet to Caddy: HTTPS. Caddy is the only thing that can reach the gateway's port 8000.

## Threats and mitigations

| # | Threat | Likelihood / impact | Present today | Planned |
|---|---|---|---|---|
| T1 | **Unauthenticated gateway use.** Anyone who can reach the port can spend teacher credits and read `/ratchet/stats` and `/ratchet/bom` | High / High | `RATCHET_API_KEYS` (v0.4): named keys required on `/v1/*` (401 otherwise), compared as SHA-256 digests with `hmac.compare_digest`; only the name is stored. `RATCHET_API_KEY_DAILY_REQUESTS` caps each key per UTC day (429). Off by default so the mock demo stays open. `/ratchet/stats`, `/ratchet/bom` and the dashboard stay public (client names, not keys, appear in stats) | Per-key token budgets, an auth-protected dashboard, key scopes |
| T2 | **Data poisoning via prompts.** An attacker sends crafted requests, the teacher answers, and those answers become training data. The attacker controls the prompt, not the label, but can skew the data distribution, or plant prompt-injection text that makes the teacher output harmful labels. Since v0.5 the client's generation parameters reach the serving teacher, so sampling fields (`logit_bias` of +100 forces a token) could also steer the label | Medium / High | The teacher writes every label; the student's own outputs are never training targets. A served answer written under a client's `logit_bias`, a non-zero penalty, a temperature above 1 or a vendor field is never stored (`GenParams.unstorable`, [ADR 0017](adr/0017-generation-parameters-by-role.md)); audits and arbitrations run at temperature 0 without those fields. A request for `n` choices stores only the teacher's choice 0, so a client cannot pick which of its choices becomes the label, and a request still adds or bumps at most one example ([ADR 0020](adr/0020-n-choices-and-token-logprobs.md)). The conditions that are stored (`stop`, `response_format`, `tools`, `tool_choice`) are recorded with the example, and every variant of a prompt shares its golden or train split. A fixed golden split and release gates catch broad quality drops. Per-tenant task names keep datasets separate | Per-tenant datasets and adapters, anomaly detection on new examples (bursts from one client, near-duplicates), a cap on examples per client, optional human review of the golden set |
| T3 | **Backdoor through rare triggers.** Poisoned data affects only inputs with a trigger phrase, so golden and audit precision stay high | Low / High | Audits sample live traffic at random, but a rare trigger may never be audited | Trigger scanning, higher audit rates on low-frequency patterns, provenance per client |
| T4 | **PII in logs and training data.** Escalated and audited requests are stored and trained on; adapters can memorise text | High / High | Pattern-based redaction before `add_example`, on by default (`RATCHET_REDACT_PII`, v0.4, [ADR 0009](adr/0009-pattern-based-pii-redaction.md)): emails, phones, cards, IBANs, Aadhaar, SSNs, PANs, IPs and API secrets become placeholders in both the request and the teacher answer: message content, `name`, an assistant's `refusal` and tool and function call arguments (v0.5). Message keys Ratchet does not use are dropped before storage, never stored raw. Names and addresses are **not** detected. The teacher still sees the original. Storage opt-outs (v0.5, FR-13.1, [ADR 0080](adr/0080-storage-opt-outs-and-pseudonymous-end-users.md)): per request (`store: false`, `X-Ratchet-Store: none`, `metadata.ratchet_store`), per API key (`store=0`), per task, per end user (no-train) and zero retention (`RATCHET_STORE_EXAMPLES=0`); none can be undone from a request, and opting someone back in needs a key. End users are kept only as a 16-hex HMAC scoped to the API key (FR-13.2), so the operator cannot link one person across clients or deployments; the generated key lives in the ledger, so a stolen database file lets an attacker test guessed identifiers against it unless `RATCHET_END_USER_KEY` is set outside the file. Erasure by client, end user, hash or stored text (v0.5, FR-13.3, [ADR 0081](adr/0081-retention-tombstones-erasure-and-export.md)) removes the text for good and tombstones its hash so it is never stored again; retention windows expire examples and fold old request rows (FR-13.4). **Unlearning is out of scope:** an adapter trained on erased text may still reproduce it. Ratchet lists those versions (`affected_versions`, exact when a version committed its training set, otherwise a timestamp approximation that errs toward listing) and trains the next one without the rows, but cannot edit an existing adapter; retiring it is the operator's decision. Backups made before an erasure still hold the text | NER-based detection (Presidio) for names and addresses, Token Factory zero-data-retention setting, excluding fields marked sensitive, signed erasure certificates and a forced retrain (FR-16.9) |
| T5 | **Key leakage** (`NEBIUS_API_KEY`, `RATCHET_STUDENT_KEY`) | Medium / High | Keys are read from the environment only. `.env` is in `.gitignore` | A secrets manager, separate keys for gateway and Night School, spend alerts |
| T6 | **License misuse.** Training on outputs from a teacher whose terms forbid it | Medium / High | `licenses.require_distillable()` refuses closed teachers (`gpt`, `o1`, `o3`, `o4`, `claude`, `gemini` prefixes) and unknown models at startup, the fallback teacher (`RATCHET_TEACHER_FALLBACK_MODEL`) included. Every example stores the teacher that wrote it and that teacher's license (a fallback teacher's answers only with `RATCHET_STORE_FALLBACK_TEACHER=1`, [ADR 0019](adr/0019-teacher-breaker-degraded-mode-and-fallback-teacher.md)). `dataset.rows()` drops non-distillable rows. `/ratchet/bom` exports provenance. Each adapter gets its own bill of materials at training time, signed with Ed25519 when `RATCHET_BOM_SIGNING_KEY` is set (v0.4, [ADR 0010](adr/0010-signed-adapter-bom.md)); `python -m ratchet.bom verify` detects any edit. The BOM also names the base model's license and carries the exact NOTICE.md written next to the weights; live Night School puts both in the adapter's bucket folder and `python -m ratchet.live export` bundles them (v0.5, [ADR 0090](adr/0090-licenses-travel-with-the-adapter.md)). Teachers added by configuration (`RATCHET_TEACHER_LICENSES`) must use an allowed open license and may not name a closed model family, so the environment cannot make a closed model a teacher; the BOM and NOTICE mark them `config` | A license registry kept up to date with model cards, and legal review per teacher. An operator can still claim a wrong open license for an open model in `RATCHET_TEACHER_LICENSES`; the `config` marks make such claims visible to whoever receives the adapter. *Not legal advice* |
| T7 | **Token Factory terms §5(f).** "Develop a product or service that competes with the Service" | Unknown / High | Written clarification requested from Token Factory support (Oct 19, 2026). Positioned as running on Nebius end to end | Act on Nebius's answer |
| T8 | **Student endpoint exposed** without a token, or with a weak one | Medium / Medium | `student_endpoint.sh` requires `RATCHET_STUDENT_KEY` and sets `--auth token` | Rotate keys, private networking |
| T9 | **Unauthorised runtime LoRA loading.** `VLLM_ALLOW_RUNTIME_LORA_UPDATING=True` lets any caller with the endpoint token load adapters from paths the server can read | Medium / High | Protected only by the endpoint token | Separate admin path or proxy, an allow-list of adapter paths |
| T10 | **Release state tampering.** Writing to the ledger changes which model serves users | Low / High | File permissions on the host | Signed state changes, an audit table of manual changes |
| T11 | **Denial of wallet.** Long prompts, or many escalations to the teacher | Medium / Medium | Request limits on the gateway (v0.5, [ADR 0012](adr/0012-openai-request-validation-and-error-envelope.md)), checked before any model call: body size (`RATCHET_MAX_BODY_BYTES`, 2 MiB, 413, also for chunked bodies), messages per request (`RATCHET_MAX_MESSAGES`, 256) and characters of input (`RATCHET_MAX_INPUT_CHARS`, 120,000, 400 `context_length_exceeded`), counting every string forwarded to the teacher (content, `name`, tool call arguments and ids); message keys Ratchet does not use are dropped rather than forwarded, and non-text parts (only with `RATCHET_TEACHER_MODALITIES`) are bounded by the body size alone; `n` is at most `RATCHET_MAX_N` (4; v0.5, [ADR 0020](adr/0020-n-choices-and-token-logprobs.md)): each choice past `RATCHET_SAMPLES` costs one more student sample, and an escalation asks the teacher for `n` answers, so the cap bounds what one request can multiply; `RATCHET_MAX_N=1` refuses `n` above 1 as before. A refused request costs nothing and uses no quota. Per-key daily request quotas (`RATCHET_API_KEY_DAILY_REQUESTS`, T1) and Token Factory rate limits. Teacher retries are bounded (v0.5, [ADR 0014](adr/0014-upstream-failure-semantics.md)): two at most within 180 s, a read timeout (whose tokens may be billed) once, never a 4xx the same request would get again; and `X-Should-Retry: false` on errors a retry cannot fix stops OpenAI SDKs from resending a request whose student samples would run again. Output is capped per call (v0.5, [ADR 0017](adr/0017-generation-parameters-by-role.md)): every teacher call carries `max_tokens` of at most `RATCHET_TEACHER_MAX_TOKENS` (8,192) and every student call at most `RATCHET_STUDENT_MAX_TOKENS` (1,024), whatever the client asks (a larger value is capped, none means the cap); the reasoning headroom stays under the teacher's cap. Allowlists (`RATCHET_TEACHER_PARAMS`, `RATCHET_STUDENT_PARAMS`) decide which client fields reach each model, so a client cannot raise `n` or pick the model, and unknown vendor fields go nowhere unless named | Per-tenant budgets, escalation-rate alerts |
| T12 | **Task registry abuse.** Every new `X-Ratchet-Task` value adding an entry to the in-memory registry; a client inventing task names whose answers become training data; a client using another tenant's task (its labels, its spend); a client turning distillation on or off for a task others share; anyone redefining a task's rules | Low / Medium | Fixed in v0.1.1: unknown names get a temporary task that is not registered; names must match `[A-Za-z0-9_.-]{1,64}`. Since v0.5 ([ADR 0022](adr/0022-task-registry.md)): tasks are registered only by an operator (the code, `RATCHET_TASKS_FILE`, or the admin API behind `RATCHET_ADMIN_KEYS`, which must differ from every API key; off in live mode without them; 401 or 403 otherwise; the admin's name, never the key, is stored and logged), at most 500 in all (50 API tasks in mock mode); `RATCHET_UNKNOWN_TASKS=teacher` or `reject` stops unregistered names from becoming training data (and answers a header that is not a valid name with a 400 instead of `default`); a task's `clients` allow-list answers 403 to any other key, and to a request without one, before any quota or model call; only an operator's spec can pin or unpin a task, never a header, metadata, `model` or `response_format`; a spec is checked whole (unknown keys refused, every value range-checked, bounded nesting, strict JSON) before it is registered, and fixture paths cannot leave `RATCHET_FIXTURES_DIR` | Per-tenant registries; an audit table of admin changes beyond the event log |
| T13 | **Judge manipulation.** Candidate output contains instructions to the judge | Low / Medium | The judge is used only for free-text tasks and does not gate releases in v0.1. Labels are compared exactly | Keep exact-match fields as the gate; delimit candidate text in the judge prompt |
| T14 | **Dashboard XSS** from event or license text | Low / Medium | `dashboard.html` escapes all dynamic text with `esc()` and opens links with `rel="noopener"` | Content-Security-Policy header |
| T15 | **Prompt injection from web search results into Scout's agents.** A page Tavily returns contains text like "ignore your instructions and…", aimed at the triage, reader or writer agent | Medium / Medium | Results are only data: titles, URLs and snippets go into a JSON user message, never into a system prompt. Triage and reader outputs are labels (`relevant`, `source_type`, `answers_question`, `fact_type`) plus one short free-text field that is ignored for agreement and training comparison. The writer is pinned to the teacher, so injected text cannot steer which model answers it. No agent runs tools or code from model output: the only tool is search, called with the planner's queries. The Scout page escapes all text and only links `http(s)` URLs, opened with `rel="noopener noreferrer"` | Delimit untrusted text more strictly in prompts; cap excerpt length further; flag answers that cite a source the reader marked as not answering |
| T16 | **Poisoned training data through Scout.** Injected search text makes the teacher write wrong labels, which become training data for `source-triage` and `page-read` | Low / Medium | Only label fields are compared; the release gate and audits catch broad quality drops (see T2). Pinned planner and writer answers are never stored | Same as T2 |
| T17 | **Budget exhaustion on the public demo.** Someone runs Scout over and over to spend Token Factory credit and Tavily credits | High / Medium | Budget guard in live mode: `RATCHET_SCOUT_DAILY_BUDGET_USD` (default $3.00 per UTC day), `RATCHET_SCOUT_MAX_RUNS_PER_DAY` (default 30, about 90 Tavily credits), `RATCHET_SCOUT_RUNS_PER_HOUR` per IP (default 6). Spend is counted per step, so failed runs count. Questions are capped at 300 characters. Worst case per day is the cap plus the runs in progress when it is reached. Many IPs can still use up the daily budget early (a denial of service for others, not extra cost) | Per-user quotas behind a login; CAPTCHA |
| T18 | **Shared mock demo controls.** Any visitor can run days, break the next deploy or reset the shared simulation, or flood the controls | Medium / Low | Mock mode only, no real cost. `day` and `reset` run one at a time (409 when busy); `reset` has a 30 s cooldown (429); `requests` is clamped to 100–5,000. `RATCHET_API_GUARD=guarded` blocks `/ratchet/demo/*` at Caddy | Per-visitor simulations |
| T19 | **Public paid API on the demo URL.** `/v1/chat/completions` is open on the VM, and the Scout budget guard does not cover it | High / High in live mode | Opt-in Caddy guard: `RATCHET_API_GUARD=guarded` returns 403 on `/v1/*` and `/ratchet/demo/*` without `X-Ratchet-Admin-Token`; a token shorter than 32 characters blocks everyone; Caddy strips the header before the gateway. Gateway API keys (`RATCHET_API_KEYS`, see T1) work with or without it. The guide says to turn one of them on before switching to live mode. Both are **off by default** | Per-key spend caps |
| T20 | **Spoofed client IP** to dodge the per-IP limit | Low / Low | On the VM, Caddy overwrites `X-Forwarded-For` and uvicorn trusts it only because port 8000 is not published. `RATCHET_TRUST_PROXY` is off by default | Keep port 8000 private |
| T21 | **Stolen BOM signing key.** Someone signs a BOM that claims clean provenance for an adapter trained on anything | Low / High | The key is only read from the environment and never logged or returned; `/ratchet/bom/public-key` returns the public half only. Each BOM names its key id, so a rotated key can be listed as revoked | Keep the key in a secrets manager; sign on a separate machine instead of the gateway |
| T22 | **Misleading cost records.** Someone records the student endpoint as down while it runs (or up while it is not), so the cost report hides or invents GPU cost and recommends the wrong thing | Low / Medium | `POST /ratchet/cost/endpoint` needs an admin key (`RATCHET_ADMIN_KEYS`; off in live mode without them); every change writes an `endpoint` event with its source and the admin's name; the API and CLI open and close intervals and never delete one; the report labels prices unverified and the runbook reconciles endpoint hours with the Nebius bill weekly ([ADR 0023](adr/0023-utilization-aware-cost-accounting.md)) | Read uptime from the Nebius API instead of trusting records |

## Privacy notes

- Mock mode and the simulation use only synthetic tickets (`sim/tickets.py`) and simulated search results on `example.org` (`sim/research.py`). The repo contains no real customer data.
- In live mode, Scout sends its search queries (written by the planner from the user's question) to Tavily under Tavily's terms. Do not type personal data into the public demo.
- In live mode, requests that reach the teacher are also processed by Nebius under its terms. Token Factory stores inputs and outputs for speculative decoding unless you opt out (ToS §7). Opt out for customer data.
- Stored examples have identifiers replaced by placeholders (`RATCHET_REDACT_PII=1`, the default). `/ratchet/redact` shows what would be stored for any text and stores nothing. The redactor does not find names or street addresses.
- Requests the student serves without an audit are not stored as examples, but their metadata (task, confidence, cost) is logged in `requests`. Message text is not stored in `requests`.
- A client or an end user can keep requests out of the training set (`store: false`, a no-train registration; [API.md](API.md#end-users-and-storage)), and an operator can turn storage off entirely (`RATCHET_STORE_EXAMPLES=0`). The `user` and `safety_identifier` fields are never stored or forwarded: only a keyed hash is.
- What was stored can be erased (an end user's examples by the client itself, `DELETE /v1/ratchet/examples`; anything by an operator, `POST /ratchet/admin/privacy/erase` or `python -m ratchet.admin erase`), expires with `RATCHET_EXAMPLE_RETENTION_DAYS`, and can be exported with its provenance. An erasure record holds hashes, counts and a redacted reason, never the text or a raw end user; erased hashes stay as tombstones, so anyone holding a candidate text can check whether it was erased. Adapters already trained on erased text are reported, not changed ([API.md](API.md#erasure-and-export)).
