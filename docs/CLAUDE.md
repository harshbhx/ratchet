# CLAUDE.md: `docs/`

Index: [docs/README.md](README.md). Product docs (PRD, business, competitive analysis, roadmap, Devpost submission, research summary, glossary) and technical docs (architecture, API, configuration, Scout, deployment, demo VM, runbook, threat model, testing, ADRs).

Rules:

- Docs must match the code. When you change behaviour, update the doc that describes it in the same commit (API.md for endpoints, CONFIGURATION.md for env vars, ARCHITECTURE.md for flow/states, RUNBOOK.md for operations, SCOUT.md for Scout's agents and event contract, DEPLOY_NEBIUS_VM.md for `deploy/vm/`).
- Plain English, short sentences, no hype. Numbers need units and a source link or a "simulation"/"estimate" label.
- Facts about third parties (prices, model IDs, competitor status, terms) carry a source link and an as-of date. Re-check before the Devpost submission.
- Claim only what is true (NFR-70, `tests/test_docs_claims.py`). The customer owns the LoRA adapter and its signed training lineage, not the base model's weights (Nemotron 3 Nano stays under NVIDIA's Nemotron Open Model License). Savings are never promised below break-even. Name prior art instead of claiming uniqueness. A fact taken from the research notes without a fresh check says "(research notes, <date>)"; a claim nobody can source is left out.
- `HACKATHON_SUBMISSION.md` has `[LIVE NUMBER]` placeholders. Fill them only with results from a real live run.
- `REQUIREMENTS.md` is generated by `scripts/reqtrace.py` (`make trace`); never edit it by hand. PRD statuses must follow the grammar in PRD §6, requirement ids never change or get reused, and a new requirement goes into the section that matches its number (`FR-12.x` in §6.12). `make lint` fails on anything else ([TESTING.md](TESTING.md#traceability)).
- New architectural decisions get an ADR (`adr/NNNN-title.md`: Status, Context, Decision, Consequences, Alternatives) and a line in `adr/README.md`.
