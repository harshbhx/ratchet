# ADR 0070: Configuration checks that list every bad variable, a config check CLI, liveness apart from readiness, and `/readyz` with bounded dependency probes

- Status: Accepted
- Date: 2026-10-21

## Context

A code reading found that a misconfigured gateway either failed badly or did not fail at all:

- `RATCHET_AUDIT_RATE=5%` stopped the import with one `ValueError`; an operator with three typos found them one restart at a time.
- `RATCHET_AUDIT_RATE=5`, `RATCHET_SAMPLES=0` and `RATCHET_GOLDEN_FRACTION=1` were accepted: an audit on every answer, a cascade without samples, a training set held out entirely.
- `RATCHET_MODE` other than `mock` (an empty value, `Live`, `prod`) started live mode.
- Live mode started with an empty `NEBIUS_API_KEY`: every teacher call then failed with a 401.
- A teacher, judge or fallback model missing from `DEFAULT_PRICES` was priced as another model, silently.
- A misspelled variable (`RATCHET_AUDIT_RAT`) did nothing, silently.
- Release policy values that disagree (a rollback floor above the golden gate's bar, `RATCHET_MIN_AUDITS=0`) were accepted, because each field is checked alone.
- `/healthz` was a sync route, so it waited for a worker thread: with the thread pool full of slow chat requests a Docker health check could restart a process that was working.
- Nothing told a load balancer whether a gateway could serve: the ledger could be read-only, the teacher's breaker open, or the student endpoint restarted without its adapters, and `/healthz` still said `ok`.

## Decision

- **Every problem at once, before anything opens.** `config.load()` reads `Settings` with the helpers `_int`, `_float`, `_float_or_none` and `_bool` collecting a value that does not parse as a `ConfigIssue(level, var, message)` instead of raising (the setting keeps its default meanwhile). `Settings.validate()` returns every other problem: ranges (`RATCHET_AUDIT_RATE` and `RATCHET_CONFIDENCE_THRESHOLD` from 0 to 1, `RATCHET_SAMPLES` from 1 to 16, `RATCHET_GOLDEN_FRACTION` above 0 and at most 0.5, counts 0 or more), `RATCHET_MODE`, http(s) base URLs, the license registry for the teacher, judge and fallback teacher (INV-1), each setting's own reader (timeouts, breakers, allowlists, cost, log and access settings, reserved settings), the key rings, and in live mode the teacher key, the API keys and a writable `RATCHET_DB`. In live mode `ReleasePolicy.validate()` adds the rules across fields: 0 < `live_floor` <= `min_precision` <= 1, `min_audits` and `min_shadow` at least 1, `tolerance` at most 0.2. Building a `ReleasePolicy` does not run them, so tests and simulations keep any value. `config.check()` runs all three; `Runtime.__init__` runs it before `reset()` opens the ledger and raises one `ConfigError` listing every error, each naming its variable.
- **`ConfigError` stays compatible.** It is a `ValueError` (code that caught the old errors still does), built from one bad value as `ConfigError(var, value, expected)` or from a list with `ConfigError.of(issues)`. When a teacher is refused it is a `ConfigLicenseError`, also a `LicenseError`, so `except LicenseError` keeps working. Outside `load()`, reading a bad variable still raises at once, naming it.
- **Warnings start the gateway; strict mode stops it.** Warnings: an unknown `RATCHET_*` variable with the closest known name (`difflib`), a model without a price, a student endpoint without a token, an audit rate under 1% in live mode (a canary may never collect `RATCHET_MIN_AUDITS` audits), a mock-only variable set in live mode, a 0/1 switch spelled otherwise (`true` reads as off). They are kept in `Runtime.config_warnings`, logged once as `config_warning` lines naming the variable, never the value, and counted in `/readyz`. `RATCHET_STRICT_CONFIG=1` makes them fatal.
- **Known variables are a list the build checks.** `config.KNOWN_ENV` holds every variable the package reads (ReleasePolicy's `RATCHET_<FIELD>` are derived from the dataclass); `config.DEPLOY_ENV` holds the ones only the deploy scripts and the demo VM read, because Docker Compose hands the VM's whole `.env` to the gateway. `scripts/reqtrace.py` fails when code reads a variable missing from `KNOWN_ENV` or `KNOWN_ENV` lists one nothing reads, so the unknown-variable warning can never call a real setting unknown.
- **A CLI with exit codes.** `python -m ratchet.config check [--json]` runs the gateway's check in its own process, plus the tasks file (the gateway reports a bad one itself, as a `SpecError`, when it builds the registry), opens nothing, and exits 0 when clean, 1 with warnings only and 2 with errors (or warnings under strict). `deploy/vm/update.sh` builds the new image, runs the check in it with the VM's `.env` and stops on exit 2 before it replaces the running container; CI runs it on the defaults.
- **A key-less teacher on another host is a warning.** An empty `NEBIUS_API_KEY` is an error only when the teacher base is on `nebius.com`, where every call needs it; a self-hosted OpenAI-compatible teacher may run without authentication.
- **Liveness is a coroutine that asks nothing.** `/healthz` and its alias `/livez` are `async def` routes that read only the settings, so they answer while every worker thread is busy, and a restart policy on them never follows a dependency.
- **Readiness asks the dependencies, within bounds.** `GET /readyz` (public, `async def`) reports `ledger` (`Ledger.probe`: `SELECT 1`, then `BEGIN IMMEDIATE`, a write of the header's `user_version` to its own value, `ROLLBACK`; the write is what a read-only file or a `query_only` connection refuses, where `BEGIN IMMEDIATE` alone succeeds; it waits at most 2 s for the ledger's lock and SQLite's), and in live mode `teacher` (its breakers and a `GET {teacher_base}/models`, which spends no tokens) and `student` (its breakers and, with an endpoint, a `GET {student_base}/models` that must list the adapter of every live, canary and shadow version; each missing one is reported and handed to the `AdapterReloader`, the queue a vLLM 404 already uses). It answers 200 `ready`, 200 `degraded` while requests can still be answered (the student down, a teacher model list that fails, a missing adapter, the teacher's breaker open with a closed fallback teacher or a student standing in under `RATCHET_ON_TEACHER_FAILURE=serve_student`), and 503 `not_ready` when the ledger cannot be written or no teacher can answer (its breaker open with no stand-in, or a 401/403 on its model list: the key is refused). Mock mode checks the ledger only. The body carries the config warning count and operational flags (`scout_budget_exhausted`) that never change the status.
- **Probes on their own threads, cached.** The two HTTP probes run on a process-wide pool of two threads and the ledger probe on a thread of its own, never AnyIO's request threads. `ProbeCache` keeps each result for 15 s and shares one run between every caller that arrives while it runs; a caller waits at most 2 s and reports a slower probe as `timeout` (it uses `asyncio.wait`, never a cancel, so a run other callers share is never cut short), and the run's result is kept when it ends. However often a load balancer asks, each dependency sees one probe per 15 s. A probe's failure is named by a short code or the exception's class, never its message (an httpx message holds the URL). A `/readyz` 503 writes no `failures` row.

## Alternatives considered

- **Raise at the first bad variable, as before.** One restart per typo; on the demo VM each restart is a rebuild. Collecting costs a context variable during `load()`.
- **Validate in `Settings.__post_init__`.** Every `Settings(...)` in the tests, the simulator and Night School would then have to be a valid live configuration; the simulations deliberately use values the gateway refuses (an audit rate of 0, small golden sets). The gateway's startup and the CLI are the places where a value meets an operator.
- **Make every unknown `RATCHET_*` variable an error.** The VM's `.env` holds variables for Caddy and the deploy scripts, and a later version may drop a setting an old `.env` still sets; a warning with a suggestion says what is wrong without taking the demo down, and strict mode is there for operators who want the error.
- **One probe pool for everything (the spec's two threads).** With a hung teacher and a hung student holding both threads, the ledger's probe would queue past the caller's 2 s and a working gateway would answer 503. The ledger gets a thread of its own; the HTTP pool keeps two.
- **Probe the teacher with a one-token completion.** It proves more, but it costs tokens on every probe and counts against the teacher's rate limits; `/models` proves the endpoint and the key, and the breaker already reflects real calls.
- **Restart on readiness.** A teacher outage would turn into a restart loop of every instance. Docker's health check stays on `/healthz`; `/readyz` is for routing.

## Consequences

- A misconfigured gateway stops with one message that names every bad variable, before it touches the ledger or an endpoint; `python -m ratchet.config check` gives the same verdict without starting it, and the VM's update script refuses to replace a running gateway with one that would not start.
- Some configurations that started before now stop: an empty or misspelled `RATCHET_MODE`, live mode with an empty Token Factory key, out-of-range values, and live release policies whose rules disagree. Each message says what to set.
- A variable a change starts reading must go in `config.KNOWN_ENV` (and docs/CONFIGURATION.md); the traceability check fails until it does.
- Load balancers get a 503 when the ledger cannot be written or no teacher can answer, and a 200 with the reason when the gateway works around a failure. A routed adapter the student endpoint lost is reloaded within a probe's TTL even without traffic.
- `/readyz` is public and says which dependency is down (states and statuses, no URLs or keys); the operational flags registry (`readiness.FLAGS`) is where later switches (a gateway budget, frozen releases, paused training) register.
