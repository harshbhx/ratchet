# ADR 0019: When the teacher is down: a teacher breaker, an opt-in degraded mode and an opt-in licensed fallback teacher

- Status: Accepted
- Date: 2026-10-20

## Context

ADR 0014 made each teacher call retry within a deadline (180 s by default) and ADR 0015 stopped a dead student endpoint from costing every request its timeout. The teacher had no such guard:

- **A hung Token Factory holds every request that needs it for the whole deadline.** Each escalation, cold start and pinned request waits up to 180 s (three attempts) before its 502 or 504, and each holds a worker thread from the default pool while it waits, so a burst during an outage can take every thread and stall requests the student could have answered.
- **The only answer to a teacher outage was an error.** An escalated request has a student answer in hand (below its threshold, so not served), and many deployments would rather serve that, marked, than fail. Others have a second licensed model on Token Factory that could answer instead. Neither was possible.
- **Provenance was written with the configured teacher's license, whatever wrote the answer.** `_store_example` used `settings.teacher_model` for every example; a second teacher would have been recorded under the first one's license, which breaks the point of the BOM (ADR 0010).

## Decision

- **One breaker per teacher.** `Ratchet._teacher_complete(messages, gen, fallback=False)` wraps every teacher call (escalation, cold start, pinned, teacher-only, audit, arbitration) in a `resilience.Breaker`: `teacher` for the primary, `fallback_teacher` for the fallback, made in `Ratchet.__init__` so `health()["breakers"]` shows them from the start. The provider's retries come first: one failed call, after its retries, is one failure. `resilience.endpoint_down` decides what counts, as for the student: a timeout, no connection, an unreadable or 5xx answer, 408 or 429 count; a 400 such as `context_length_exceeded`, a 401 and a tool-call answer are the teacher answering; an error that is not an HTTP failure counts neither way. `RATCHET_TEACHER_BREAKER_FAILURES` (5; 0 turns it off) and `RATCHET_TEACHER_BREAKER_COOLDOWN_S` (30), with the student breaker's doubling waits up to 300 s; transitions write `circuit` events (`teacher: closed->open after 5 failures (UpstreamError 503)`).
- **An open breaker is a fast 503.** While open, the call raises `CircuitOpen` (503 `teacher_circuit_open`) without calling, with `retry_after` set to the time until the next probe (`Breaker.retry_in()`). The gateway maps it to **503** `teacher_circuit_open` with that wait as `Retry-After`, clamped to 1 to 60 s as for the teacher's other waits (OpenAI SDKs ignore a longer one). No `X-Should-Retry: false`: a retry after the wait can succeed.
- **Optional calls are skipped, not counted again.** An audit or arbitration refused by the open breaker is skipped as a failure would be (the student's answer is served, the shadow disagreement stays unarbitrated, ADR 0013), but it is not another `audit_error` or `shadow_error`: the breaker already counted, as for the student (ADR 0015).
- **Opt-in degraded mode: `RATCHET_ON_TEACHER_FAILURE=serve_student`** (default `error`; empty means the default; anything else stops startup). When the escalation's teacher call fails because the teacher is unavailable (`resilience.teacher_unavailable`: any HTTP failure or an open breaker, except a 400, 413 or 422 about the request and a tool-call answer, which the client must act on), and the student answered this request with at least one valid sample (`Scored.valid`), that answer is served: route `degraded`, `served_by` `student`, `audited` 0, `escalated` 1, nothing stored, the response's `ratchet.degraded` set to `teacher_unavailable` and the header `X-Ratchet-Degraded: teacher_unavailable`. A throttled `degraded` event names the failure (`ticket-triage: UpstreamError 503`). Pinned and teacher-only requests never degrade (they have no student answer), nor does a request with `tools` (the student never saw them), a cold start, or a request whose student call failed or was skipped.
- **Opt-in fallback teacher: `RATCHET_TEACHER_FALLBACK_MODEL`**, at `RATCHET_TEACHER_FALLBACK_BASE` (empty: the teacher's endpoint, and then the teacher's client) with the teacher's key, timeouts and retries. `licenses.require_distillable` runs on it in `Ratchet.__init__` (invariant 1), so a closed or unknown model stops startup. It answers only a served call (escalation, cold start, pinned, teacher-only) and only after the primary is unavailable (`teacher_unavailable` again: its retries failed or its breaker is open). Its answer is served with route `fallback_teacher` and its model id, priced with `Settings.price(fallback model)`; the baseline stays the primary teacher's price for the same tokens. A throttled `fallback_teacher` event names the primary's failure. When the fallback fails too, the primary's error is raised: it is the configured teacher, and its breaker says when to come back. Order on an escalation: primary, then fallback, then degraded mode, then the error.
- **Fallback answers are not training data unless asked.** `_store_example(..., fallback=True)` stores nothing unless `RATCHET_STORE_FALLBACK_TEACHER=1`, so golden labels keep the primary teacher's quality. When stored, the example records the fallback model and its own license: `Ratchet.licenses` maps each configured teacher model to its license at startup, and `_store_example` looks it up by the configured model that answered.
- **Audits and arbitrations stay with the primary.** They are the release gate's evidence and the training set's labels; a different model's verdict would mix two teachers in one signal. While the primary is down they are skipped.
- **A request a stand-in answered runs no shadow.** A degraded or fallback-served request's only reference would be the student's below-threshold answer or another model's, so no shadow call is made and no shadow verdict recorded. With `audited` 0 as well, these requests never move a release.
- **Visible in stats.** `ROUTES` gains `degraded` and `fallback_teacher` (per task in `routes`); `stats_by_day` adds `degraded` and `fallback_teacher` counts per day; `Ratchet.health()` adds `degraded_answers` and `fallback_answers`. `/ratchet/stats` only gains keys.

## Consequences

- PRD FR-2.12 (new); NFR-2 and FR-1.11 extended. During a long teacher outage requests that need the teacher fail in milliseconds with a 503 and a `Retry-After`, instead of holding a thread for up to 180 s; one request per wait probes the teacher.
- A teacher that rate-limits every call (429 after the retries) opens the breaker too: clients then get the breaker's 503 and wait instead of the teacher's 429. Fewer calls reach a teacher that is already refusing them.
- Degraded answers are, by construction, below the threshold the release gate calibrated for the precision target. The mode is off by default, every such answer is marked in the response and the header, and none is stored, audited or counted toward a release. An application that cannot use a lower-confidence answer leaves the mode off or checks the flag.
- The fallback's answers can differ in quality from the primary's. They are served under their own model id and fingerprint, are not stored by default, and never judge a candidate.
- `requests.route` for a fallback-served escalation says `fallback_teacher` rather than why it escalated (`confidence`, `cold_start`, `student_error`, `student_breaker`); `escalated` and `confidence` keep that information.
- Pinned requests may be answered by the fallback teacher; they are still never stored (invariant 10).
- The reference simulation is unchanged: the mock teacher never fails, both modes are off by default, and the breaker draws no random numbers.

## Alternatives considered

- **License the model in the completion (`c.model`) when storing.** The spec this ADR implements suggested it, but `c.model` is the upstream response's own `model` string (`providers._completions`), which can differ in case or suffix from the configured name, or be anything a misbehaving endpoint says. Looking it up could fail a request at storage time, or record a name nobody licensed. The configured model that answered is licensed at startup and is what was asked for.
- **Use the fallback for audits and arbitrations too.** More evidence during an outage, but the release gate and the training labels would then rest on two teachers without saying so.
- **Store fallback answers by default.** More training data, at the cost of golden labels from a weaker model. Off by default; one variable turns it on, and each example names its teacher and license.
- **Shadow the stand-in answers anyway.** It would compare a candidate with a below-threshold student answer or with another model, so a teacher outage would move the shadow's statistics. Skipping costs one outage's worth of shadow evidence, never a wrong promotion.
- **Degrade on any teacher error, a 400 included.** A request too long for the teacher is the client's mistake; serving a low-confidence answer to it would hide the error the client must fix.
- **No breaker settings.** The spec fixed the threshold at 5; the variables mirror the student breaker's, so an operator can tune the wait or turn the breaker off (0) without a code change.
