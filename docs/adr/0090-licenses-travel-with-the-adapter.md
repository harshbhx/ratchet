# ADR 0090: Licenses travel with the adapter, and open teachers can be added by configuration

- Status: Accepted
- Date: 2026-10-20

## Context

Licensing is Ratchet's core claim ([ADR 0001](0001-open-teacher-only.md)), and NFR-9 says the model licenses travel with any distributed adapter. Until now only half of that held:

- Each adapter's signed BOM ([ADR 0010](0010-signed-adapter-bom.md)) listed the teachers and their licenses, but not the license of the base model the adapter runs on. A LoRA adapter for Nemotron 3 Nano 4B is used together with that model, which is governed by the NVIDIA Nemotron Open Model License; a recipient of the adapter had no record of it.
- Nothing license-related sat next to the weights. The training job wrote `ratchet_manifest.json` (teacher and license names, no URLs), and live Night School wrote the BOM to `data/boms/` after the dataset sync, so the BOM never reached the bucket folder that holds the adapter.
- There was no way to hand an adapter over with its licenses in one step (US-10, NFR-7).
- The teacher registry was code only. Adding an open teacher (an Apache-2.0 model on Token Factory, say) meant a code change, and the obvious shortcut, a configurable registry, would let anyone with access to the environment mark a closed model as distillable, which is exactly what invariant 1 forbids.

## Decision

**The base model's license is recorded.** `licenses.BASE_MODELS` maps the student base models Ratchet knows (Nemotron 3 Nano 4B BF16 and FP8, Nano 30B-A3B as served on Token Factory and on Hugging Face) to `NEMOTRON_OPEN`, matched in any case (Hugging Face ids are case-insensitive). The BOM gains `base_model_license: {name, url}`. An unknown base model is not an error: operators may train any base model, so the section then has `name` and `url` null and a `warning`, and the NOTICE says the same.

**A NOTICE.md goes next to the weights.** `ratchet/nightschool/notices.py` renders it from the base model and the sources (teacher, license, URL, origin, examples) plus the Ratchet version: the base model's license, a table of teachers, the statement that the targets were teacher outputs only (invariant 2), and a pointer to the BOM. Rendering is deterministic (sources sorted, cells on one line with pipes escaped) and uses only the standard library and `ratchet.licenses`, because the training job imports it inside the GPU container. `train.py` writes it with `ratchet_manifest.json` after `save_pretrained` (`write_metadata`), from the container's built-in registry; a configured teacher's URL is "not recorded" there.

**The BOM carries the exact NOTICE.** `bom.manifest` adds `notices: [{file: "NOTICE.md", sha256, text}]`, rendered with the manifest's own sources and generator, so the signature covers the notice and a recipient can compare the file's SHA-256 with the signed one. Carrying the text, not only its hash, means an export never re-renders: a later Ratchet that words the notice differently still ships the text that was signed at training time (invariant 14). A BOM without `notices` (v1, or v2 written before this change) gets a NOTICE rendered from what it records.

**These fields join schema v2, which is not released yet.** `ratchet.bom/v2` was defined in this release cycle ([ADR 0024](0024-evidence-foundations.md)) and no v2 document has shipped in a release, so `base_model_license`, `notices` and each source's `license_origin` are added to it rather than starting v3. `verify` never checked the shape, only the schema name, the SHA-256 and the signature, so v1 documents and v2 documents written before these fields still verify. Stored documents are never rewritten.

**Live Night School completes the bucket folder.** After a night that trained, `python -m ratchet.live night` writes the BOM to `data/boms/student-vN.json` (as since v0.4) and, with its NOTICE, into `RATCHET_DATA_DIR/adapters/<name>/` (`ratchet_bom.json`, `NOTICE.md`), the local mirror of the bucket folder the job wrote the weights to, then runs `RATCHET_SYNC_CMD` a second time. The sync must only upload (no `--delete`). If it fails, the night still stands (the version exists and is in the release gate): a `sync_failed` event names the exception's class, the report prints, and the command exits non-zero so cron notices. Adapter names are checked to be one folder name before any path is built from them.

**Export in one command.** `python -m ratchet.live export --version N --out DIR` copies `RATCHET_DATA_DIR/adapters/<name>/` when the weights are on the machine (a bucket mount, or synced down), writes the stored BOM and the NOTICE it signed (replacing any copy from the folder), and prints the BOM's `sha256`. With an upload-only sync, the local folder after a night holds only the BOM and NOTICE the night wrote, so the export counts only the adapter's own files (`adapter_files`: never those two) and, unless they include `adapter_config.json` and a weights file (`has_weights`), says that the weights are not there and where in the bucket to copy them from. It refuses an unknown version, a version without a BOM (trained before v0.4), a stored BOM that does not verify against its own SHA-256 and signature, and an output folder that exists and is not empty, so two adapters are never mixed, or that lies inside `RATCHET_DATA_DIR` (the adapter folder included), which the next sync would upload to the bucket.

**Open teachers by configuration, without weakening invariant 1.** `RATCHET_TEACHER_LICENSES` names a JSON list of `{model, license, url, note}`. `licenses.install(path)` parses it and publishes `{**BUILTIN, **configured}` as `licenses.REGISTRY` in one assignment (the built-in registry is a read-only `MappingProxyType`, so the merge is always into a copy, and a reader on another thread sees the old registry or the new one). An entry is accepted only when:

- its license is one of `ALLOWED_LICENSES`: OpenMDW-1.1, Apache-2.0, MIT, NVIDIA Nemotron Open Model License, licenses that put no restriction on training other models with the outputs (matched in any case, stored in canonical spelling);
- its model id belongs to no closed family (`closed_family`): split at every character that is not a letter or digit, no part starts with a `CLOSED` prefix or with `o` and a digit (the o-series after o4, `o5-mini`), contains one of three letters or more (`gpt`, `claude`, `gemini`: `chatgpt-4o-latest`), a closed model's name without such a prefix (`CLOSED_NAMES`: `davinci`, `babbage`, `codex`) or a closed vendor's name (`CLOSED_VENDORS`: `openai`, `anthropic`, for a model with a new name). This is stricter than `lookup`'s rule (start of the last path segment), so `azure-gpt-4o`, `my_gemini_mirror`, `davinci-002` or `anthropic/next-model` are refused too, and so is `openai/gpt-oss-120b`, an open model that has to be added in code after its license is read. The spec asked only for the prefix rule; a prefix alone would have let `chatgpt-4o-latest`, a closed OpenAI model, through;
- its model id is no router alias (`ROUTER`): no part contains a router's name (`ROUTER_VENDORS`: `openrouter`) and the last path segment is not `auto` (`ROUTER_ALIASES`). The model that answers an alias is chosen per request and may be closed, so no license claim can cover it;
- it does not name a built-in teacher (configuration never relabels what the code says) or repeat an earlier entry, its URL is `https://`, and it has no other keys.

Configured entries carry `origin="config"` (`TeacherLicense.origin`; built-in ones `builtin`), which the BOM records per source (`license_origin`) and the NOTICE marks "(configured)", so a reader can tell an operator's claim from Ratchet's reviewed registry. The model check knows only the closed families, model names, vendors and routers it lists: a closed model from another vendor under its own name (`x-ai/grok-4`) passes it and is admitted on the operator's claim alone. What configuration cannot do is relabel a closed model Ratchet knows of; for anything else the `config` mark is the safeguard, by making the claim visible to whoever receives the adapter. As defence in depth, `lookup` returns the closed terms for a configured entry that names a closed family, should one ever get into the registry. Every error in the file is collected with its place (`[2].license: ...`) and raised together as `LicenseConfigError` (a `LicenseError`, so a `ValueError`); the registry stays as it was.

Every entry point installs the file at startup, before anything else that could look a teacher up: the gateway's `Runtime.reset` (before it opens the ledger), `Ratchet.__init__` (so the simulator and any direct construction see the registry its settings name, and the teacher and fallback teacher are licensed against it), `python -m ratchet.live` (before the ledger is opened, so Night School keeps a configured teacher's rows and the BOM names them) and `python -m ratchet.admin` (an erasure counts a configured teacher's rows as training rows as Night School does).

## Consequences

- An adapter copied out of the bucket, or exported, carries its base model's and teachers' licenses next to the weights, and the signed BOM proves the notice is the one written at training time. NFR-9 is met.
- An operator can add an open teacher without a release, but cannot relabel a closed model Ratchet knows of (the `CLOSED` families, `CLOSED_NAMES`, `CLOSED_VENDORS`, router aliases) by configuration. A closed model the check does not recognise is admitted on the operator's claim, and every adapter trained on a configured teacher says so in its BOM and NOTICE.
- The registry is process state again (like the task registry, [ADR 0022](0022-task-registry.md)): tests reset it after each test (`tests/conftest.py`), and the last `Ratchet` constructed in a process decides it, which in production is the gateway's.
- Removing an entry later makes the teacher unknown again: startup refuses it as `RATCHET_TEACHER_MODEL`, and Night School leaves its stored rows out of training. Earlier BOMs keep what they recorded.
- A configured teacher has no price in `DEFAULT_PRICES`, so it is priced as any unknown model (the teacher's price, or 1.00 / 3.00 USD per million tokens).
- The NOTICE written inside the training job may lack a configured teacher's URL until the night's sync replaces it; an export always uses the BOM's text.
- None of this changes a decision or a simulation number: the BOM is not part of the pinned reference runs, and the registry with no file is the built-in one.

## Alternatives considered

- **A schema v3 for the new fields.** Correct for a released schema, but v2 has not shipped in a release, and two schema versions in one release would make every verifier and reader handle three shapes for no reader's benefit.
- **Only the NOTICE's SHA-256 in the BOM.** Smaller, but an export after a wording change would have to reproduce the old renderer, or ship a notice that no longer matches.
- **A configurable registry with no allowlist.** Simplest, and it would let configuration override invariant 1. The allowlist and the closed-family check keep the decision in code review.
- **Letting configuration replace built-in entries.** Useful if a license changes, but a code change with review is the right place for that, and allowing it would make the BOM's `builtin` origin meaningless.
- **Match base models by their last path segment** (so `/models/NVIDIA-Nemotron-3-Nano-4B-BF16` counts). A local path or a re-upload may hold anything; a warning that asks the operator to check is safer than naming a license for weights Ratchet cannot identify.
