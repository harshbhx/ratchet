# ADR 0017: Generation parameters by role, token caps, and the conditions stored with an example

- Status: Accepted
- Date: 2026-10-20

## Context

Until v0.5 the gateway validated `max_tokens`, `stop`, `seed`, the penalties, `response_format`, `tools` and the rest ([ADR 0012](0012-openai-request-validation-and-error-envelope.md)) and then dropped them: `Provider.complete` could not send them. The teacher always ran at temperature 0 with no output limit, and the student at its fixed sampling. Three problems follow:

- **Clients get the wrong answer.** A client that asks for `stop: ["\n\n"]` or 50 tokens, or JSON mode, gets whatever the teacher writes without them. Agent frameworks depend on stops and JSON mode.
- **Cost has no ceiling.** Nothing bounds a teacher answer (or a student sample) but the model's context. One long answer, or a client that asks for 10⁶ tokens, is paid in full (threat model T11).
- **Training targets lose their conditions.** A teacher answer written under JSON mode or a stop string is stored as if it had been written for the bare prompt. Two requests with the same messages but different formats collapse into one example, and the golden eval scores the student without the conditions production will impose.

The roles do not want the same parameters. The teacher serving an answer should do what the client asked. The student's sampling must not change: confidence is scored over n samples at temperature 0.7 with logprobs (FR-2.1), and its threshold was calibrated that way. An audit or arbitration is a reference the student's answer is compared with, so it should be deterministic, under the same conditions as the answer it checks.

## Decision

- **One carrier.** `providers.GenParams` holds a request's parameters by OpenAI's names (`max_completion_tokens` arrives as `max_tokens`, `stop` as a tuple, unknown top-level fields in `extra`). `Provider.complete(messages, model, n, temperature, logprobs, response_format, params=None, **_)`; the explicit arguments win over the same fields in `params`, and `logprobs=False` also drops `top_logprobs`.
- **One policy, three roles.** `providers.GenPolicy` (from `Settings.gen_policy()`) turns the client's parameters into a `GenPlan` per request:
  - *student*: the fields in `RATCHET_STUDENT_PARAMS` (default `max_tokens`, `stop`, `seed`, `response_format`, `top_logprobs`: what shapes the answer it must give; not `logit_bias`, which would steer the answers the audits compare), `max_tokens` at most `RATCHET_STUDENT_MAX_TOKENS` (1,024). Its n, temperature and logprobs stay `Settings.samples` and `confidence.STUDENT_SAMPLING`, so calibration still holds.
  - *serve* (escalation, cold start, pinned, teacher-only): the fields in `RATCHET_TEACHER_PARAMS` (default every standard field but `tools`, `tool_choice`, `parallel_tool_calls`, `logprobs` and `top_logprobs`, below; `user`, `safety_identifier`, `store`, `metadata` and `service_tier` are not generation parameters and are never forwarded), at the client's temperature or 0, `max_tokens` = the client's plus `RATCHET_TEACHER_REASONING_HEADROOM`, at most `RATCHET_TEACHER_MAX_TOKENS` (8,192), or the cap alone.
  - *check* (audit, arbitration): the serve parameters at temperature 0 without `top_p`, `seed`, the penalties, `logit_bias` and logprobs; the length limit, stops, format, tools and reasoning effort stay, so the comparison is like for like.
  The router, `LiveEvaluator` and `MockFleet` all use the policy, so the golden eval sends the student what production sends (FR-5.1). A field outside an allowlist is never sent; the caps apply either way. A vendor field (`top_k`) is forwarded only when an allowlist names it. Allowlist names are matched in any case. An allowlist that names a field Ratchet sets itself (`model`, `n`, `messages`, `stream`) or never forwards, a name that is not an identifier, a near miss of a standard field (`max_token`, `stops`: a typo, by difflib's ratio of 0.88 or more), or a negative cap stops startup; any other name is taken as a vendor field.
- **Nothing the gateway cannot return is forwarded by default** (`providers.NOT_YET_FORWARDED`). `tools`, `tool_choice` and `parallel_tool_calls` stay off both default allowlists until the tool-call item: the provider reads only `content`, so a teacher's tool call would reach the client as an empty message with `finish_reason: "tool_calls"` and no `tool_calls` (the OpenAI SDK's agent loop then raises), and the student's vLLM (`deploy/student_endpoint.sh`) runs without a tool parser, so it answers 400 to every request with `tools`. The teacher's `logprobs` and `top_logprobs` stay off too: a response's `logprobs` is null. (Changed by [ADR 0020](0020-n-choices-and-token-logprobs.md): responses now return token logprobs, so the teacher gets these two fields when a client sends them.) An operator can name any of them. A response never says `tool_calls` (`router.CLIENT_FINISH` leaves it out; a student sample that ended in one is reported as `stop`), and a teacher answer that is a tool call raises `UpstreamError` 502 `tool_calls_unsupported` in `Ratchet._ask_teacher`: the client gets a 502 with `X-Should-Retry: false`, nothing is stored, and an audit or arbitration counts it as a failed optional call. (Changed by [ADR 0043](0043-tool-calls-teacher-only-by-default.md): the provider reads tool calls and the response returns them, so the teacher gets `tools`, `tool_choice` and `parallel_tool_calls` by default; a tool request is answered by the teacher alone and never stored, and `tool_calls_unsupported` remains only for a tool call to a request without tools.)
- **The reasoning headroom.** A teacher that reasons before it answers spends output tokens on reasoning; with the client's limit alone it can be cut off before the answer. The headroom (default 0) lets it write more. Its visible answer (`tasks.clean_answer`) can then exceed what the client asked for; when it does by `approx_tokens`, the answer is marked `length`: the client is told, and the answer is not stored (INV-16) or used as a reference. The text is not cut, because the count is an estimate. Without headroom the teacher stopped at the client's limit itself and its own `finish_reason` stands.
- **Conditions stored with the example.** `ledger.STORED_PARAM_KEYS` = `response_format`, `tools`, `tool_choice`, `stop`: the conditions that define what a right answer is. Temperature, seed and penalties change how an answer is sampled, not what it should be, and are not stored. `_store_example` stores the conditions of the call that produced the answer (the check parameters for an audit), redacted like the messages (`redact.redact_json`, INV-12), in `examples.params`. `example_hash(task, messages, params)` adds a `params` key to the hashed object only when there are conditions, so every v0.4 hash is unchanged, and the same messages under other conditions are another example. `dataset.rows` returns them and `cascade_eval` passes them to the student sampler.
- **One split per prompt.** The golden or train split comes from `example_hash(task, messages)`, the hash without conditions (`Ledger._split`), so every variant of a prompt lands in the same set. The trainer sees only the messages: with the split taken from the full hash, a prompt sent once bare and once with a stop had about an 18% chance of putting the same prompt and answer in both sets, trained on (INV-3) and graded as held out (INV-6). For an example without conditions the two hashes are the same, so every v0.4 split is unchanged. The frequent rule (`dataset.FREQUENT`) counts every variant of a request together, so the variants also leave the golden set together.
- **The client may choose its answer, not the label.** The serving teacher gets the client's sampling, so a `logit_bias` of +100, a penalty or a temperature of 2 shapes what it writes. Such an answer is served but never stored (`GenParams.unstorable`, a `skip_example` reason): a client's `logit_bias`, a non-zero `presence_penalty` or `frequency_penalty`, a temperature above 1 (`providers.STORED_MAX_TEMPERATURE`), or a vendor field, since Ratchet cannot tell one that only samples (`top_k`) from one that constrains the answer (vLLM's `guided_choice`). `top_p`, `seed` and a temperature up to 1 sample from the teacher's own distribution and do not stop storage. Audits and arbitrations drop the sampling fields (*check* above), so their answers are stored as before, unless an allowed vendor field went with them. Without this, whoever holds an API key could write the label in the shared training set and the golden references (threat model T2).
- **A refused golden row is an escalation, not a failed night.** Golden rows are sampled under their stored conditions, and an endpoint may refuse one it cannot serve (a schema its guided decoding cannot compile, `tools` when an operator allows them on a student without a tool parser, a prompt over its context). In production that refusal escalates (INV-7); `cascade_eval` (and `LiveEvaluator`'s judge loop) scores such a row as confidence 0 and wrong, and reports `refused_n`. Only a refusal of that one request counts (`evaluate.REFUSED`: 400, 413, 422); an auth error, a missing adapter or an outage still stops the night, since it would refuse every row. Before, one such row stopped every night, because the golden split never changes.
- **The client sees the real finish.** `Result.finish_reason` is the served answer's (`stop`, `length`, `content_filter`; anything else is reported as `stop`), and the gateway returns it in the response and the last stream chunk.
- **A request channel for later items.** `router.RequestMeta(request_id, client_request_id, retry_count, storable, end_user, idempotency_key)` travels with `handle(messages, task, client, params, meta)`. `storable=False` keeps the request's teacher answers out of the training set; the gateway does not set any field yet.

## Consequences

- PRD FR-1.13 (new), FR-5.1 and NFR-3 (extended).
- The mock models honour `n`, `stop` and `max_tokens` (about 4 characters per token) and report `finish_reason`. Mock answers are short and contain no stop string, so the pinned reference simulation is identical.
- Every teacher call now carries `max_tokens` (8,192 by default). A reasoning teacher whose reasoning plus answer needs more is cut off (`finish_reason length`, not stored); raise the cap, or set the headroom when clients send tight limits.
- A server that checks prompt plus `max_tokens` against its context (vLLM does) now refuses a prompt that leaves less room than the cap. For the teacher, `RATCHET_MAX_INPUT_CHARS` keeps prompts far below its context; a student refusal is a 4xx, so the request escalates and the breaker does not count it.
- A custom `Provider` must accept `params` (and should accept `**_`); one written against v0.4's signature raises `TypeError` on the first call.
- A request with `tools` is answered as in v0.4: neither model sees the tools, and the teacher's prose answer to a prompt stripped of them is stored as a target, until the tool-call item routes such requests. An operator who allows `tools` gets a 502 `tool_calls_unsupported` whenever the teacher calls one. (Changed by [ADR 0043](0043-tool-calls-teacher-only-by-default.md): a request with tools now goes to the teacher alone, with its tools, and nothing of it is stored.)
- `logit_bias` is forwarded to the serving teacher by default, but token ids are tokenizer-specific: an id meant for OpenAI's tokenizer means something else to Nemotron. Remove it from the teacher's allowlist when clients send OpenAI ids. It is not forwarded to the student by default (changed at the merge of the hackathon lanes): a client's bias would steer the student's answer while the teacher's audit runs without it, so audited agreement would measure the bias, not the model. A served answer under a client's `logit_bias` is not stored either way.
- Night School's training script (`train.py`) renders the messages only and ignores every stored condition: `stop`, `response_format`, `tools` and `tool_choice`. An answer the client's `stop` ended early would teach the student to stop there on the bare prompt, so `dataset.rows` holds such rows out of training; as golden rows they still serve the eval, which samples the student under the same stop. An answer written in JSON mode is trained on as it is, which is right when the prompt asks for JSON, as it usually does. Training rows carry `params` for when the script renders them.
- `scripts/day1_check.py` sends the teacher `max_tokens` at `RATCHET_TEACHER_MAX_TOKENS` with a stop, a seed, a temperature and JSON mode, since a teacher that refuses the cap would fail every escalation (INV-9).

## Alternatives considered

- **Forward everything to every call.** Simple, but the client's temperature would change the student's sampling and break calibration, and an audit at temperature 1.2 is not a reference.
- **Filter in the provider only.** The provider cannot tell the client's `max_tokens` from Ratchet's cap, or the client's temperature from the audit's 0, so the allowlists live in the policy; `OpenAICompatProvider(allow=...)` remains for a provider used on its own.
- **Store every parameter with the example.** Seeds and temperatures would split one request into many examples that teach the same thing, and change the dedup and golden-split identity of almost every example.
- **Cut an over-budget answer to the client's limit.** It would match OpenAI more closely, but the cut would rest on an estimate of the tokenizer and could break a JSON answer the real tokenizer fits.
- **Refuse `max_tokens` above the cap with a 400**, as OpenAI does above a model's limit. Clients often send large defaults; capping serves them and bounds the cost the same way.
