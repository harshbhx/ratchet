# CLAUDE.md: `deploy/` (Nebius)

- `train_job.sh <version>`: submits a Nebius Serverless Job with `nebius ai job create` (the scripted command; `nebius ai create` is the interactive wizard) that runs `python -m ratchet.nightschool.train` with the bucket mounted at `/data`, `--timeout 2h`, and `--subnet-id` / `--registry-secret` only when `RATCHET_SUBNET_ID` / `RATCHET_REGISTRY_SECRET` are set. If `RATCHET_BUCKET_S3` is set, it polls for `adapters/<version>/adapter_model.safetensors` (up to 2 h) so `ratchet.live` can wait on it. `DRY_RUN=1` adds `--dry-run` and returns without polling.
- `student_endpoint.sh [create|start|stop|status]`: `create` (once) makes a Nebius Serverless Endpoint running `${RATCHET_VLLM_IMAGE:-vllm/vllm-openai:v0.18.0-cu130}` with `--enable-lora`, the model card's `--mamba_ssm_cache_dtype float32`, `--max-model-len 8192`, `--max-num-seqs 64`, thinking off by default (`--default-chat-template-kwargs`) and, with `RATCHET_REASONING_PARSER_PLUGIN`, the `nano_v3` reasoning parser; `VLLM_ALLOW_RUNTIME_LORA_UPDATING=True`, so new adapters are hot-loaded (`POST /v1/load_lora_adapter`) without a restart. `start` (the default) and `stop` run `nebius ai endpoint start|stop --id <id>` on the same endpoint (same URL and token); the id is `RATCHET_ENDPOINT_ID` or found by name in `nebius ai endpoint list --format json` (read with `RATCHET_PYTHON`), and `start` falls back to `create` when no endpoint has the name. The lookup never guesses (not JSON, two endpoints with the name, no id, or a missing name on a list with more pages: exit 1 before any start, stop or create). `status` prints `<id> <state>`. `DRY_RUN=1` adds `--dry-run` to `create` and prints `start` and `stop` (which have no `--dry-run`) instead of running them; any other value than `0` or `1` exits 2. `create`, `start` and `stop` then record the endpoint's uptime for the cost report with `"${RATCHET_PYTHON:-python}" -m ratchet.cost endpoint up|down --source deploy` (ledger at `RATCHET_DB`; not in a dry run); that call is best effort and must never fail the deploy (`|| echo note`). Commands are echoed on stderr with the token as `<RATCHET_STUDENT_KEY>`.
- Every `RATCHET_*` variable the two scripts read is either read by `config.py` or listed in `config.DEPLOY_ENV`, and documented in [docs/CONFIGURATION.md](../docs/CONFIGURATION.md#deploy-scripts-deploy) (checked by `test_deploy_variables_are_listed_and_documented` and the traceability check).
- `Dockerfile.train`: CUDA 12.8 devel + exact versions of torch, Transformers, PEFT, TRL, Accelerate, datasets and the Mamba kernels, as listed in `train-versions.txt` (read as pip constraints after torch; no Unsloth, which requires an older TRL). No `|| true`: the last build step imports the kernels, so a failed kernel build fails the image. `python-is-python3`, because the job runs `python`. Build from the repository root. Change a version in both files together (`test_dockerfile_is_pinned`; ADR 0145).

- `vm/`: the public demo on one Nebius CPU VM ([docs/DEPLOY_NEBIUS_VM.md](../docs/DEPLOY_NEBIUS_VM.md)).
  - `create_vm.sh`: boot disk + VM with a static public IP + `cloud-init.yaml` as user data. `DRY_RUN=1` prints the commands.
  - `cloud-init.yaml`: Docker, `ufw` (22/80/443), unattended upgrades, a `ratchet` service user, clone to `/opt/ratchet`, `.env` from `.env.vm.example`, sslip.io domain default, `docker compose up -d --build`, and `/etc/cron.d/ratchet` (daily backup on; Night School lines commented out).
  - `docker-compose.yml`: the gateway (1 uvicorn worker, `--proxy-headers`, ledger in the `ratchet-data` volume, health check on `/healthz`, which stays public when `RATCHET_API_KEYS` protects `/v1/*`) and Caddy (`caddy:2.11.7-alpine`).
  - `Caddyfile`: HTTPS for `RATCHET_DOMAIN`, security headers, no buffering for `/scout/stream`, and the opt-in `RATCHET_API_GUARD=guarded` (403 on `/v1/*`, `/openai/*` and `/ratchet/demo/*` without `X-Ratchet-Admin-Token`; `tests/test_live.py` checks that every OpenAI-compatible route is under a guarded path).
  - `update.sh`: pull, build, run `python -m ratchet.config check` in the new image with `.env` (exit 2 stops the update before the running container is replaced; ADR 0070), `docker compose up -d`, wait for the Docker health check (`/healthz`) and for `/readyz` to answer 200 inside the container, then check `/`, `/healthz`, `/readyz`, `/dashboard`, `/scout` over HTTPS, and `/ratchet/stats` when the dashboard is public (`RATCHET_PUBLIC_DASHBOARD`). Keep the Docker health check on `/healthz`: restarting on `/readyz` would turn a teacher outage into a restart loop. A new `RATCHET_*` variable read only by the deploy kit goes in `config.DEPLOY_ENV`, or the gateway warns that it is unknown. `backup.sh`: SQLite online backup, integrity check, keep 14, optional upload to Object Storage.
  - `update.sh` (as above) also takes `update.lock`, backs up (`backup.sh`, `RATCHET_BACKUP_TAG=pre-update`), tags `ratchet-gateway:previous`, verifies (healthy, `/readyz`'s ledger, mode, `python3 -m ratchet.watch probe --once`) and rolls back the checkout and image on `fail:*` (never for a teacher outage; `DRY_RUN=1`, `--skip-backup`, `--no-rollback`, `--no-probe`); `restore.sh <backup.db.gz>` moves the old ledger and its WAL aside and restores; `ratchet-watch.cron` (also in `cloud-init.yaml`) runs the watchdog; `config/tasks.json` pins the probe task (mounted read-only at `/config`). `tests/test_watch.py` runs the scripts with a fake `docker` and `sleep` first on `PATH`.
  - `.env.vm.example`: every VM setting with comments. Starts in mock mode with `RATCHET_MOCK_WARMUP_DAYS=4`, and a public dashboard (`RATCHET_PUBLIC_DASHBOARD=1`, scrubbed for anonymous readers in live mode) so judges see it. Live mode without `RATCHET_API_KEYS` needs `RATCHET_ALLOW_UNAUTHENTICATED=1`, meant only with the Caddy guard (ADR 0061).

Rules:

- **The `nebius ai` commands here follow the CLI reference** (pages auto generated on 19-Oct-2026, read Oct 21, 2026: `ai job create`, `ai endpoint create|list|start|stop`) but have not run against a real account. Run both scripts with `DRY_RUN=1`, check `nebius ai job create --help`, `nebius ai endpoint create --help`, `... start --help` and `... stop --help` on day 1, and fix them here, not in docs only. Paste the output of `nebius ai endpoint list --format json` (ids redacted) into `tests/fixtures/nebius_endpoint_list.json`.
- Stop the endpoint when idle. A stopped endpoint is not billed for compute or its own storage; the mounted bucket still is (docs.nebius.com/serverless/overview, read Oct 21, 2026).
- Never put keys in these scripts; read them from env vars. On the VM, keys live only in `deploy/vm/.env` (mode 0600, git-ignored).
- In live mode on the VM, keep the Scout budget guard on and set `RATCHET_API_GUARD=guarded` with a 32+ character hex token; otherwise `/v1/chat/completions` is an open, paid endpoint.
- Port 8000 must stay unpublished (`expose`, not `ports`): `--forwarded-allow-ips "*"` is safe only because Caddy is the only thing that can reach the gateway.
- `nebius compute` flags in `vm/create_vm.sh` were checked against docs.nebius.com on Oct 20, 2026; the lines marked VERIFY ON DAY 1 were not.
- Pin image versions once the day-1 run passes, and record them in [docs/DEPLOYMENT.md](../docs/DEPLOYMENT.md). The training image's Python packages are already pinned (candidates read Oct 21, 2026); the Oct 22 smoke job's `versions.json` confirms or replaces them.
- `tests/test_live.py` runs `bash -n` on every `*.sh` here, `DRY_RUN=1 bash vm/create_vm.sh` (the printed `nebius` commands, never the user data or a token in the repo URL, and each early refusal) and `vm/backup.sh` in mock mode. It also checks that `train_job.sh` reads `/data/night/train.jsonl` and writes `/data/adapters/${VERSION}` (the paths `ratchet.live` uses) and that both scripts default to the gateway's student base model. With a fake `nebius` first on `PATH` (`fakes.FakeNebius`: it logs each call's argv and prints `tests/fixtures/nebius_endpoint_list.json` for `ai endpoint list`) and a stub `ratchet.cost`, it runs both scripts and asserts the exact `nebius` calls: `ai job create` with its flags, `ai endpoint start|stop --id` after the lookup, the `create` flags and vLLM arguments, dry runs, and every refusal (`test_train_job_uses_job_create`, `test_endpoint_stop_and_start_use_the_id`, `test_endpoint_lookup_never_guesses`, `test_endpoint_args_carry_the_model_card_flags`). `tests/test_cost.py` runs `student_endpoint.sh` start and stop with the same fake: the ledger records the uptime, and a missing ledger leaves the exit code 0. Keep those in step when you edit a script; they check the commands against the CLI reference as read, not against a real account.
